# 可行动事务 Agent · 优势与可行性分析

> **用途**：从「黑客松项目」与「创业产品」两个身份，分维度评 idea 的优势与可行性。两者结论不同，勿混为一谈。
> **配套**：[[可行动事务Agent-定位决策]] · [[可行动事务Agent-路演答辩应答卡]] · [[可行动事务Agent-学分认定Demo规格]]

---

## 一、Idea 优势（六类）

| 类 | 优势 | 为什么是真优势（非自吹） |
|---|---|---|
| **定位** | 判定 ≠ 记忆，避开血海 | 「第二大脑」是血海；「条款级裁决 + 举证」是浅红真空位。主动从红海挪出，少见的清醒 |
| **场景** | 双约束是「真痛 + 不可见」痛点 | 总量 128/120 达标但某类不够——学生在教务系统里**根本看不见**。系统能做、人做不到，硬价值 |
| **技术** | 神经符号架构天然规避幻觉 | LLM 只归一化、规则引擎裁决。学分是纯数值 → 判定层零幻觉、可复算。让「AI 判资格」这件高危事**可信** |
| **Demo** | 一屏 gotcha + 3 分钟可讲完 | 128/120 ✓ 停顿 → 12/20 ⛔ 翻车，极强现场戏剧点。且能真解析真跑，不靠嘴吹 |
| **合规** | 选对场景规避学术诚信红线 | 从奖学金（代写风险）换到学分认定（只算数）——主动绕开评委老师最敏感的雷 |
| **演进** | 同一能力可迁移，路径清晰 | 个人 → 团队 → 企业，换文件就复用（学分 → 奖学金 → 教育局通知）。「一个工具」升级成「一类能力」 |

**最核心的一条**：选场景的判断力。学分认定同时满足「高痛 + 不可见 + 纯数值 + 无诚信风险 + 多文件交叉」五个条件——这种场景很难找，选中了就赢一半。

## 二、可行性评分卡

| 维度 | 黑客松 | 创业 | 关键卡点 |
|---|---|---|---|
| 技术实现 | 🟢 高 | 🟢 高 | 中文 PDF 表格解析、学时/学分单位换算 |
| 数据获取 | 🟡 中 | 🟡 中 | **教务能否导出真实学时（第一风险）** |
| 产品留存 | 🟢 高 | 🔴 低-中 | 学分认定极低频 |
| 市场规模 | — | 🟡 中 | 学生付费意愿低，真金在企业（未验证） |
| 商业变现 | — | 🔴 低-中 | 变现路径未验证，企业侧零访谈 |
| 竞争差异 | 🟢 高 | 🟡 中 | 差异化窗口短（NotebookLM 免费 / Mem 迭代快） |
| 执行范围 | 🟡 中 | — | 72h 分工，两个 demo 都想做深 = 都做不完 |
| 合规红线 | 🟢 高 | 🟢 高 | 已通过换场景规避 |

## 三、逐维详析

**1. 技术实现 🟢** — 管线：PDF 解析 → LLM 抽条件（受控词表 + JSON schema）→ LLM 抽个人学时 → 规则引擎比较（纯代码，极简）→ 缺口计算 + 排序 → 反查可补途径（同一份认定办法文本）→ 7 屏渲染。判定层是纯阈值比较，没难度。**唯一硬点**：中文 PDF 表格 / 排版解析不稳。缓解：demo 文件固定、抽取范围限定、允许预置。72h 可跑通。

**2. 数据获取 🟡** — 第三份文件（个人学时）来源是**全项目最大工程风险**。方案 A 教务导出 PDF/Excel（推荐，还正面证明「无痛输入」）；降级 B 截图 OCR（可信度掉）。**必须本周找 1 位同学实测导出**，导不出立刻切 OCR。别拖到赛前一天。

**3. 产品留存 🟢黑客松 / 🔴创业** — **战略最大软肋**。学分认定一辈子认定一两次，极低频。作 demo 无敌，作产品留不住人。唯一解：学分认定当**钩子**，奖学金（年）+ 通知报名（周）当**留存主线**。黑客松不影响（3 分钟不谈留存），但评委一问「谁持续用」就暴露——用应答卡 Q8 顶。

**4. 市场规模 🟡** — 全国本专科生约 4700 万，盘子大但**学生付费意愿极低**。真正的钱在企业文档 workflow（教育机构 / 行政）。问题：企业侧**零真实访谈**，全是推演。缓解：赛前访谈 2–3 人 or 老实标「方向假设」。

**5. 商业变现 🔴-🟡** — 变现路径（「个人免费获客 → 企业订阅席位」）逻辑通但未验证。黑客松通常不重商业模式评分，但被问要能答（应答卡 Q11）。别硬编数字。

**6. 竞争差异 🟢黑客松 / 🟡创业** — 差异化窗口短：NotebookLM 免费带引用、Mem 迭代极快、腾讯 ima 撞国内场景。相对稳的差异是**裁决层（判达标 + 算缺口）**，通用工具不会为特定规则写的逻辑。护城河诚实放「已核验规则集 + 数据网络效应」，别吹端 / 中文。

**7. 执行范围 🟡** — 最现实的翻车点不是技术，是**贪心**。两个 demo（校园 + 公司）都想做深 = 都做不完。铁律：校园做真（1 主线 × 1-2 类 × 3 文件），公司一句话带过。先做交互原型再写功能。

**8. 合规红线 🟢** — 已通过换场景 +「整理已有材料 + 列缺口，不代写」话术规避。团队做得最对的一步。

---

## 四、关键卡点排序（先拆哪个雷）

1. **教务导出实测**（本周内）——导不出整个 demo 重新设计，最该先验证
2. **单位换算（学时 / 学分）先定死**——认定办法常混用，口径错缺口全错且错得「很自然」不易发现
3. **中文 PDF 解析验证**——拿真实文件跑一次抽取，看准确度决定要不要预置
4. **demo 分工冻结**——校园做真、公司做短，白纸黑字定下，防贪心

---

## 五、诚实双结论

**作为黑客松项目：🟢 高可行，是很强的参赛作品。**
场景选得精、能真跑、故事有戏剧点、主动规避红线、技术上站得住（神经符号）。72h 内做出可炸的 demo 完全可行，前提是不贪心 + 教务数据能拿到。

**作为创业产品：🟡 中等可行，有真问题待验证。**
三个真软肋——**低频留存、变现未验证、护城河薄**——都不是靠 demo 能解决的，得进产品阶段用真实用户验证。但赛道目标是「让模型进入生产关系」，**企业文档驱动 workflow** 方向对，只是还没被真实访谈支撑。

一句话：**这个 idea 拿去比赛，赢面大；拿去创业，方向对但功课没做完。** 两者别混——路演时讲成「验证过的能力 + 诚实标注的假设」，比讲成「已验证的商业模式」得分高。
