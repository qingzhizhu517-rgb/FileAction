# 可行动事务 Agent · 参赛主线方案

导航：[[可行动事务Agent-00-总览|文档总览]] · [[02-调研与可行性/可行动事务Agent-竞品分析|竞品分析]] · [[03-参赛与路演/可行动事务Agent-路演答辩应答卡|路演答辩应答卡]]

> 本篇于2026年9月30日经三轮追问重整，取代旧方案（已移入 [[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-定位决策|旧方案归档]]）。方向回到原始愿景：主动发现、可信复用、直接行动，并以同一内核延伸到团队与企业。

## 1. 一句话

**丢一份文件，它站在你的角度读给你听：跟你有什么关系，要不要做点什么。**

口号：每份文件，都从你的角度读一遍。产品名：文启（英文 FileAction），中文取“从文件开启行动”之意，英文直指 File → Action，对应内核 Document → 可行动事务 → Workflow；2026年10月1日确定，取代此前的“旁批 / Margin”。尚未做商标查重；同日简单网页检索未见同名 AI 文件应用，但“文启”已被教育类公司用作品牌（文启AI测学系统、北京文启智行），“FileAction”在 Nextcloud 中是开发接口名，正式使用前需核查。图标待重新设计；讲解视频仍为旧名，暂未更新。

通用 AI 读文件，给的是人人都一样的解读和“怎么办”。本产品读文件时带上你的经历、意向和用过的材料，给的是你的解读：这张证书这次能用，那张去年评过国奖、这次不能再用，还缺一份推荐信。它记下的是每次办事留下的证据（出处、版本、用没用过），不是聊天偏好。记忆只是手段，不是卖点。

## 2. 内核：站在你的角度读，再决定要不要行动

普通 AI 读完文件只会说“该文件主要包括以下几点”。本产品先判断这份文件和你有什么关系，再决定怎么回应。能变成事务的，推进成带对象、条件、时间、材料和下一步的可行动事务（Document → 可行动事务 → Workflow）；不需要行动的，也会直接说明，不硬凑待办。

文件种类列不完，同一份文件对不同的人意义也不同：一份公司规章，对求职的学生是“这家公司靠不靠谱”，对刚入职的员工是“试用期要注意什么”。所以产品不预设文件分类，回应由“这份文件 × 这个人”共同决定。

| 层级  | 同一内核回答的问题                   | 本届形态        |
| --- | --------------------------- | ----------- |
| 个人版 | 这份文件跟我有什么关系？要不要做点什么？我已有什么、还缺什么？ | 主线，完整实现     |
| 团队版 | 我们这支临时队伍各自擅长什么？这件事谁做哪块最合适？还缺什么能力？ | 临时组队轻量实现    |
| 企业版 | 收到文件后，判断谁需要做什么、准备材料、执行和汇报   | 路线图，不做 Demo |

校园通知高度标准化，规则、时间节点和材料要求都很强，是验证这条内核的天然实验场。

## 3. 个人版

### 交互形态：对话为主，卡片按需出现

页面不预设固定步骤。以对话为主，按需要插入卡片积木：材料对照卡、待办卡、条款卡、提问卡、意向匹配卡。一份竞赛通知可能出现对照卡和待办卡；一份公司简章可能只有一段解读和一张意向匹配卡；跟你关系不大的文件，就一句话说明。

只有两处保持固定结构，保证可信：

- 判断材料能不能用时，统一用 ✓ 可用 / △ 要处理 / ✗ 本次不能用，并附出处（见亮点二）。
- 导出待办、日历和清单时，格式固定。

例：用户说过想找教育方向的实习，这次上传一份教育公司简章。

```text
这是「某某教育」的公司简章。
你说过想找教育方向的实习，这家公司有产品和教研岗。
要不要：□ 对照你的经历看适合哪个岗  □ 准备面试要点  □ 先存着
```

### 反馈：随时纠正，纠正也在了解你

每次回应后给两三个轻量选项，用户也可以直接打字纠正，例如“你理解错了”“我只是存着”“我关心的是薪资”。Agent 据此调整这次的回应。纠正里透露的意向或事实，经用户确认后沉淀为记忆。这和“按需索取”是同一套机制。

### 第一次使用：一次点击看到差异

零记忆时，第一版解读和通用 AI 差别不大。所以读完文件后，Agent 只问一个和这份文件直接相关的问题，例如“你上传它是在找实习吗？”，并给出两三个猜测选项。用户点一下，立刻得到站在他角度的第二版解读。不建档，也让差异当场可见。

### 亮点一：主动发现

用户丢进一份通知，Agent 从个人记忆中找出相关的 Idea、经历、获奖和意向，主动提示（以下为事务类文件的一种典型回应）：

```text
发现一项可能与你有关的活动

【大学生创新创业大赛】 截止：10月12日（原文第2条）
你此前保存的「校园交友平台」Idea 与本次“社会服务”赛道相关。
你曾表达意向：“以后想做 To B 教育方向创业”。

你已有： ✓ 项目 Idea   ✓ 项目介绍（v2，6月）   ✓ 部分团队信息
要处理： △ 成员名单需按本届重新签字
本次不能用：✗ 往届获奖证明（第5条：已获奖成果不得重复申报）
还缺：   □ 商业计划书   □ 项目 PPT   □ 指导老师信息

下一步：「起草项目简介」「导出待办与日历」
```

意向层记住用户随口说的一句话，例如“以后想找教育相关的兼职”，并在之后的相关通知中说明关联理由。意向只用于解释相关性，不等于用户决定报名。

### 亮点二：可信复用

每条匹配都能点回通知原文和资料原文。对外只讲三类状态，每类下面列具体原因：

| 对外状态 | 内部原因举例 |
|---|---|
| ✓ 可用 | 来源可定位、版本有效、本次用途未发现冲突 |
| △ 要处理 | 需按本次更新、缺签字、版本过期、尚未检查、规则不明需核实 |
| ✗ 本次不能用 | 适用的禁用条款与触发事实同时成立，例如已获奖成果禁止重复申报 |

护栏规则：模型初稿与用户确认分开标注；“本次不能用”不能被普通勾选解除；未检查不等于缺材料；材料齐全不等于资格通过。用户纠正事实后，相关旧结果标为过时。

### 亮点三：直接行动

- 生成缺项待办和截止日期，导出日历文件与 Markdown 准备清单。
- 用已确认的资料起草缺项材料，例如项目简介、个人事迹材料，标为模型初稿供用户修改。
- 不替用户提交、不代签字、不编造经历。

### 两个底色

- **无痛输入**：截图、拍照、转发的文字、PDF、Word 都可以进入。多模态模型负责识别，识别不清的部分标出来请用户确认。
- **按需索取，不建档**：产品从不要求用户先填个人档案或能力问卷。用户丢进一份文件，Agent 站在他的角度读；只有当这件事确实需要某条信息时，才在当下问一句，并说明为什么要问，例如“这份通知要求近三年获奖，你有相关证书吗？拍一张就行”。用户可以跳过。
- **记忆自己长出来**：每次被问到并确认的事实，都沉淀为记忆卡片，关联图随之增长。用得越多，下次要问的就越少。第二份通知（例如奖学金）进来时，竞赛获奖记录会自动连到“个人事迹材料”。用户可以查看、修改、停用和删除每张卡片。

## 4. 团队版：临时组队，按人推荐

**一句话：临时组队时，汇集 Agent 了解每个人擅长什么、想做什么，按人推荐分工，并帮团队把共用材料做出来。它是队友，不是监工：不催交、不盯进度。**

以5人临时组队参加西客松为例：

1. **授权能力名片。** 每位成员从个人记忆生成一张能力名片，例如“做过2个 React 项目”“写过商业计划书”“想做教育方向”，每条可点回原始材料。成员逐条确认，不想公开的可以隐藏。
2. **拆出工作块。** 汇集 Agent 读懂赛事指南，把这件事拆成工作块：产品原型、模型接入、路演 PPT、用户访谈、录屏封包等。
3. **按人推荐分工。** 每个推荐都附理由，例如“小王适合前端原型：做过2个 React 项目（来源：项目经历 v2）；他也表达过想做教育方向”。成员可以接受、互换或拒绝。
4. **指出能力缺口。** 例如“队内没有人做过用户访谈，建议由表达意向最接近的小李承担，并先看一份访谈提纲”。本届只在队内提示，不跨用户推荐队友。
5. **协助完成共用材料。** 用成员授权的名片起草团队介绍、分工表、计划书的“团队”章节，以及首晚60秒视频的团队介绍稿，标为模型初稿。

**没有沉淀的成员不被索取。** 汇集 Agent 不要求任何人先填能力问卷。没有记忆的成员照常参与，名片先空着；等他分到一块工作、开始处理相关文件时，Agent 才在当下问一句需要的信息，例如“这块要做前端原型，你之前做过类似的吗？有作品链接可以贴一个”。回答会沉淀进他的个人记忆，名片随之变丰富，之后的推荐理由也更充分。已有沉淀的成员推荐更准，这本身就体现了个人版的价值。

白盒边界：汇集 Agent 只看得到成员授权的名片，看不到完整记忆；推荐理由和依据对全队可见；分工由成员决定，Agent 只给建议。

与竞品的关系：接龙管家、飞书、钉钉擅长分派、催交和汇总，团队版不走这条路。差异是“先了解人，再推荐事”，而且对人的了解来自成员在真实事务中逐步沉淀的记忆，不是一张一次性的技能表。

## 5. 企业版：路线图

企业入口不是“企业 AI 知识库”，这一类 Glean、Notion、飞书和 M365 已经很强。入口是这条流程：

```text
收到文件/通知 → 判断谁需要做什么 → 准备材料 → 执行 → 汇报
```

例：教育局通知 → AI 理解 → 判断涉及哪些教师 → 生成任务 → 匹配模板 → 教师提交 → 自动汇总 → 负责人周报。差异点在第一步：读懂一份非结构化通知，并判断谁要做什么。审批流和表格收集已有成熟工具，可以作为下游对接。

## 7. 5 分钟展示

| 时间 | 内容 |
|---|---|
| 0–30秒 | 痛点：群通知刷屏、材料散落、每次都要重新向 AI 解释自己；同一份文件，通用 AI 的解读人人一样 |
| 30–60秒 | 零记忆首问：丢一份文件 → 通用解读 → 回答一个问题 → 站在你角度的第二版解读 |
| 60–180秒 | 已有记忆：截图竞赛通知 → 主动发现旧 Idea 与意向 → ✗ 拦下往届获奖证明 → 起草简介并导出待办 |
| 180–250秒 | 团队版：5人临时组队读西客松指南 → 能力名片 → 按人推荐分工并给理由 → 指出能力缺口 → 起草团队介绍；一名零记忆成员在处理文件时被按需问一句，名片当场变丰富 |
| 250–275秒 | 商业需求：种子用户是谁、痛点证据（访谈与截图门槛的真实数字）、下一步付费测试 |
| 275–290秒 | 企业路线图一句话：同一内核放大到“教育局通知 → 教师任务 → 周报” |
| 290–300秒 | 边界：合成资料、模型初稿需确认、不自动提交 |

“个人 → 团队 → 企业”作为路线图假设讲，不作为已成立的商业路径。每层配一个验证信号：

| 层级 | 验证信号 |
|---|---|

## 11. 商业需求：先做 0→1

本节参考10月1日赛前直播的商业需求讲解：企业成长分三阶段，需求按“欲望、需要、需求、刚需、痛点”分级；不用问卷，看真实历史行为；用行为门槛筛出核心用户；先学用户，再用 MVP 验证付费。项目目前处在第一阶段，路演只讲 0→1，规模化和生态一句话带过。

### 种子用户

**一学期内多次参加竞赛或申报、且经常临时组队的活跃学生。** 他们同时用得上个人版和团队版，人群窄、好触达；西客松现场本身就是这类人。其他学生、社团负责人和企业暂不作为首批对象。

### 需求分级：主打痛点，不打“需要”

| 候选 | 需求强度 | 处理 |
|---|---|---|
| 用错材料被退回、失去资格：往届获奖成果不得重复申报、版本过期、缺本届签字 | 有明确后果，最接近痛点 | **主打。** 通用 AI 的记忆不记使用史，给不出“这张证书去年用过、这次不能再用” |
| 临时组队不了解队友，分工靠猜 | 待验证 | 第二个痛点，由团队版承接 |
| 每次都要重新跟 AI 解释自己 | 偏欲望，大厂已充分竞争 | 只作开场铺垫，不当卖点 |

以上强度判断来自公开通知和团队推断，还没有用户证据，要由下面的验证来确认或推翻。

### 验证：看行为，不看表态

| 步骤 | 做法 | 记录什么 |
|---|---|---|
| 回顾访谈（开赛前） | 找3名种子用户，请对方打开上次申报时的真实文件夹和聊天记录，逐步还原：从收到通知到提交，每一步做了什么、在哪里卡住、有没有用错或被退回。不问“你需不需要这个产品” | 卡点、用错材料的真实经历、耗时估计（标明为回忆） |
| 截图门槛 | 请受访者把手头正在准备的一份真实通知截图发来，愿意发的才算核心用户 | 发出人数 / 邀请人数；原样报告，人数少也照实说 |
| 现场观察（赛中，有余力时） | 看其他队伍在锁队（10月1日21:30）前后如何组队和分工 | 分工依据、是否了解队友 |
| 付费测试（赛后 MVP） | 给正在准备申报的同学提供一次真实的材料对照，付小额费用才能使用 | 实际付款人数，与口头愿付分开记录 |

### 优势从哪里来

用 AI 降低开发成本，大厂同样能做到，不构成优势。可主张的是**窄场景规则加信任设计**：禁重复申报、版本过期、按需索取、授权边界。先在校园事务这一小块把它做对。

“AI 让临时组队参赛变多”可能是一个上升趋势，但目前没有来源，只能当假设讲。

## 12. 不变的底线

- 演示资料为合成数据并明示；不编造用户、经历或测试结果。
- 模型初稿与用户确认分开；准备清单不等于已报名，材料齐全不等于资格通过。
- 本机保存不等于云端模型看不到数据：说明发送了哪些片段、发给哪个服务方。
- 不做框架式建档：只在当前事务需要时索取信息，并说明原因，用户可以跳过。
- 团队版只推荐、不监督；分工由成员决定。
- 不使用“零幻觉”“竞品都做不到”等说法。
