# Repository Guidelines

## 项目结构与文档职责

本目录是「可行动事务 Agent」的 Obsidian/Markdown 产品文档库，尚无应用源码、测试目录或独立资源目录。

- 从 `可行动事务Agent-00-总览.md` 入手，了解阅读顺序和文档地图。
- 产品范围以 `可行动事务Agent-定位决策.md` 为主；字段、状态与计算以 `可行动事务Agent-UI原型规格表.md` 为主；外部依据见 `可行动事务Agent-核查修订报告.md`。真实制度优先于演示样例。
- `可行动事务Agent-学分认定Demo规格.md` 定义主场景；`可行动事务Agent-Demo状态表.md` 与 `可行动事务Agent-UI原型规格表.md` 描述演示流程和实现规格。
- `_归档草稿/` 保存历史灵感，不作为当前规范；`.obsidian/` 保存编辑器配置；`.planning/` 保存核查记录和修订前副本。

## 本地阅读与检查命令

用 Obsidian 打开此目录查看双向链接，或用 Markdown 编辑器阅读。当前没有构建、运行服务或自动测试命令；规格中的技术栈建议不代表已有实现。

在根目录执行以下命令（需安装 ripgrep）：

```sh
rg --files -g '*.md'                 # 列出文档
rg -n '学分|奖学金' -g '*.md' -g '!_归档草稿/**' .  # 检查现行场景用词
rg -n '\[\[' -g '*.md' .             # 列出双向链接，供人工核对
```

## 格式与命名约定

- 正文与协作回复使用中文，保留既有英文模型名和字段名。
- 新业务文档命名为 `可行动事务Agent-主题.md`，并更新总览的文档地图。
- 每篇文档保留一个一级标题，按层级组织章节；命令和字段使用反引号，代码块标注语言。
- 库内引用沿用 `[[文档名]]`；重命名文件时同步更新引用。
- 保留已有 YAML 元数据，修改正文时更新 `updated`；YAML 和 JSON 示例采用两个空格缩进。当前未配置格式化或 lint 工具。

## 验证要求

当前没有测试框架或覆盖率门槛。提交前人工检查 Markdown 渲染、表格和链接；部分链接指向本目录之外的笔记，应核实用途后再改动。

修改 Demo 时，交叉核对定位决策、学分规格、状态表和 UI 规格，复算示例，检查单位、四态与覆盖范围。已核验的 0 不等于缺证，局部满足不等于完整认定。区分计划、合成样例、人工核验、实时抽取与回放；测试目标不能写成已通过结果。

外部事实附来源和核查日期；产品/模型比较记录相同输入与实测条件。文档逻辑核查不能替代运行测试或用户验证。引入应用代码后再按实际工具更新构建和测试说明。

## 提交与 Pull Request 建议

当前目录未初始化 Git，无可验证的提交历史。启用版本管理后，建议使用简短的动作式消息，例如 `docs: 统一学分认定词表`，每次提交聚焦一个主题。

PR 应说明修改原因、涉及文档及验证结果；有相关 issue 时附链接，涉及渲染或原型展示变化时附截图。

## 数据与配置

个人成绩、获奖和学时明细不入库，示例应脱敏。避免将 `.DS_Store`、`.obsidian/workspace.json` 等本机状态混入内容变更。
