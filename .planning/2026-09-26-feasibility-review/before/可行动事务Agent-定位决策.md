## 0. 一句话定位

> 面向个人合规的**神经符号 Rules-as-Code**：LLM 做感知与归一化，确定性规则引擎做裁决（零幻觉），可归因引用做审计。

对外白话：别人告诉你「文件说了什么」，我们告诉你「**这份文件对你意味着什么、你还差什么、下一步做什么**」。

- **核心原语**：可行动事务（Actionable Obligation / Opportunity）
- **核心能力**：Requirement → Person matching + 举证
- **核心押注**：双约束缺口计算 + 证据链（其余都是背景板）

---

## 1. 起点判断（其他都是推论）

模型的智力与知识量已不是瓶颈，且只会更强；它有一个结构性空白——**不了解你**，而这个空白只能由用户供给。所以真瓶颈不是「AI 够不够聪明」，而是「**喂给它的输入质量够不够高**」。

切入点：把「整理」成本从用户身上转移到系统身上。

一句话：不做更聪明的 AI，做「**让『你』成为 AI 能用的高质量输入**」。

---

## 2. 真正的创新点（只押这一个）

不是记忆、不是标签、不是无痛输入。是：

> **把杂乱制度文本自动编译成可执行判定规则，再对用户自己的杂乱事实做带举证的裁决。**

硬且有价值的那道缝 = 「非结构化政策 → 可执行规则」的自动编译 + 双约束裁决。

对评委讲法：「我们不做模糊语义匹配，我们把它**编译成一个约束满足问题（CSP）**。」——这句拿技术分。

---

## 3. 与普通 AI / Mem 的差异：推理类型不同

**不打「输入方向」**（Mem 已支持 Slack/Gmail 双向同步、WhatsApp、日历、PDF——「谁先输入」不成立）。打**推理类型**。

|      | 普通 AI / Mem 类           | 本方案                                 |
| ---- | ----------------------- | ----------------------------------- |
| 核心对象 | Note / Context / Task   | **外部制度性事务**                         |
| 首要问题 | 我正在做什么？                 | **这件事对我有什么要求？**                     |
| 输入   | 我的工作 / 记录 / 消息          | 通知 / 简章 / 制度 / 要求                   |
| 输出   | Task / Reminder / Draft | **可行动事务（Obligation / Opportunity）** |
| 关键推理 | Context understanding   | **Requirement → Person matching**   |
| 核心能力 | Remember                | **Interpret + Adjudicate（判定）+ 举证**  |
| 下一步  | Remind / Draft          | **Gap → Prepare → Workflow**        |
| 价值   | 不忘事情                    | **降低完成事务的成本**                       |

## 4. 红海评测（分层看，不能一句话定）

| 层                    | 红 / 蓝    | 判断                                                                                                |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------- |
| 广义「AI + 个人文档 / 第二大脑」 | 🔴 血海    | Mem / Notion / Reflect / Tana / Capacities + 国内豆包 / Kimi / **腾讯 ima.copilot** / WPS AI。**已弃这层，对** |
| 窄楔「条款级判定 + 举证」       | 🟡 浅红，非蓝 | govtech / legaltech 早有「资格判定」品类，机制成熟（Rules as Code）                                                |
| 二课双约束缺口计算（Demo）      | 🟢 真空位   | 但市场小、频次低                                                                                          |

**相似产品（此前只盯 Mem，漏了更危险的）：**

- **Google NotebookLM**——免费、多文档、答案**带出处引用**。这是「证据链」claim 最危险的对手，不是 Mem。差异：NotebookLM 只做 grounding / 引用，**不裁决（pass/fail）、不算数值缺口**。
- **腾讯 ima.copilot**——中文个人知识库 + 问答 + 来源，直接撞国内场景。
- **资格判定本身不新**：Benefits.gov、TurboTax 访谈式报税、Instrumentl（grant matching）、**OpenFisca**（法条→福利资格引擎）。你的机制在 govtech 叫 **Rules as Code**。

**结论**：方向对（判定 ≠ 记忆），楔子选得准，但护城河薄。真护城河 = **已核验规则集 + 用户事实数据的网络效应**，不是端、不是中文、不是语言。诚实讲这点比吹壁垒强。

## 5. 三大必答软肋 + 应对（评委必问，答不出当场垮）

| 软肋                       | 事实                                                  | 应对                                                                |
| ------------------------ | --------------------------------------------------- | ----------------------------------------------------------------- |
| **频次 / 留存**              | 学分认定 = 高痛但**极低频**（一辈子认定一两次）。用 Pain×Frequency 矩阵一测就露 | 学分认定当**钩子**（demo 炸裂）；**奖学金（年）/ 通知报名（周）作留存主线**。别把低频场景说成产品主战场       |
| **竞品（NotebookLM / ima）** | 免费、已知、带出处引用，看着像「证据链」                                | 预埋应答：它们只 **grounding + 引用**，**不裁决、不算数值缺口**；我们做的是 Adjudicate + Gap |
| **护城河薄**                 | LLM 抽取会商品化，领域规则可抄                                   | 诚实归因：护城河 = **已核验规则集 + 用户事实数据网络效应**；不吹端 / 中文 / 语言                  |

> Pain × Frequency：高痛低频是**止痛药**（怕毕不了业），demo 好、留存差。必须有高频入口兜底。

## 6. 产品边界

**核心押注**：双约束缺口计算 + 证据链。

**增（提 Demo 密度 / 防守力）：**
- 缺口按**关闭成本排序**（先补哪个最省力）
- **反事实 what-if**：「参加这个大创 +10 学时 → 缺口清零 ✓」——一行逻辑，巨大 wow，证明真在算
- 例外条款 → `UNKNOWN` 态，主动示弱 = 诚实边界，评委吃这套

**删（从 pitch 拿掉，不是从产品）：**
- 意向层 Intent Layer（美但不可证伪、demo 慢）→ 留一句路线图
- 主动提醒（Mem 红海，3 分钟里价值低）
- 团队 / 企业版 → 各一句带过，别演
- 多模态输入（语音 / 微信 / 拍照）→ MVP 只 PDF/Word/图片+文本
- 关系图谱可视化（藏后台，不做卖点）

**明确不做**：通用文档管理 / 网盘 / 笔记软件 · 开放式聊天 · 用户自建标签 · 全能输入 · 自动提交外部系统。

## 7. 主 Demo：第二课堂学分认定

**为什么选它**（而非奖学金）：
- 命中「**总量达标 ≠ 分类达标**」——双约束、各类不可抵扣，学生最痛又最看不见
- 输出**数量缺口**（「再修 8 学时」）而非资格判定（「你不合格」）→ 天然可行动
- 判定**纯数值** → 完美适配「LLM 归一化 + 规则判定」，零幻觉
- **无学术诚信风险**（只算数、列清单，无代写）

**高潮屏**（整个 pitch 就是这一屏）：

```
总量  128 / 120 ✓ 已达标
      ← 停 2 秒，让评委以为够了
分类明细
  ✓ 社会实践 32/20   ✓ 志愿服务 18/10   ✓ 思想成长 24/20
  ⛔ 创新创业 12/20  差 8 学时
  ⚠  文艺体育  0/10  差 10 学时
结论：总量达标 ≠ 认定通过。你还差 2 类共 18 学时。
```

**72h 现实约束**：3 份真实文件真解析（培养方案 + 认定办法 + 教务导出学时）；只真做 **1–2 类**（创新创业 + 文艺体育）；**先定单位换算（学时/学分）再动代码**；**赛前实测教务能否导出真实学时**（第一风险）。

**公司 Demo**：做广不做深，一句话证明可迁移，不做同等深度。

## 8. 路演故事线

**弧**：陷阱钩子 → 命名反派 → demo 证明 → 拉远成一类能力。

1. **钩子 = 陷阱**：上来甩高潮屏，先让人以为「够了」，再翻车。别用「模型不了解你」开场（太哲学，前移到中段）。
2. **反派**：不是「AI 不够聪明」，是「**总量达标的假象**」/「信息进来了，事情没往前走」。
3. **证明**：真文件跑通 + 反事实 what-if。
4. **拉远**：「这不是学分工具，是**一类能力**」——Document → Requirement → Person → Evidence → Gap → Action。换奖学金、换教育局通知同一套。

**StoryBrand**：学生是英雄，产品是向导，别让 AI 当主角。

**收尾**：「AI 已经很会回答问题了。我们想解决的，是信息进入之后，**事情怎么真正往前走**。」

## 9. 理论弹药（对口新定位）

> ⚠️ 旧附录 B 的文献（A-MEM / LoCoMo / Mem0 / PIM）支撑的是**旧的「记忆」定位**，与新定位（裁决）**错位**，退居毕设用。新定位换下面这批：

| 文献 / 项目 | 用途 |
|------|------|
| **Rules as Code**（OECD OPSI《Cracking the Code》；新西兰 Better Rules；**Catala** POPL/ICFP 2021） | 最强学术锚：把法条/制度编译成可执行、可审计、带溯源的规则——几乎是本产品的学名 |
| **OpenFisca** | 开源法条→资格引擎，国家级落地，证明范式可行 |
| **Logic-LM**（Pan et al., EMNLP 2023 findings） | LLM 翻成符号形式、外部求解器推理，忠实度↑。**精确对应「LLM 归一化 + 规则判定」**，给「零幻觉」背书 |
| **LegalBench**（Guha et al., NeurIPS 2023）/ **SARA**（Holzenberger 2020） | 论证「为什么不能让 LLM 直接判条文」→ 所以要规则引擎 |
| **ALCE**（Gao et al., EMNLP 2023）/ Attributed QA | 把证据链从「功能」升成「可信度机制」（可归因生成） |
| Gilbert et al.（cognitive offloading） | 认知卸载：为何把负担交给外部系统 |

**用它秒杀「你这不就是 RAG + LLM 吗」**：
> RAG 到「理解内容」为止、且不保证正确；神经符号里**判定是符号的、可验证的**，RAG 做不到。

## 10. 演进路径

| 阶段 | 形态 | 说明 |
|------|------|------|
| 1 · 个人版 | 我的大学事务系统 | 一人用，沉淀个人信息 |
| 2 · 团队版 | 团队聚合 Agent | 每人都在用、都沉淀后汇总；成员对汇集 Agent **白盒可视** |
| 3 · 企业版 | Document-driven Workflow | 文件→判断谁做什么→备料→执行→汇报 |

企业侧入口**不是**「企业 AI 知识库」（Glean / Notion / 飞书 / M365 已极强），而是上述流程。
⚠️ 企业侧**未做真实访谈**，属方向假设，路演只能说「下一阶段延伸」。

## 11. 决策清单（团队现在拍板）

1. **押不押「事务」原语？** → 必须押，否则回到 Mem 红海无胜算
2. **72h 砍到哪？** → 1 场景 × 1 输入（PDF）× 3 分钟；校园做真，公司做短
3. **频次软肋** → 认同「学分认定当钩子、奖学金/通知作留存主线」？
4. **企业侧** → 赛前访谈 2–3 人（老师/辅导员/行政）or 明确标注「方向假设」？
5. **命名** → 暂不定名，核心假设验证后再做命名 + slogan + Logo
