# 可行动事务 Agent · Idea 完善方案

导航：[[可行动事务Agent-00-总览|文档总览]] · 分类：产品方案

> 本版承接9月26日公开市场调研，吸收9月27日产品、技术和官方流程反例复核。用户可触达大学生及校园社团；团队、企业仍为假设。问题处置与审定依据见 [[01-产品方案/可行动事务Agent-问题处理与方案审定|可行动事务Agent-问题处理与方案审定]]。

## 1. 产品定位

**帮助准备竞赛或项目报名的学生，把通知要求与手头资料逐项对照，形成有依据、可带走的准备清单；有下一次任务时，再复用本人选择保存的内容。**

保留原始愿景：让个人资料、经历和意向在下一件事中继续有用。先交付眼前的准备结果，记忆随使用积累，不要求用户先整理全部个人档案。

一句话介绍：**“先看这次要准备什么，再核对手头哪些能用、哪些需要更新，把愿意保留的内容留给下一次。”**

首轮希望减少要求对照和版本复核，不承诺自动找回所有散落文件。找文件、选择、上传和确认都算使用成本；记忆、引用和生成清单已有强替代，独立产品优势尚未证明。

## 2. 为什么选择这个切口

| 路线 | 判断与取舍 |
|---|---|
| 通用个人知识/记忆平台 | 保留为愿景；Mem、remio、通用AI等已覆盖相关能力，建库和迁移负担过大 |
| **竞赛/项目报名材料复核与复用** | 当前推荐；通知、要求、资料和产物均可观察，能比较两次完整任务成本 |
| 社团材料收集与交接 | 先观察一位负责人的个人准备过程；未证明表单/共享盘不足前，不做多人产品 |
| 团队与企业平台 | 独立假设，不是个人版收入不足时的必然升级路线 |
| 第二课堂学时核对 | 保留技术备选；已有平台展示分类进度，原三条件算法和合成数据仅适用该场景 |

官方通知证明多材料、版本、签字和多渠道流程存在，不能证明用户普遍痛苦或愿付费。若同题比较发现现有AI加模板同样省事，应改做模板/插件，或停止独立应用投入。

第一批主要观察近期实际准备竞赛/项目材料的学生。活跃申请者、低频用户和社团负责人分组记录，不把不同任务混成一个成功比例；历史通知只作历史样本。

## 3. 完整使用过程

以下为产品设计示例，尚无完整应用或真人试用结果。9月30日新增的受控交互原型可按 [[05-交互Demo/可行动事务Agent-交互Demo使用说明|两份Demo使用说明]] 操作；其规则模拟不代表真实模型抽取已完成。

1. **通知先入。** 先展示材料、适用对象、期限、渠道及原文位置；未知身份分支先确认。附件未读、暂定时间和版本冲突保持可见。零个人资料也能得到要求清单，个人项为“未检查”。
2. **按需选资料。** 用户从现有文件夹选相关文本/PDF，可跳过，每次最多5份。按本次要求提示所需类型，不要求标签或全量迁移。
3. **逐项复核。** 显示“要求—候选资料—原文—本次限制—下一步”。本人审核会改变行动的事实与解释，再决定选用；普通勾选不能改变事实。
4. **先得到产物。** 导出可打开的Markdown准备草稿，含待办、覆盖范围、来源、版本和未确认项。准备好不等于已报名；各提交渠道和审核阶段分别陈述。
5. **自愿保存。** 结果之后再选择保存已确认事实及必要来源文本。拒绝保存不妨碍使用或导出；首版不承诺归档PDF原件。
6. **下一次重新检查。** 新建事务或重启后读到持久保存内容。演示一项稳定资料可引用，一项因新用途而需更新或不可用；纠正后旧清单先过时，新结果经复核再选用。

第二次使用的增量应超过“把原文件保存下来”。同一聊天里追加通知、重新展示静态卡片，不证明跨事务记忆。

## 4. 可靠性必须体现在行为里

| 材料状态 | 用户应看到什么 |
|---|---|
| 未检查 | 尚未提供资料或相关检查未完成；不能称个人缺材料 |
| 可引用候选 | 本次已核对的用途未发现冲突，来源可定位；仍需审阅与决定选用 |
| 需更新/确认 | 具体缺哪项事实、版本、名单或本次签字，如何补足 |
| 本次未找到 | 要求明确、选定范围非空且检查完成；仅表示该范围没有候选 |
| 不可用于本次 | 适用禁用条款和触发事实均有依据；该资料与该用途配对不能选用 |
| 无法判断 | 规则、适用性或来源冲突尚未解决，列出核实对象 |

状态针对“资料版本×本次要求”，不代替人的整体资格。没有使用史不能推断从未重复使用；确认命中禁重复条款后，不能点一下“确认”就放行。新依据或版本改变后才可重新审核。

候选、规则审核、事实审核、覆盖和本人选用分别记录。部分文件失败时可展示已找到的候选，但不得声称全文检查完毕。草稿保留未知；待更新、未知及禁用项不进入已选材料区。模型引用可定位也不自动证明解释正确。

保存后修改、停用或删除，使相关旧结果和选用标记过时；保存与导出前重新检查版本及已知有效期。旧请求晚返回不能恢复删除内容。具体契约见 [[01-产品方案/可行动事务Agent-产品定义|可行动事务Agent-产品定义]]。

本届在本机单用户环境运行。未选保存内容仅留会话内存，刷新/退出可能丢失；云模型可能接触获准发送的片段，须说明服务方与用途。删除覆盖应用内关联内容，无法撤回外部下载和云端已接收数据。演示优先用合成资料。

## 5. 西客松本届范围与展示

**冻结范围：单用户、2份演示通知、个人资料可跳过且每次最多5份、粘贴文本/可读取文本PDF。** 三个工作面为“通知要求、资料与依据、准备结果”，记忆详情放在侧栏。

必做：来源与覆盖、六种状态、Markdown草稿、选择保存、新事务重审、变更失效。文件打包、后台提醒、OCR泛化、全量采集、学校接口、自动提交、复杂资格判断、多用户和企业部署退出本届。

PDF失败可请求粘贴文本并明确限制；持久保存未完成，只能展示单次整理能力。不能用预填答案或同一聊天伪装自动分析和长期记忆。学时备选不与新主线并做。

| 展示时段 | 内容 |
|---|---|
| 0–35秒 | 目标用户与重复准备问题 |
| 35–85秒 | 通知先入、要求及适用分支 |
| 85–145秒 | 选资料、看来源、复核与选用 |
| 145–205秒 | 选择保存后新事务读取；一项禁用或需更新 |
| 205–255秒 | 纠正、旧结果过时、真实可打开清单 |
| 255–300秒 | AI分工、本届新增及边界 |

正式展示5分钟，另有3分钟问答；上述分秒为团队设计，不是解析速度承诺，预审输入和回放须标明。

官方开发窗口为10月1日14:30—10月4日09:30，共67小时。内部关口：2日18:00单次链、3日12:00保存复用与过时、3日18:00边界检查和彩排并冻结、4日09:00前完成候选包与上传检查。未达到时缩声明与功能，不临时换成两套产品。赛前仅做研究、问题交流、方案草图和通用准备；细则与外部未定条款见 [[03-参赛与路演/可行动事务Agent-西客松参赛对齐|可行动事务Agent-西客松参赛对齐]]。

## 6. 怎么验证，什么结果会改变方案

| 顺序 | 做法与必须记录的证据 | 不成立时 |
|---|---|---|
| 首次任务价值 | 先访谈6名学生、2名负责人；原型后与本人最佳方法及合理配置的通用AI＋模板比较，计入找文件、输入、确认、纠错和导出 | 改成模板/插件、缩任务；仅人工代办有效时，明确作为服务实验 |
| 记忆增量 | 两次任务单独及合计计时；比较原文件保存与结构化记忆；记录变化是否被拦住 | 保留一次性核对工具或来源索引，不强加长期档案 |
| 真实再次使用 | 按事务周期观察；同时报告机会发生率、有机会后的自然返回率、全体返回人数及材料复用项 | 机会少则考虑按次；有机会不用则查工作流和负担 |
| 收费与可持续交付 | 先研究有限任务的真实价格选择，记录支付、支持工时、模型/存储/重试/模板维护及获客 | 成本过高就缩范围或改服务形式；不自动转企业订阅 |

以上均未执行。失败和人工辅助保留在分母；失联不当“无机会”，提醒后返回与自然返回分开。关键误导不能被节时抵消。原“4/6独立完成、25%中位节时”仅是待校准的讨论信号，不是本次审定依据或自动扩大投入门槛。创始人支持时间不能按零计，正的单次贡献也不等于整体盈利。

## 7. 重新审定的结论

**设计层面通过，值得准备并尝试受控参赛原型。** 首次建档、材料可用性、版本失效、范围过大和低频指标已有具体处置；这些处置仍需实际实现。

尚未通过运行验收、用户价值或商业验证。团队版仅在负责人多个周期确有未被表单解决的问题后另立实验；企业版需独立查明岗位、付款人、权限与集成成本。保留愿景，但每次增加投入都由新证据支持。
