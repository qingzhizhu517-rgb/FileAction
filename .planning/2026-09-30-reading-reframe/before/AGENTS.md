# 文档协作规范

## 项目结构与文档职责

本仓库是西客松 XiHack 2026「可行动事务 Agent」的 Markdown/Obsidian 方案库。2026年9月30日按原始愿景重整：内核为 Document → 可行动事务 → Workflow，个人版主动发现、可信复用、直接行动，并按需索取信息而非建档；团队版在临时组队时按能力推荐分工，不做监督；企业版为路线图。旧方案整体归档，不再约束当前方案。

- 从 `可行动事务Agent-00-总览.md` 查阅文档地图。
- 根目录仅保留总览和本规范；业务文档按职责放入下列目录，文件均以 `可行动事务Agent-` 开头。
- `01-产品方案/`：`参赛主线方案` 维护定位、亮点、范围、展示、分工与底线。
- `02-调研与可行性/`：`竞品分析` 保存外部证据与差异判断。
- `03-参赛与路演/`：`路演答辩应答卡` 维护展示与问答口径。
- `05-交互Demo/`：9月30日赛前交互设计稿（旧方案，规则模拟、未接模型），已降级，参赛时如实申报。
- `90-历史归档/`：`旧方案-2026-09-30/` 保存被取代的旧方案；`原始草稿/` 保存原始愿景，正文原样保留，引用的两张图片尚未提供；另有核查修订报告。
- `.planning/` 保存来源、核查及整理前副本，既有快照不随现行文档改写；`.obsidian/` 为编辑器配置。

## 阅读与检查命令

```sh
rg --files -g '*.md'                   # 列出文档
rg -n '\[\[' -g '*.md' .               # 检查双向链接
python3 05-交互Demo/serve.py            # 启动赛前交互设计稿
node --test 05-交互Demo/tests/engine.test.mjs  # 设计稿规则测试
```

## 格式与命名

正文及协作回复使用中文。新业务文件采用 `可行动事务Agent-主题.md`，放入职责目录并同步总览；每篇一个一级标题，逐级组织章节。原始草稿与归档文档不改写正文。

库内用带目录的 Obsidian 链接 `[[目录/文档名|可读名称]]`，表格中的别名分隔符写成 `\|`。移动或重命名时同步现行引用。保留 YAML 元数据，正文变更更新 `updated`；该字段不代表外部来源重新核验。YAML/JSON缩进两个空格，代码块标明语言。

## 验证要求

文档修改后核对标题、表格、围栏和链接。修改前将原文与路径清单保存到独立的 `.planning/日期-任务/`。赛中代码变更须运行测试并实际走通浏览器操作。

## 真实性底线

- 外部事实附来源及实际读取日期；设计修改不冒充重新核验。
- 演示资料为合成并明示；不编造用户、访谈、经历或测试结果。
- 赛前资产（含交互设计稿）如实申报；本届成果须在官方67小时窗口内完成。
- 模型初稿与用户确认分开；准备清单不等于已报名，材料齐全不等于资格通过；不说“零幻觉”“竞品都做不到”。
- 本机保存不等于云端模型看不到数据；个人资料不入库，示例脱敏。
- 团队、企业与商业路径是路线图假设，各层分别以真实信号验证。
- 避免提交密钥、`.DS_Store`、`.obsidian/workspace.json` 等本机状态。
