## 1. 是否可行

**作为西客松 AI软件应用赛道的候选 idea，建议继续准备。** 最新方向是校园个人事务中的材料复用；用户可触达大学生及校园社团。公开调研已执行，真实任务对照、重复使用和付费仍待验证。

可保留的核心是双约束核对、条款与事实溯源、显式未知及独立假设试算。这些需求可以用现有技术组合实现，不依赖新的基础模型突破。但规则来源、适用性、记录完整性和人工审核成本决定最终结果是否可靠、是否值得使用。

| 层面 | 当前判断 | 依据与缺口 |
|---|---|---|
| 文档逻辑 | 可以修正并形成统一规格 | 统一状态、数字、范围及真实性后可作为开发依据 |
| 限定原型 | 技术上有条件可行 | 简单规则比较可实现；尚未跑通目标学校数据 |
| 本届现场 Demo | 有条件可完成的方案 | 正式窗口67小时，须留出活动、休息与封包时间；旧72小时假设已撤回 |
| 用户价值 | 待验证 | 没有证据表明比现有教务页面、人工表格或通用 AI 更省事 |
| 商业模式 | 未验证 | 无付费试点、重复使用或采购证据；个人与机构需求须分别验证 |
| 真实部署 | 当前证据不足 | 尚无应用、权限、数据处理与运行测试；不应直接用于正式认定 |

## 2. 关键问题与修订决定

以下问题来自修订前正文，不应再作为对外承诺。

| 问题 | 为什么影响可行性 | 修订决定 |
|---|---|---|
| “规则层零幻觉” | 错误抽取、版本、单位或重复记录会产生稳定的错误 | 改为已核验规则与事实下可复算，补人工审核与拒判 |
| 宣称自动编译、CSP 求解突破 | 实际只描述阈值比较，没有通用编译器或求解器 | 使用具体架构描述；复杂约束后置 |
| 把 RAG 与规则引擎对立 | 检索和确定性执行可以组合 | 改为可组合的工程分工 |
| 分类合计 86，总量却为 128 | 演示不能复算 | 明确第六类 42，使六类合计 128；全部标为合成样例 |
| 0 学时等于缺证 | “知道为零”与“不知道多少”会触发不同动作 | 已核验 0 为 `CONFLICT`；缺证为 `MISSING`，数值 `null` |
| 事实冲突、单位不明仍计算 | 缺口失去有效依据 | 标记 `UNKNOWN`，先解决冲突或适用性 |
| 创新 +10 后宣称缺口清零 | 文体仍缺 10，且假设活动尚未认定 | 只关闭创新缺口；试算不写回真实记录 |
| 只核验两类却宣布整体通过 | 部分覆盖不能证明全部要求满足 | 明确总量与两类共三条件；其他类别仅显示导入汇总 |
| 奖学金与学分主线并存 | 字段、逐屏内容和测试口径互相冲突 | 现行 Demo 统一为学时核对；奖学金只作后续假设 |
| 输入范围不断扩大 | PDF、Word、截图、语音和多校格式超出短期预算 | 先文本 PDF + 一种 CSV，其他格式后置 |
| “需要实测”写成“已经实测” | 路演稿会虚构完成状态 | 删除已实测声明；结果必须有日期、样本和记录 |
| 虚写亲身经历及团队技能 | 不能从方案推导成员背景 | 删除未经用户确认的个人事实 |
| 竞品不会算、市场真空 | 未做同输入对照，也无完整市场调查 | 删除绝对断言，改为可复现竞品和替代流程测试 |
| 论文给本项目正确性背书 | 他人数据集实验不能直接迁移到本项目 | 论文仅支持方法背景与评测设计 |
| 低频“一生两次”、市场 4700 万等 | 无年份、口径或目标人群证据 | 移除数字承诺，回到目标校真实触发任务 |
| 用户数据自动形成网络效应 | 个人复用与跨用户增益不同，且存在数据权限约束 | 改为潜在规则、评测及维护资产 |
| 换场景就“无风险” | 不代写不等于完成个人信息、权限和质量治理 | 保留产品边界，并增加真实数据处理条件 |
| 72h 完全可行、参赛赢面大 | 没有实际人员、样本或评分依据 | 改为条件预算及停止/降级条件，不预测胜率 |

## 3. 前轮统一的学时备选方案

**一所学校、一版制度、一个适用群体；1–2 份文本制度 PDF + 一种 CSV 导出；先核验总学时、创新创业、文艺体育三个条件。**

执行链为：提取候选 → 人工核验规则、来源与口径 → 确定性比较 → 逐条件结果与证据 → 独立试算/核对清单。制度文本作为数据处理，不执行其中的指令或模型生成的代码。

四态按 `UNKNOWN` → `MISSING` → 有效数值比较的顺序判定。合成样例中总量 128/120、创新 12/20、文体 0/10；其他类别 32、18、24、42 只作汇总，不宣称已经完成规则核验。总量和分类缺口不能相加当作毕业要求。

学时备选技术契约仍由 [[90-历史归档/旧方案-2026-09-30/04-学时备选/可行动事务Agent-UI原型规格表|可行动事务Agent-UI原型规格表]] 维护。当前材料主线的范围、契约和审定分别见 [[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-Idea完善方案|可行动事务Agent-Idea完善方案]]、[[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-产品定义|可行动事务Agent-产品定义]]、[[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-问题处理与方案审定|可行动事务Agent-问题处理与方案审定]]，不沿用学时算法作通用判断。

## 5. 赛后真实试点仍需回答的问题

以下用于判断完整产品与真实部署，不要求在当前idea初稿或报名之前全部完成。赛前可以了解公开制度并设计合成记录方案；本届具体执行与交付见参赛对齐篇。

1. **数据关**：目标学校、有效版本、适用群体是什么？能否有权取得制度及一种完整导出？目标校若只有截图，当前 MVP 是否需要重新估时？
2. **正确性关**：规则审核人能否给出参考答案？单位、重复计入、分类、统计期、例外和版本变化能否明确处理？
3. **价值关**：与人工表格、教务展示及通用 AI 相比，含人工复核的总耗时是否更低，重要遗漏是否更少？
4. **成本关**：每次调用、解析、存储、重试与人工校正规则的真实成本是多少？冷启动与持续维护分别由谁承担？
5. **商业关**：谁反复触发任务、谁付款、为什么不继续用现有方法？机构采购与个人使用分别有什么证据？

赛后试点先完成数据关，再按 [[90-历史归档/旧方案-2026-09-30/02-调研与可行性/可行动事务Agent-可行性分析|可行动事务Agent-可行性分析]] 开展小样本验证。30条规则用例和10组端到端样例是扩展建议，不是赛事门槛，也不是统计意义上的普遍可靠性证明。测试指标事先确定，不能按结果倒改。
