# 可行动事务 Agent · Demo 状态表

> 180 秒 Demo 的 **11 个状态 / 7 屏**原型规格。配套文档：[[可行动事务Agent-产品定义]]
> 🔧 开发级规格（字段 / 接口 / 排期）见：**[[可行动事务Agent-UI原型规格表]]**

## 核心论证链（全片只讲这一条）

```
Document → Requirement → Person → Evidence → Gap → Action
```

## 四个阶段

| 时间 | 阶段 | 评委应该看到什么 |
|------|------|-----------------|
| 0–42s | **Understand** | AI 能把真实通知变成结构化 Requirement |
| 42–82s | **Adjudicate** | AI 能把 Requirement 与具体用户 Context 对上 |
| 82–125s | **Verify** | AI 能判断 Gap，并给出 Evidence Chain |
| 125–180s | **Act** | AI 能把判断结果转成可确认的材料 Workflow |

> `Understand → Adjudicate → Verify → Act` 这四个词比 `Context → Intent → Action` 更适合本项目——它们直接对应你这次真正想证明的能力。

---

## ⚠️ 前置规则：真实性分级（最重要的一节）

Demo 里一旦有假，被拆穿的代价是全盘归零。因此**先定规则，再定屏**：

| 等级 | 含义 | 范围 |
|------|------|------|
| 🟢 **必须真实** | 现场真跑，不能写死 | ① 从真实 PDF 抽出条件项 ② 原文高亮定位 ③ 条件 ↔ 事实的逐条匹配判定 ④ Gap 计算 ⑤ 证据链的来源文件与位置 |
| 🟡 **允许预置** | 不违背真实性 | 个人 Context 数据（成绩 / 获奖 / 实践证明）· 学校申请表模板 · 学校评定办法条款库 |
| 🔴 **禁止伪造** | 一旦出现即 Demo 失败 | 判定结果写死 · 证据来源指向不存在的文件 · 材料包内容无中生有 |

### 一条判据记住全部

> **预置只允许发生在「输入侧」，不允许发生在「输出侧」。**

- 输入侧预置（"用户已经上传过这些材料"）＝ 合理，真实产品也是这个前提
- 输出侧预置（判定结论、证据来源是提前写好的）＝ 造假，且**评委换一份 PDF 就露馅**

---

## 屏 A ｜ 问题屏

### 状态 0 ｜ 开场　⏱ 0–8s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 极简首页，中央一句话；下方一份 PDF 缓慢浮现。**不要复杂 Dashboard** |
| 文案 | 「收到一份文件，它到底和我有什么关系？」 |
| 数据 | `关于开展2026年度国家奖学金评审工作的通知.pdf` |
| 动效 | PDF 淡入 + 轻微上浮（1s 内完成，不要炫技） |
| 真实性 | 🟡 静态文案 |
| 证明什么 | **问题不是「文件太多」，而是「文件进入之后，用户不知道它对自己意味着什么」** |
| 最易做砸 | 一上来放 Dashboard / 侧边栏 / 功能列表 → 评委立刻归类为「又一个知识库」 |

---

## 屏 B ｜ 输入屏

### 状态 1 ｜ 零整理输入　⏱ 8–20s

| 项 | 内容 |
|---|---|
| 屏幕元素 | **直接把 PDF 拖进去**。不出现「上传按钮 → 选择文件 → 等待 → 文件列表」的传统流程 |
| 文案 | `拖入通知 PDF` → `AI 正在理解……` |
| 数据 | 同状态 0 的 PDF |
| 动效 | 文件吸附入区 → 进度态 |
| 真实性 | 🟢 真实读取文件 |
| 证明什么 | 「用户不整理，系统负责理解」 |
| 最易做砸 | 把「自动整理文件」讲成核心卖点——**它只是入口，不是价值** |

---

## 屏 C ｜ 事务屏（状态 2 + 3 同屏递进，不切屏）

### 状态 2 ｜ Requirement Extraction　⏱ 20–42s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 左：PDF 原文视窗　右：结构化条件卡　中间：点击条件 → 原文对应位置高亮 |
| 数据 | 事务名称 / 截止时间 / 面向对象 / 学业要求 / 材料清单（逐条） |
| 动效 | 条件卡逐条刷出；点击任一条 → 左侧原文高亮 + 平滑滚动定位 |
| 真实性 | 🟢 **必须真实** |
| 证明什么 | **结构化条件 ← 原文证据**。这是 Evidence Chain 第一次出现，也是整场 Demo 的信任起点 |
| 最易做砸 | 只展示「AI 总结」。**必须展示「条件 ↔ 原文出处」的双向定位** |

### 状态 3 ｜ 认知转折：这不是一份通知　⏱ 42–62s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 卡片上浮覆盖原文区，标题变化：`一份文件` → `一件与你有关的事务` |
| 数据 | 事务名 / 截止 10 月 10 日 / 还需准备 3 项 / Why Me 三条 |
| 动效 | 标题文案替换（这是全片最重要的一个动效，值得单独打磨） |
| 真实性 | 🟡 Why Me 的三条理由来自预置 Context，但**匹配判定必须真实计算** |
| 证明什么 | **对象转换**：从「这是一份文件」到「这是一件可能与我有关的事务」 |
| 最易做砸 | 把 Why Me 写成「AI 猜你可能感兴趣」。**它是「用通知里的条件去匹配用户已有事实」，不是兴趣推荐** |

---

## 屏 D ｜ 匹配屏

### 状态 4 ｜ Context Matching　⏱ 62–82s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 左右对照：左列「通知要求」←→ 右列「我的信息」，中间连线 |
| 数据 | 本科生←→本科生 ✓ ／ 年级←→大三 ✓ ／ 成绩←→成绩记录 ✓ ／ 获奖经历←→获奖材料 ✓ ／ 社会实践←→**尚未发现** |
| 动效 | 连线逐条连接，命中为实线，未命中为虚线 |
| 真实性 | 🟢 **必须真实**（这是核心的技术证明屏） |
| 证明什么 | **Requirement ↔ Evidence 的逐条映射能力** |
| 最易做砸 | ❌「AI 觉得你适合」❌「智能推荐」❌「你的画像高度匹配」——这些词太虚。**要让评委看到的是「条件 → 用户事实 → 匹配结果」三段式** |

---

## 屏 E ｜ 缺口屏（状态 5 + 6，证据链为可展开层）

### 状态 5 ｜ Gap Analysis　⏱ 82–105s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 上下两段：`你已经具备什么` / `还缺什么` |
| 数据 | ✓ 成绩证明 ✓ 获奖证明 ✓ 实践经历　⚠ 申请表 ⚠ 指定格式个人材料 ⚠ 辅导员审核材料 |
| 底部汇总 | **「当前还有 3 项材料需要准备」** |
| 动效 | 分段展开 |
| 真实性 | 🟢 必须真实（由状态 4 的结果计算得出） |
| 证明什么 | 「这件事与你有关」还不够，**「你距离完成它还差什么」才是价值** |
| 最易做砸 | ❌ **绝对不要写「预计准备时间 3 小时」**。时间预估不可靠，一旦报错，用户对你所有判定的信任一起塌。改成「还需准备 3 项材料」——**这个能算准** |

### 状态 6 ｜ Evidence Chain　⏱ 105–125s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 点击任一 `✓` 项 → 右侧滑出证据面板 |
| 数据 | 来源文件 / 证据内容 / 对应条件条款 / 匹配状态 |
| 示例 | 为什么判定「已具备」？来源：`《个人获奖证书.pdf》`　证据：2025 年度 ×× 奖学金　对应条件：「具有相关获奖经历」　匹配状态：✓ 已满足 |
| 动效 | 右侧面板滑出，可连续点开多条 |
| 真实性 | 🟢 **必须真实** |
| 证明什么 | **不是「我们的 AI 很聪明」，而是「我们的 AI 每一个判定都可以追溯」** |
| 最易做砸 | 做成静态示意图。**对于「资格判断」类产品，可追溯性的价值远高于漂亮的 Agent 动画** |

---

## 屏 F ｜ 执行屏（状态 7 + 8，执行日志 → 材料工作区）

### 状态 7 ｜ Agent 工作状态　⏱ 125–145s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 用户点击「开始准备」→ 执行日志逐条推进 |
| 日志条目 | ✓ 读取通知要求　✓ 找到已有成绩材料　✓ 找到获奖证明　✓ 整理相关实践经历　→ 建立材料清单　→ 标记缺失材料　→ 生成待确认材料包 |
| 真实性 | 🟡 日志节奏可脚本驱动，但**每一条必须对应真实发生的动作** |
| 证明什么 | Agent 味道：从「判断」进入「行动」 |
| 最易做砸 | ① 让 Agent 一开场就说「你好，我是你的 AI Agent」→ 变成普通聊天机器人<br>② 措辞越界：只能说**整理 / 归档 / 校对 / 匹配**，❌ 不能说「帮你生成获奖经历」，更不能「自动编造个人事迹」 |

### 状态 8 ｜ Material Workspace　⏱ 145–162s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 材料工作区清单 + 单项详情 |
| 数据 | 01 申请表 ⚠ 待填写　02 成绩证明 ✓ 已找到　03 获奖证明 ✓ 已找到　04 实践材料 ✓ 已找到　05 个人材料 ⚠ 待补充 |
| 单项详情 | 来源：`2025实践证明.pdf`　系统建议：将该材料作为「社会实践证明」　`[确认使用]` |
| 真实性 | 🟡 材料映射可半预置，但**建议动作必须基于真实匹配** |
| 证明什么 | 从「判断」进入「行动」的那一步 |
| 最易做砸 | 让人机关系变成「AI 替我决定」。**应该是「AI 负责整理和判断，我负责确认」** |

---

## 屏 G ｜ 确认与回环屏

### 状态 9 ｜ Human Confirmation　⏱ 162–174s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 材料包汇总 + `[确认并导出]` |
| 数据 | 3 项材料已整理 / 2 项材料待补充 |
| 真实性 | 🟢 真实交互 |
| 证明什么 | **刻意展示「不自动提交」**。涉及资格判断、个人材料、学校提交、教师审核——Human-in-the-loop 是必要的，它让系统更可信 |
| 最易做砸 | 为了显得厉害而演示「AI 自动提交」→ 在校园场景里这是信任上的自杀 |

### 状态 10 ｜ 最终状态：回到最初那份 PDF　⏱ 174–180s

| 项 | 内容 |
|---|---|
| 屏幕元素 | 回到开场的同一份 PDF，但它已经变了 |
| 变化后 | → 与我有关　→ 需要准备 3 项材料　→ 已找到 3 项已有证据　→ 还缺 2 项　→ 已生成待确认材料清单 |
| 真实性 | 🟢 由前面真实结果汇总 |
| 证明什么 | **首尾呼应，让评委在 3 分钟后能复述出一句话**（见下） |
| 最易做砸 | 最后又切回 Dashboard / 展示一堆统计图 → 力量全散 |

> **希望评委离场时能复述的那一句话**：
> 「它不是在总结通知，而是在判断这份通知对具体的人意味着什么，并告诉他有什么证据、缺什么、下一步做什么。」

## 状态 ⇄ 屏幕映射总表

| 屏 | 状态 | 时间 | 阶段 | 核心证明 |
|----|------|------|------|---------|
| A | 0 | 0–8s | — | 问题定义 |
| B | 1 | 8–20s | Understand | 零整理输入 |
| C | 2 · 3 | 20–42s | Understand | 条件抽取 + 原文举证 → 对象转换 |
| D | 4 | 62–82s | Adjudicate | Requirement ↔ Evidence 映射 |
| E | 5 · 6 | 82–125s | Verify | Gap + 证据链 |
| F | 7 · 8 | 125–162s | Act | Agent 执行 + 材料工作区 |
| G | 9 · 10 | 162–180s | Act | 人工确认 + 回环 |

**7 屏承载 11 个状态。** 180 秒切 11 次屏会造成视觉噪音；**同屏递进优于切屏**，切屏次数应控制在 7 次以内。

## 开工前必须准备的数据

| # | 素材 | 要求 |
|---|------|------|
| 1 | **1 份真实通知 PDF** | ⚠️ 关键：**通知里必须有明确的条件条款**（成绩要求 / 年级要求 / 材料要求），否则条件抽取没有说服力。建议用真实的奖学金或评优通知，展示时脱敏 |
| 2 | 个人材料一套 | 成绩单 1 份、获奖证书 1–2 张、实践证明 1 份（均可脱敏） |
| 3 | 缺口设计 | **必须保证至少覆盖 1 条「已满足」+ 1 条「缺失」+ 1 条「需人工判定」**，否则 Gap 面板不立体、Demo 不成立 |
| 4 | 学校申请表模板 | 可选，用于状态 8 的材料映射演示 |

> 第 3 条最常被忽略：**选源文件时就要先设计好缺口**，而不是等做完了再看跑出什么。

## 评委可能打断的点 + 应答

| 打断 | 应答 |
|------|------|
| 「这不就是 RAG + LLM？」 | 如果只是把文件总结出来，那确实是 RAG。我们的 Agent 要完成四次判断：① 这件事和谁有关 ② 它要求我做什么 ③ 我还缺什么 ④ 下一步怎么完成。**RAG 到「理解内容」为止** |
| 「Mem 也能做。」 | **不是它做不到，是它不需要做。** Mem 的任务是跟上你的工作上下文，不需要做「逐条判定你是否满足《评定办法》第 3 条」并给出证据。这是推理类型的不同 |
| 「换一份通知还行吗？」 | **诚实回答边界**：当前限定在同类型的校内制度性文件。**不要吹通用**——说通用就等于承诺通用规则引擎，那是 18 个月的事 |
| 「AI 判定错了怎么办？」 | 两个机制：证据链可追溯（每条判定能展开到条款 + 来源文件）+ 关键动作用户确认 |
| 「你们凭什么比 Mem 好？」 | **不比它好，是不同的问题。** 它解决「我正在做什么」，我们解决「别人给我的要求，对我意味着什么」 |

**可选加分项**：现场邀请评委提供一份通知，当场跑。这是最强的证明——**但只在规则解析足够稳时才做**，否则留作 Q&A 环节的备用方案。

## 明确不做的屏

这十项**现在都不做**。每一个都会让评委产生「所以你到底解决什么？」的疑惑：

❌ 知识库首页　❌ 标签系统　❌ 信息资产图谱　❌ Memory 页面　❌ 「AI 记住了你什么」　❌ 通用聊天窗口　❌ 多 Agent 协作动画　❌ 多种通知同时处理　❌ 通用规则引擎　❌ 自动提交第三方系统

### Mem 实测只测这 4 个问题

1. 能不能正确抽取**所有资格条件**？
2. 能不能把条件与**预置个人材料**逐条匹配？
3. 能不能对每个「满足 / 不满足」给出**证据来源**？
4. 能不能把缺口变成**可执行的材料清单**？

> 实验目的不是「我要证明 Mem 不行」，而是确认：**面对同一份真实制度文件，Mem 和我们的系统，最终产生的判断对象是不是不同。**
> **把 Mem 的真实输出截图留下来**——如果它已经做到其中 70%，反而是好事，我们就继续往下钻到真正不可替代的那 30%。
