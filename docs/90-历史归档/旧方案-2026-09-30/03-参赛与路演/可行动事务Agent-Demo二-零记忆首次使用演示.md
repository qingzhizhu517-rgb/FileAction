# Demo 二：没有用户记忆，也能完成本次准备

导航：[[可行动事务Agent-00-总览|文档总览]] · [[05-交互Demo/可行动事务Agent-交互Demo使用说明|启动与使用说明]] · [[90-历史归档/旧方案-2026-09-30/03-参赛与路演/可行动事务Agent-Demo一-已有记忆上传演示|Demo 一：已有记忆]]

**演示目标：第一次使用就能获得有来源的准备清单，不需要先建个人档案，也不需要同意长期保存。** 无记忆表示没有跨事务留存，用户仍可自愿提供本次所需的少量资料。

[打开 Demo 二网页](../../../05-交互Demo/demo-no-memory.html)。先启动本机服务。与Demo一共用同一份合成N02通知，便于比较起点；分析是受控规则模拟，不接真实模型。

## 1. 演示素材与起点

进入本页，打开侧栏“演示工具”→“清空本演示数据”，确认侧栏为“0份已保留资料”。本页使用独立的浏览器存储空间；即使Demo一已经保存资料，这里也不能出现那位学生的身份、项目或成果。

| 阶段 | 输入 | 允许出现的信息 |
|---|---|---|
| 首次进入 | 没有个人资料或已保存记忆 | 产品说明与操作入口，不预填姓名、经历或证书 |
| 只上传N02通知 | 公共要求与本次主动确认的适用分支 | 通知要求、期限、渠道、附件缺口；全部个人材料项为未检查 |
| 自愿补少量资料 | 本次选择P01身份、P02经历、P03旧名单，共3份 | 仅据这3份内容提出候选和待办，不能推测未提供的私人事实 |
| 导出后拒绝保存 | 不创建跨事务记忆 | 下载草稿仍可保留；新事务重新回到没有本次私人资料的状态 |

不使用“零记忆”来暗示用户没有材料、没有资格或没有经历。文件由演示者实际选择，找文件的时间也属于完整任务成本。

## 2. 两分半主线脚本

| 时间 | 演示动作 | 观众应看到的结果 | 讲解要点 |
|---|---|---|---|
| 0–15秒 | 在“演示工具”清空本演示数据，展示侧栏0份已保留资料 | 没有私人事实，也没有从Demo一带来的材料 | “第一次来，一份通知就能开始。” |
| 15–40秒 | **加入通知**：点“选择通知文件”上传N02；选适用身份，核对后点“一次确认以上三项”；点“下一步：选择资料”，不添加资料，再点“先生成要求清单” | 六项要求有来源，个人材料均为“未检查”；附件A缺口保留 | “先知道要准备什么。未检查，不等于没有材料或不合资格。” |
| 40–60秒 | 在**准备清单**点“导出准备清单” | 带来源、未检查、待核实和覆盖说明的Markdown可下载 | “不用先建档，也能把这次要求带走。” |
| 60–90秒 | 点“调整资料”→“选择资料文件”，自愿上传P01、P02、P03；点“生成准备清单” | 身份和经历为候选，旧名单需更新；其他明确要求仅在本次所选范围未找到，附件相关要求无法判断 | “这次只需要三份资料，系统只依据这三份判断。” |
| 90–115秒 | 在R1、R2点“查看依据”，依次勾选“我已核对本次依据”“选用于准备清单”；关闭面板，点“导出准备清单” | 审核与选用分离；旧名单未进入已选区，待办仍保留 | “原文在这里。看过、核对过，再决定选用。” |
| 115–150秒 | 点“为下次保留”→“不保存，结束本次”→“开始新事务” | 侧栏仍为0份已保留资料，本次资料与结果不自动恢复 | “清单已经拿到，这次的个人资料可以不留下。” |

主线始终沿“加入通知 → 选择资料 → 准备清单”前进；详情和保存按需打开。排练可用通知的“使用样例”；三份个人资料可在“使用合成资料演示”内逐份选取并点“载入所选样例”，不要一键载入4份而改变本场景范围。样例载入不能称为现场上传。

选做纠正：导出前回到“调整资料”，在P02点“查看详情”→“更正为项目成员”。旧结果随即过时；重新生成、核对后再导出。额外用时应计入记录。

## 3. 两份可带走的结果

**第一次导出：只有通知的准备草稿。** 应包含N02版本、规则原文位置、期限与渠道、六项准备要求、个人材料未检查、附件A待取得。不得出现姓名、项目经历或“你没有老师确认书”等推断。

**第二次导出：加入本次3份资料的准备草稿。** 加入经核对并选用的身份/经历索引；保留旧名单需更新、本次所选范围未找到项、附件缺口与后续动作。下载文件是独立副本，结束事务不能远程回收它。

## 4. 六个关键问题如何体现

| 可行性分析中的问题 | 本Demo中的具体处理与证据 |
|---|---|
| 首次没有记忆 | 0条记忆＋通知先入＋跳过资料＋直接导出，完整展示首次独立价值 |
| 找文件与确认成本 | 用户自行选择3份相关资料，集中核对规则；“演示工具 → 运行与成本”记录寻找与辅助时间，完整计时包含上传、确认和纠正 |
| 文件存在但不适用 | P03虽然上传成功，仍是第一期名单，需要第二期新名单；不以“上传成功”冒充适用。明确禁用的完整演示见Demo一 |
| 记忆过期或纠正失效 | 本次P02更正也使旧结果过时；拒绝保存后新事务没有本次私人内容。没有跨事务记忆不等于可以忽略本次版本 |
| 支持与调用失控 | 输入失败可粘贴TXT；“演示工具 → 故障演练”最多一次自动重试，语义不明保留待核实；计数不冒充真实API统计 |
| 协作与企业扩张 | 仅准备本人事务，不共享文件、不替成员确认、不自动分派或提交；一次演示不推导企业采购需求 |

## 5. 选做的反例检查

1. **A/B隔离。** 在Demo一保存后打开本页并重置，只上传N02；本页仍不得出现Demo一私人事实。
2. **无法读取的文件。** 上传错误格式，不能用样例答案替代失败；保留未完成覆盖，提供粘贴受控文本或移除该文件的选择。
3. **未完成覆盖。** 一份文件失败、另一份可读时，只展示已读部分；未读范围可能包含的材料不能判为“本次未找到”。
4. **拒绝保存。** 先导出，再点“为下次保留 → 不保存，结束本次 → 开始新事务”，刷新后仍为0份记忆。实际存储中不应有本次来源。
5. **可选保存分支。** 另起一轮点“为下次保留”，对一份资料勾选“已核对这份资料”“保留到本机记忆”，点“保留所选资料 → 开始新事务”。此后称“选择保存后的使用”，不能继续声称零记忆。

## 6. 与已有方法比较时如何记录

两份演示的快速出结果不直接证明节时。与文件夹、表格或通用AI比较时，提供同样的通知、附件状态和个人材料，把找文件、上传、初始化、确认、纠正、检查产物和导出全部计入。

分别记录首轮、第二轮、两轮合计，以及实际可复用项、错误、辅助完成和失败。无第二次机会、未知机会、提醒后使用分开；演示者重复点开合成通知不算真实留存。模型调用为0的本原型不能用于推导真实推理成本或利润。

演示完成的结尾是：**“现在有一份可检查的准备草稿；个人信息是否留给下一次，由你决定。”** 不说材料齐全、资格通过、已提交或独立产品已经成立。

此原型形成于2026年9月30日，参赛时须如实说明既有资产；真实模型、PDF泛化、正式服务端持久化和用户价值仍需另行验收。
