# 可行动事务 Agent · 内部筛选速览

> **推荐：优先验证校园事务的材料准备与复用，竞赛/项目报名是第一候选。** 这是结合公开调研提出的方案，不代表用户已经拍板；当前没有可运行演示或真实任务验证结果。
> **原始愿景**：让已经整理过的个人资料，在下一件事情到来时继续有用。保留低摩擦输入、白盒记忆、跨文件关联和个人意向，用具体事务验证价值。
> 完整方案见 [[可行动事务Agent-Idea完善方案]]，证据见 [[可行动事务Agent-市场调研与验证]]，范围与实现契约见 [[可行动事务Agent-定位决策]]、[[可行动事务Agent-UI原型规格表]]，赛事依据见 [[可行动事务Agent-西客松参赛对齐]]。

## 一、一句话与第一批任务

**把新通知和你已有的材料对上，告诉你能用什么、还缺什么，并为下一次保留可复用的内容。**

用户已确认可接触大学生和校园社团。优先找近期准备竞赛、项目申请或评优材料的学生：手里有一份通知，也已有部分项目介绍、经历记录、证明或旧表格。首个目标是少找文件、少重复解释背景、少遗漏当次变化；不要求用户先整理完整个人档案。

输入应包含**新通知、少量已有资料和用户确认的当前目标**。读过通知不等于想报名；想参赛不等于已经报名；旧材料中的数字也不自动成为当前事实。

## 二、路线筛选与调研反证

| 路线 | 为什么值得看 | 代价与反证 | 当前建议 |
|---|---|---|---|
| 校园个人事务材料准备 | 官方竞赛通知存在双平台报名、计划书/PPT/证明准备及历史项目背景；结果可检查 | 表格、网盘、学校系统和通用AI可能已经够用；用途与版本不能自动通用 | **优先验证，竞赛/项目报名为第一候选** |
| 社团材料与交接 | 官方通知有申请、总结、报销的连续材料链；可从一位负责人观察 | 已有审批、表单与共享盘；多人权限和交接增加范围 | 相邻实验，先帮助负责人个人整理 |
| 通用个人记忆工具 | 最接近宽愿景，资料类型多 | Mem、remio、通用AI等已具备相关能力；迁移和初始化成本高 | 作为长期愿景，不从全量资料管理起步 |
| 第二课堂学时比较 | 三条件与假设试算便于展示规则执行 | PU学校指南已有总分、分类得分、最低要求与完成进度；不能以“看不见分类”推导市场 | 保留为**备选技术演示** |

公开流程证明事务存在，不证明用户痛苦、使用频次或付费意愿。北理工奖学金通知还明确禁止同一获奖成果再次申报：旧资料“找得到”不等于“本次能提交”。这些证据用于改进假设，不是用户访谈结果。

## 三、推荐演示：第二次使用才体现记忆价值

下面是拟实现的使用链，不是已经运行的产品：

```text
用户说明本次目标，加入一份新通知和少量旧资料
  → 提取材料要求、时间、渠道及适用对象候选，指向原文
  → 找到旧资料的对应内容，显示来源、用途和确认状态
  → 标明可引用候选、需更新/确认、缺少材料、无法判断
  → 用户确认或纠正一项事实，相关清单随之更新
  → 打开或导出本次材料清单
  → 第二份相关通知到来，复用已确认内容，只处理差异
  → 展示一份旧材料不能直接复用，说明原因与下一步
```

例如旧项目介绍可提供问题背景，但成员名单需确认、表格要换成当次版本、签字页仍需本人取得。如果通知明确限制重复使用某项成果，不能把旧证明直接标为可提交；规则不清时保留无法判断。

**演示至少让人看见三件事：**要求来自哪段通知，复用建议来自哪份旧资料，第二次任务到底少做了什么。只有第一份清单，能证明单次文件处理；展示记忆列表本身不能证明减少重复劳动。

## 四、白盒记忆与材料状态

每条记忆拟展示内容、来源、确认状态、适用时间、所属人和可见范围。事实、用户意向、系统建议分开；用户可以查看、确认、改正、停用或删除。停用来源后，应能检查其不再影响新结果；完整删除与共享副本处理需在真实服务前落实，不以一个按钮宣称全部完成。

| 材料准备状态 | 说明 |
|---|---|
| 可引用候选 | 找到相关内容且来源可查，仍需按本次用途确认 |
| 需更新/确认 | 资料存在，但时间、版本、格式、用途或权限需检查 |
| 缺少材料 | 当前授权可见资料中没找到通知明确要求的内容 |
| 无法判断 | 原文、适用规则或现有证据不足以得出结论 |

同一份文件可能已经找到，但缺本次签字或使用权限不明，应说明具体原因。这组状态描述材料准备，不是资格通过；既有学时 `SATISFIED`、`CONFLICT`、`MISSING`、`UNKNOWN` 只在备用的可执行条件场景使用。

最低产物是可打开、可下载的材料清单，包含来源、版本、待办与待确认项。若只输出索引就称“材料索引”；只有用户选定并实际附入文件才称文件包，均不代表已向学校或赛事提交。

## 五、本届范围与官方安排

| 项目 | 推荐安排 |
|---|---|
| 输入 | 文本PDF或粘贴通知文本，加少量项目/经历资料；不承诺任意格式和全量导入 |
| 核心能力 | 有出处的要求、少量可确认记忆、旧资料引用、需更新/缺失提示、第二次任务复用 |
| 界面 | 事项收件箱、材料与依据、准备结果；记忆详情可展开 |
| 输出 | 可打开或导出的清单；附文件打包按时间决定 |
| 后置 | OCR泛化、全量微信采集、自动全网找机会、多成员协作、企业部署、外部自动提交 |
| 备用 | 学时三个条件的既有合成演示；不要与新主线拼成两套Demo |
| 队伍与开发 | 官方1–5人，每人一队、每队一个主赛道作品；10月1日14:30—10月4日09:30，共**67小时** |
| 正式评审 | **5分钟展示＋3分钟问答**；展示需包含第二次复用及一处不能直接复用的情况 |

官方AI软件应用赛道建议准备可运行应用或入口、必要源文件、运行说明和演示录屏，核验场景与核心流程。源文件受限供授权评委核查，不统一要求公开开源。备用录屏须在10月4日09:30封包前提交。

67小时包含休息、活动、视频和封包，不能全部排成净开发。详细安排见 [[可行动事务Agent-Demo状态表]] 和 UI 规格。赛前允许问题梳理、访谈、方案草图、资料了解和通用工具准备；不得把赛前完整核心成品或本主题成片冒充现场新增，复用底座须申报。10月1日晚60秒介绍讲团队、问题和计划即可。

## 六、先验证什么，不急着扩什么

- **眼前事务**：通知要求是否提对，旧材料建议是否有出处，缺失与未知是否明确，产物能否让人实际继续准备。
- **第二次使用**：哪些内容免于重输，哪些仍需要确认；把首次导入和人工纠正成本也算进去。
- **纠错与停用**：改正事实后受影响清单是否更新；旧版本和停用来源不继续悄悄生效。
- **最佳已有方法**：与用户实际使用的文件夹、表格、校内系统和合理使用的通用AI比较，不假设竞品没有记忆或行动能力。
- **现实边界**：历史通知只作历史样本，合成个人资料明确标注；文件齐全不等于资格通过，草稿不等于获批准或已提交。

具体用户实验见市场调研篇，均仍是计划，不是已有测试、留存或付费结果。初稿可以继续推进，不把完整商业验证当作本届参赛门槛。

## 七、团队和企业只保留为可选假设

团队版可从“一件事的协作材料夹”探索，由一位负责人发起，成员按授权补材料，不要求人人先建个人记忆。是否值得做，取决于共享盘、表单和现有校园流程还没解决的实际问题；个人档案默认私有，职责由人指定或确认。

企业版目前只是扩展设想，需要另找一个岗位和流程核实用户、付款方、数据权限及维护成本。不预设个人免费自然走向团队付费和企业采购，也不安排本届企业Demo。

当前最值得落实的是：选一位可触达学生的真实事务作为观察候选，确认他已有哪部分材料、现在如何准备；再据样本决定是否采用竞赛/项目报名主线。暂用“可行动事务 Agent”作为工作名。
