## 1. 打开方式

在macOS双击本目录的 [启动演示.command](启动演示.command)，保持打开的服务窗口，再在浏览器中使用 [Demo 总入口](http://127.0.0.1:8765/)。只监听本机，不发布到公网。

也可在终端运行：

```sh
python3 docs/05-交互Demo/serve.py
```

建议用启动文件打开的系统浏览器进行真实上传和下载；若内嵌预览未弹出文件选择或下载，请在系统浏览器打开同一地址。通知页点“使用样例”，资料页展开“使用合成资料演示”，可直接排练状态变化。样例载入和真实文件上传须区分讲述。

需要Python 3；网页不需要安装第三方依赖。不应直接双击HTML文件，因为浏览器可能限制本地模块加载。端口被占用时，使用 `--port 8766`，并按启动窗口显示的地址打开；不同端口属于不同浏览器存储空间。

## 3. 素材与操作顺序

页面的主流程是 **加入通知 → 选择资料 → 准备清单**。依据、资料详情与保存各自打开面板；故障、成本记录、素材下载和重置放在侧栏“演示工具”（窄屏为顶部“记忆与工具”）。

示例文件存放于 `samples/`，也可从“演示工具”下载。请使用TXT；本原型不读取扫描件或任意PDF。

| 文件 | 用途 |
|---|---|
| [N01 第一期通知](samples/N01-第一期通知.txt) | 合成历史背景，说明第一期素材的适用范围 |
| [N02 第二期通知](samples/N02-第二期通知.txt) | 两份Demo共用的本次上传通知 |
| [P01 在读身份证明](samples/P01-在读身份证明.txt) | 有效身份候选 |
| [P02 项目经历说明](samples/P02-项目经历说明.txt) | 经历候选，可演示角色更正与版本变化 |
| [P03 第一期签字成员名单](samples/P03-第一期签字成员名单.txt) | 已存在但本期需要更新 |
| [P04 第一期已使用成果证明](samples/P04-第一期已使用成果证明.txt) | 与第二期禁重复规则配对后不可用 |
| [P05 第二期新签字成员名单](samples/P05-第二期新签字成员名单.txt) | 上传后使本期名单拥有新候选 |

**Demo一：**侧栏“载入 4 份演示记忆”会明确写入合成来源，随后点“新事务”重读。上传N02并确认关键规则 → 选择4份已有资料 → 生成清单 → 返回“调整资料”补传P05 → 重新生成、审核并导出。更正入口是P02“查看详情 → 更正为项目成员”，更正后须重查。

**Demo二：**“演示工具 → 清空本演示数据”恢复0份记忆。上传N02并确认规则 → 进入“选择资料”，留空并点“先生成要求清单” → 直接导出 → 自愿补传P01/P02/P03，重新生成、审核并导出 → “为下次保留 → 不保存，结束本次 → 开始新事务”。

**共用操作：**通知中选择适用身份，读过期限、渠道和禁用条件后点“一次确认以上三项”。候选结果点“查看依据”，再依次勾选“我已核对本次依据”“选用于准备清单”；最后关闭面板，点“导出准备清单”。审核、选用与跨事务保存分别操作。

一次最多选择5份个人资料。故意缺少的附件A只影响对应补充要求，不能被静默补全。未读或失败文件会使相关范围保持未完成；“本次未找到”仅适用于规则明确、所选非空且检查完成的范围。

## 4. 现场展示的组合

两份脚本可独立排练。若合并到正式5分钟展示，可取Demo二105秒、Demo一150秒、真实性与范围说明45秒；不把所有可选故障演练塞进主线。计时是讲解安排，不是速度承诺。

六项问题均需有证据：无记忆路径、找文件/核对成本、旧材料不适用、纠正失效、重试上限与成本记录、单人范围。详细对应表已分别放入两份脚本。

## 5. 保存、数据与重置

新上传资料默认仅用于本次。在结果页点“为下次保留”，对要留的资料依次勾选“已核对这份资料”“保留到本机记忆”，再点“保留所选资料”。成功后点“开始新事务”真实重读；也可选“不保存，结束本次”。A的“载入演示记忆”是单独、明确的合成资料预置动作。

来源文本保存在当前浏览器的当前站点空间，不是PDF原件归档或本机后端数据库。更换浏览器、端口或清理站点数据会改变可读取的记忆。“演示工具”可重新读取或清空当前Demo数据。

只用合成素材。原型不向外部模型发送资料，没有真实模型计费；页面里的技术失败与重试属于明确标注的演练。正式产品仍需另行实现与验证模型处理、授权、服务端持久化和删除机制。

下载到外部的Markdown文件无法由页面远程收回。更正后旧下载文件仍是旧版本，应重新导出。删除或停用应用内来源，不代表外部副本也被改写。
