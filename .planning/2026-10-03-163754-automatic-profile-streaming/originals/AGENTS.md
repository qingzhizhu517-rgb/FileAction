# 文启 FileAction · 开发与文档协作规范

## 1. 代码优先与仓库职责

本仓库继续承载西客松 XiHack 2026「文启 / FileAction（可行动事务 Agent）」产品代码。用户于2026年10月2日指定《路演(1).md》为核心重点，口径见 `docs/03-参赛与路演/可行动事务Agent-核心路演稿.md`，范围与验收落实在 `docs/01-产品方案/可行动事务Agent-参赛主线方案.md`。当前先验证以文件为入口的个人端 MVP：结合已确认背景，解释文件对当下用户的意义；用户选择继续后再形成可编辑产物。团队与企业留在未来探索，不恢复成本届必交付。Document → 可行动事务 → Workflow 是可选行动路径，不强制所有文件进入任务流程。

- 根目录 `src/`、`tests/` 保存产品源码和测试。2026年10月3日已新增本机单用户 MVP 与实测启动入口 `./run.sh`；`gpt-5.6-sol` 真实模型已通过合成材料流程验收；真实腾讯云 COS 尚待用户配置后验收，不能将合成替身结果作为真实集成证据。具体范围见 `docs/01-产品方案/可行动事务Agent-MVP运行与验收.md`。
- `docs/可行动事务Agent-00-总览.md` 为文档地图；`docs/` 保留 `01-产品方案/`、`02-调研与可行性/`、`03-参赛与路演/`、`05-交互Demo/`、`06-讲解视频/`、`90-历史归档/` 编号结构。产品文档、品牌素材、设计稿及本地视频放在对应目录；宣传页及配套说明按用户要求单独放在根目录 `frontend/`；现行路演仅维护核心路演稿一份。
- `docs/05-交互Demo/` 是赛前规则模拟和静态设计资产，不是赛中产品；不得复制到 `src/` 冒充本届成果。文启高保真 Demo 是静态流程可视化、非定稿 UI。
- `docs/06-讲解视频/` 保存概念动画源码；画面为合成示意、非产品实录。MP4 不纳入 Git，移除索引不删除本地文件。
- `frontend/` 保存静态概念宣传页、样式、脚本及说明；入口为 `frontend/index.html`，内容为合成交互示例，未接入模型。
- 根目录保留 `README.md`、`AGENTS.md`、`CLAUDE.md`、`.gitignore`；`.planning/` 和 `.obsidian/` 不迁移。既有来源快照、原始草稿和归档正文保持原样。

2026年10月3日用户明确修订交互：解析文件后先总结，有相关个人沉淀时结合；上传后直接进入 Agent 对话，不能先进入个人资料收集页。可以根据文件推测阅读视角，但必须标为待确认，不能变成已确认背景。按文件与对话动态给出少量可跳过的核心问题、可选产物入口，用户看完即可退出。不得恢复固定步骤条或把回答、云端保存设为理解前置条件。

2026年10月3日用户继续明确：以文件作为持久工作区，可多开会话、关闭后继续。首页突出新文件拖入和历史文件；用户档案跨文件、文件沉淀只针对当前文件。文件沉淀自动整理成可查看和修改的卡片，放弃每个文件反复确认保存；用户修改优先，下一轮重载。全局档案加入仍需用户明确选择。日期、报名链接、倒计时分块展示，来源可核对；不编造缺失链接或截止时刻。启用 COS 工作区保存后才允许持续上传对话和沉淀；未启用的临时状态必须明确。

## 3. 分支、工作树与提交

- 开始前先检查 `git status`，识别并保留用户已有暂存、未暂存与未跟踪内容；不 reset、clean、覆盖或顺手清理无关工作。
- 在普通任务分支工作；结构迁移分支 `chore/docs-and-mvp` 已于2026年10月2日合入 `main`，不是日后任务固定使用的分支。用户明确要求当前工作树时，不创建 worktree。
- 未明确授权，不 commit、push、merge，不发布部署。获授权后提交只包含确认范围，使用清晰动作式消息；PR 说明变更原因、验证结果和未完成项。
- `git mv`、`git rm --cached` 会改变索引，执行前确认范围；视频仅移除索引并忽略，不删除本地文件。不要用全量暂存混入用户已有改动。
- Git 写操作若被权限检查阻止，停止并报告，不循环重试，不用其他解释器或工具绕过，不直接修改 `.git` 内部文件。

## 4. TDD 与验收

- 产品功能和行为修复按 TDD：先编写体现预期行为的失败测试并确认失败原因，再实现最小改动使其通过，最后重构并回归。纯文档和机械路径迁移做对应的结构、链接与运行入口核验，不为此伪造产品测试。
- 测试覆盖正常、失败、取消与关键边界；测试数据使用标明的合成样例。Mock 可用于隔离单元测试，但须明确标记，不代替真实 LLM 集成验收。
- 赛中代码变更必须跑相关测试；涉及网页流程时还须在浏览器实际走通，包括上传、失败提示、引用、用户确认和导出等受影响环节。
- 记录实际命令、真实结果与未验证范围。测试未跑、浏览器打不开、模型调用失败都应明确说明，不报告为通过。
- README 中的根目录产品开发/测试命令必须在实现后实测再写入。新增产品命令见运行与验收记录；下列仍是赛前资产命令，不能作为产品验收证据。

```sh
python3 docs/05-交互Demo/serve.py --help
python3 docs/05-交互Demo/serve.py --no-browser
node --test docs/05-交互Demo/tests/engine.test.mjs

git diff --check
```

## 5. 真实 LLM、合成数据与隐私

- 个人解读区分文件原文、已确认背景、系统推断和未知。缺少信息影响判断时再询问，用户可跳过；不预设先填档案或固定首问。
- 文件沉淀根据原文与交流自动形成白盒卡片，用户可修改或移除，不反复索取逐条确认。回答问题不默认加入跨文件用户档案；全局保存仍需明确选择。原文件、对话与文件沉淀的 COS 持久化按工作区授权范围处理。用户只理解、不保存或不继续行动，也应能完成本次目的。

- 正式产品能力与展示必须来自真实 LLM 调用和真实执行；不把规则模拟、预置回答、缓存回放或固定样例伪装为实时模型输出。模型未接入或失败时如实显示状态，不静默切换假结果。
- 单元测试替身、合成通知/材料/人物与演示数据必须明示。禁止编造用户、访谈、经历、客户、付费、测试结果或业务指标；没有证据就标为假设或未验证。
- 模型初稿与用户确认分开；准备清单不等于已报名，材料齐全不等于资格通过。不说“零幻觉”“竞品都做不到”。
- 密钥只从环境或受控配置读取；`.env`、上传资料、数据库、日志中的个人信息不入库，不在截图或测试报告中泄露。示例脱敏；提交前检查密钥和数据。
- 本机保存不等于云端模型看不到数据；外发前明确告知范围和目的，按需取得用户授权。未经授权不发送真实敏感材料，不共享团队成员资料。
- 外部提交、共享、删除等有副作用操作须经用户确认；模型建议不能冒充已完成动作。团队版、企业版与商业路径分别用真实信号验证。
