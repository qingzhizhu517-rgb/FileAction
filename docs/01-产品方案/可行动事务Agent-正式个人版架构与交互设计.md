# 可行动事务 Agent · 正式个人版架构与交互设计

导航：[[docs/可行动事务Agent-00-总览|文档总览]] · [[docs/01-产品方案/可行动事务Agent-个人MVP开发验证|已验证MVP]] · [[docs/01-产品方案/可行动事务Agent-参赛主线方案|产品主线]]

技术细则：[[docs/01-产品方案/可行动事务Agent-正式个人版技术开发设计|完整技术开发设计]]。2026年10月2日正式版主库改为PostgreSQL，用户随后确认将腾讯云COS和RAG写入开发设计；原件云存储、pgvector混合检索、独立Embedding授权、Agent、任务与验收以该技术设计为准。本篇负责产品与交互概览。

## 1. 已确认要求与本设计目标

2026年10月2日，用户认可当前MVP，要求根据高保真原型开发正式完整项目，采用前后端分离，并明确选择：**个人多账号版，支持登录、各用户数据独立、具备后续部署基础，本次不发布公网。**

本设计以现有真实模型工程为基础，完成从单次会话到个人工作区的升级。参考资产为 [文启高保真原型](../05-交互Demo/可行动事务Agent-文启高保真Demo.html)。已经实际阅读文件空间、事务对话、我的行动、成果包和本次对话沉淀抽屉，并核对页面交互。

原型负责视觉与交互参考；核心路演稿及现行产品方案负责产品语义。原型中的人物、奖学金、排名、材料、时间和结果均是合成示例，不写入正式账号的默认数据，不当作模型结果。页面里提前出现的询问信改为用户主动选择、独立授权后真实生成。

正式版的完成标准：用户能注册或登录，上传并管理自己的文件，选择相关材料和背景进行真实多轮解读，自主保留沉淀，选择后建立行动和可编辑成果，刷新或重新登录后恢复已明确保存的内容；所有涉及数据的入口经过真实API和所有权校验。

## 2. 方案比较与推荐

| 方案 | 实施方式 | 优点与代价 | 结论 |
|---|---|---|---|
| 延续应用技术栈，采用正式业务数据层与受控Agent | React/TypeScript/Vite；FastAPI；LangGraph状态图；PostgreSQL/pgvector；腾讯云COS；RAG与独立Embedding；Redis；Worker | 复用已验证解析、引用校验和模型适配；需验证新基础设施、鉴权与数据归属 | 推荐，完整合同见技术设计 |
| 拆成微服务并增加独立向量库、分布式队列与集群编排 | 分别部署更多业务服务和基础设施 | 当前规模下增加运维与跨服务一致性工作，尚无已确认需求 | 本期不采用 |
| 改用另一套全栈框架 | 重写现有后端和文件处理链路 | 统一部分工具，但增加已验证能力的迁移风险，无已确认需求收益 | 不采用 |

推荐方案采用可独立构建和运行的前端与API服务，不依赖FastAPI托管前端页面；PostgreSQL保存业务事实与长期分块，pgvector提供向量检索，腾讯云COS保存明确保留的原件，Redis保存有期限的临时内容及临时向量。RAG采用授权范围内的关键词与向量混合召回，为单协调Agent提供带原文定位的证据；短材料仍可全文解读。先交付本机运行和验收的多账号个人版，不发布公网；COS和外部Embedding仍属于云端处理，须说明并授权。

## 3. 视觉与页面范围

### 3.1 统一视觉

沿用原型的暖白底色、金黄色主操作、细线边框、文启品牌、顶部导航、卡片与留白。桌面文件区采用多列卡片，工作区采用材料侧栏与主对话，成果页采用编辑区与来源检查侧栏。移动端改为单列与抽屉，确保上传、引用、确认和导出可使用。

产品组件重新编写；不将旧原型HTML、脚本和预置结果整体复制到产品目录。若复用既有Logo资产，记录其来源与既有资产身份。加载、空数据、失败、取消、过期和无权访问均有完整状态；不保留只弹出“功能演示”的产品按钮。

### 3.2 页面与功能映射

| 页面与路由 | 正式功能 | 与原型的对应及边界 |
|---|---|---|
| `/login`、`/register` | 用户名、密码注册登录；错误提示；登录过期返回原目标 | 新增账号入口，不要求先填写个人背景 |
| `/files` 文件空间 | 真实文件上传、搜索、手动分类、网格/列表切换、原文预览、重命名、删除确认、关联工作区 | 卡片数量、文件大小、时间和关联均来自当前用户数据；新账号为空态 |
| `/workspaces/:id` 事务对话 | 工作区切换、选择多份文件、补充背景、自由输入、多轮真实解读、引用展开、修改目标、取消请求 | 保留材料树、对话主区和本次沉淀入口；只理解也能结束，不自动建立行动 |
| `/actions` 我的行动 | 按工作区筛选、创建与编辑行动、调整状态和优先级、可选截止时间、关联来源和成果、暂停与删除 | 展示待决定、准备中、草稿就绪；另可筛选已完成和已暂停。完成只能由用户确认，不等于外部提交成功 |
| `/deliverables` 成果包 | 按工作区切换，多份产物与版本，正文编辑、保存、重新生成、来源和未知检查、单项下载和整包导出 | 对应草稿、材料清单、依据摘要及检查侧栏；内容由真实调用或用户编辑产生 |
| `/settings` 个人设置 | 修改显示名和密码；查看模型连接信息；保留背景的查看、编辑、停用与删除；退出登录 | 不提供前端模型密钥编辑；用户仅看到必要的服务域名和模型名 |

### 3.3 本次沉淀与引用

沉淀抽屉区分本次目标、用户确认的背景、文件提取候选、未知项和行动建议。目标不是长期人物标签，未知或建议不能被当作已确认事实。用户可编辑候选、确认仅用于本次、另行选择保留供以后使用。

引用入口支持鼠标点击、键盘和触屏；不依赖右键才能访问。展示对应文件、版本、位置和准确引文。模型输出按文本或受约束Markdown渲染，不执行原始HTML。引用无法定位时拒绝发布该结果。

## 4. 前后端独立运行与代码边界

```text
浏览器
  └─ 独立前端静态服务（开发时Vite）
       └─ /api/v1 反向代理或明确配置的API地址
            └─ FastAPI
                 ├─ 账号与访问控制
                 ├─ 文件、工作区、行动、成果、背景领域服务
                 ├─ 解析与来源校验
                 ├─ 真实模型适配
                 ├─ RAG检索与独立Embedding网关
                 └─ PostgreSQL/pgvector、Redis与腾讯云COS
```

按用户已确认要求使用 `front/` 与 `backend/`，前后端源码和测试分别归属各自目录：

```text
front/src/
  app/                 路由、登录态、应用布局
  features/auth/       登录、注册与账号设置
  features/files/      文件空间与预览
  features/workspace/  对话、材料选择、引用和沉淀
  features/actions/    行动视图
  features/deliverables/ 成果编辑与导出
  shared/              API客户端、基础组件、样式与类型
backend/fileaction/
  api/                 分域路由与依赖注入
  core/                配置、鉴权、限额与错误处理
  domain/              授权、保存、版本与失效规则
  services/            文件、工作区、模型调用、行动与成果服务
  repositories/        带用户范围的数据访问
  db/                  模型与迁移入口
  parsers.py           沿用并扩展已有解析能力
  model.py             沿用已验证真实模型适配
backend/tests/         后端行为、所有权、集成验收
front/e2e/             浏览器验收
```

前端单独构建静态产物、独立启动，API独立启动和健康检查。开发时可采用前端5173、后端8000，端口可配置且不得接管用户已有进程。后端不再依赖 `dist/` 才能工作；前端通过API配置适配实际后端地址。根目录保留协调脚本与运行说明。

浏览器与API优先通过前端服务的 `/api` 代理保持同源；需要独立Origin调试时仅允许显式配置的前端Origin，并正确处理预检及凭证。模型密钥只留在后端环境，不使用任何前端可见环境变量传递。

## 5. 账号、会话与所有权

- 账号采用用户名和密码，显示名可修改；本期不接入邮件验证、第三方登录或短信服务。用户名规范化并保证唯一，密码采用Argon2id散列，不记录明文。
- 登录采用随机不透明会话令牌，服务端保存令牌摘要；浏览器使用HttpOnly会话Cookie。部署环境启用Secure；本机HTTP开发模式显式区分。
- 写请求验证Origin与CSRF令牌；Cookie凭证不放入localStorage。跨域允许列表不得使用带凭证的任意Origin。
- 登录会话绝对有效期7天、闲置24小时失效；退出撤销当前会话，改密码撤销旧会话。登录错误使用统一提示，并对IP和账号尝试实施限流。
- 文件、工作区、消息、背景、行动、产物、生成操作均有 `owner_id`。读取、更新、关联、预览、下载和导出全部校验所有权，不能只依赖前端隐藏。
- 跨用户资源ID返回统一不可访问结果；用户不能把别人的文件或背景ID拼进自己的模型上下文。列表、搜索、统计与关联也必须限定用户。
- 用户退出或失去权限后不能继续取得旧请求结果；后台请求按操作所有者和依赖修订验证后才能保存。

正式版使用独立PostgreSQL数据库，通过受控DSN配置；不回退到SQLite。现有MVP无归属背景库保持原样，不默认归给第一个注册用户，也不对所有账号可见。本期提供全新账号的完整路径，旧个人资料不自动导入。

## 6. 保存、删除与版本规则

### 6.1 三种独立选择

| 用户选择 | 保存范围 | 未选择时 |
|---|---|---|
| 保存到文件空间 | COS私有原件、PostgreSQL解析片段和元数据；索引另行授权 | 仅用于本次临时解读，到期或结束清除 |
| 保留本次工作区 | 本次文件选择、对话、解读、目标、行动和成果 | 当前会话内可编辑导出，不自动进入长期历史 |
| 保留背景供以后使用 | 用户选中的已确认背景及来源、版本 | 只参与本次判断，不写入个人背景库 |

上传前展示“仅本次使用”和“保存到文件空间”，默认仅本次使用；明确保存才落入个人资料库。保留工作区时列出将保存的范围，涉及临时文件时一并确认保存这些来源；不能悄悄保存关联材料。用户选择保存后，编辑该工作区属于已授权保存范围，但新增文件和长期背景仍分别确认。

临时内容60分钟闲置到期，退出或明确结束时清除。保存内容刷新和重新登录后可恢复；“结束本次”不删除此前明确保留的资料，删除保存内容使用单独确认入口。

临时原件不上COS，临时文本和向量不进入长期pgvector。长期原件云存储、文本索引外发、查询向量化与生成外发按用途分别授权；可以在同一界面告知，但同意保存不能推定同意Embedding。保存工作区时明确列出具体消息/成果快照、COS原件和可选向量范围，新增内容不被旧确认自动纳入。

### 6.2 数据结构与状态

核心对象包括 `User`、`AuthSession`、`Document`、`DocumentSegment`、`Workspace`、`WorkspaceDocument`、`ConversationMessage`、`ContextFact`、`Memory`、`Reading`、`Action`、`Artifact`、`ArtifactVersion`、`GenerationOperation`。消息和结果关联本次使用的文件、背景及目标版本。

每次修改文件选择、背景或目标都会提升工作区修订号。生成开始时记录依赖快照，写回时再次比较；取消、删除、切换或修改后的迟到结果不回填。两个页面同时修改同一对象时使用乐观版本检查，冲突返回409并保留用户输入供处理。

保存的旧产物作为历史版本保留并明确标注过期。历史版本可查看，但不能从“当前成果包”无提示导出；重新生成或用户完成重新核对后才能成为当前版本。

删除文件前列出受影响工作区、产物与索引；确认后先撤销读取/检索并取消相关任务，再清理COS受管对象版本、原文片段、向量及缓存，任一清理未完成不报删除完成。用户无关资料不受影响；外部已下载副本和模型服务侧内容不承诺撤回。

## 7. 文件、多轮对话与模型边界

### 7.1 文件与引用

本期保证TXT、Markdown、文本PDF、DOCX正文和表格的完整产品路径；沿用单文件10 MiB、40,000字符和PDF50页限制。工作区可以选择多份文件，单次发送的总提取文本仍不超过40,000字符，超限请用户缩小材料范围，不静默丢弃。

原型中的JPG证书属于静态示例，本期不把它解释成已具备OCR。本期图片、扫描PDF仍明确提示无法解析；OCR和多模态服务不纳入默认承诺。正式页面的可选格式必须与实际后端支持一致。

多文件引用包含文件ID、版本、片段ID、位置及准确引文；后端验证引用属于本次已授权的文件集合。TXT/MD定位行，PDF定位页，DOCX定位段落或表格单元格。PDF在授权范围内可查看原件；DOCX以提取内容定位并可下载原件，不伪造Word分页。

文件解析与语义索引是独立状态：解析完成即可看原文；用户授权文本向量化且索引成功后才可用hybrid检索。分块保留原文页/段落/单元格映射，检索先限定本人、当前版本和授权片段，再融合关键词与向量候选；不全库召回后只靠前端过滤。缺少Embedding或用户拒绝时可明确选全文/关键词模式，不把它伪装为向量RAG。

### 7.2 真实对话与可选行动

开始解读时预览将发送的文件、当前背景和目标；后续自由输入在明确的“发送给模型”操作下发送当前消息与所显示的上下文。文件集合或背景改变后撤销旧同意，重新预览确认。保留历史不等于允许将全部历史外发。

模型完成多轮回答、结构化解读、按需提问、候选沉淀和行动建议；协调Agent用显式状态图组织受限规划、授权范围内证据工具、生成和校验。服务端代码控制确认、保存、任务创建与状态变更。后续对话可以提出目标修改，用户确认后旧方向的行动和草稿标为需重新核对，不假装重新生成了一套结果。每次运行最多2次生成模型调用、6次只读工具调用；查询Embedding单独限制为至多1次批量调用，文档索引走独立任务与预算，具体合同见技术设计第5、6、10节。

用户主动点击生成后，支持询问信/文字草稿、行动清单、依据与未知摘要及自定义目标。生成操作独立确认，不因“看懂文件”自动付费起草。模型建议先呈现给用户；确认加入行动后才创建正式行动记录。

沿用 `.env` 真实模型配置与JSON模式，本地严格校验结构、引文、背景来源和版本。60秒模型超时、可取消、无自动费用重试、无假答案替代；等待状态反映真实请求，不显示虚构的分析步骤或完成百分比。

Embedding的端点、密钥、模型、维度与批量能力单独配置和真实验证，不自动继承聊天模型配置。COS上传/下载本期由后端代理；浏览器直传和预签名下载默认关闭。

### 7.3 成果编辑与导出

产物允许全文编辑、保存新版本、查看来源和未知。用户改写的文字标注为用户编辑，不能借原模型引文声称整段改写均已得到证据支持。

单项导出Markdown；整包导出ZIP，包含用户选定的当前产物、来源定位和待核实清单，不默认包含原始上传文件。下载内容必须是当前已保存的编辑版本。没有邮件发送、代报名、自动提交或预约功能；按钮和状态不冒充这些操作已经发生。

## 8. API合同与前端调用

统一使用 `/api/v1`。数据接口返回明确资源及修订号，错误包含稳定错误码、中文说明和请求ID；不回显密钥、原文、密码或上游原始响应。认证失败401、无效输入400/422、资源不可访问404、版本冲突409、限额429、上游失败502/503。

| 领域 | 主要API | 核心约束 |
|---|---|---|
| 账号 | `POST /auth/register`、`POST /auth/login`、`POST /auth/logout`、`GET /auth/me`、`PATCH /auth/profile`、`POST /auth/password` | Cookie会话、CSRF、密码散列、限流 |
| 配置与运行 | `GET /config`、`GET /health/live`、`GET /health/ready` | 不输出密钥；健康不自动调用模型 |
| 文件 | `GET/POST /documents`、`GET/PATCH/DELETE /documents/{id}`、`GET /documents/{id}/segments`、`GET /documents/{id}/source` | 所有权、保存模式、解析状态、下载鉴权 |
| 工作区 | `GET/POST /workspaces`、`GET/PATCH/DELETE /workspaces/{id}`、`PUT /workspaces/{id}/documents`、`POST /workspaces/{id}/retain`、`POST /workspaces/{id}/end` | 临时/保留边界、文件属于本人、版本控制 |
| 对话与解读 | `POST /workspaces/{id}/context-preview`、`POST /workspaces/{id}/runs`、`GET /runs/{id}/events`、`POST /runs/{id}/cancel` | 预览授权、202后台任务、依赖快照与SSE；消息从工作区消息查询接口读取 |
| 本次背景 | `POST /workspaces/{id}/facts`、`PATCH/DELETE /workspaces/{id}/facts/{fact_id}` | 确认与保存分开 |
| 保留背景 | `GET/POST /memories`、`PATCH/DELETE /memories/{id}`、`POST /workspaces/{id}/memories/{memory_id}/use` | 不自动复用、来源及版本有效 |
| 行动 | `GET/POST /actions`、`PATCH/DELETE /actions/{id}` | 工作区和来源属于本人；状态由用户确认 |
| 成果 | `GET /workspaces/{id}/artifacts`、`GET/PATCH/DELETE /artifacts/{id}`、`GET /artifacts/{id}/versions` | 模型生成统一走runs；生成与编辑分开、草稿/当前/过期明确 |
| 导出 | `POST /artifacts/{id}/export`、`POST /workspaces/{id}/export` | 导出选择与修订一致；不含他人或失效内容 |

前端API客户端统一处理凭证、CSRF、错误和取消，不在各页面散落认证代码。路由恢复、加载和错误边界由应用层管理；业务状态以服务端资源为准，浏览器不持久化密码、原文件或模型密钥。

上表为概览；保留预览、解析版本、删除影响、账户注销、错误DTO和请求字段以完整技术设计第11节为准。

## 9. 实施顺序与验收门槛

完整实现分为以下可独立检查的交付阶段，不把阶段1当成整个正式项目完成：

1. **独立应用与账号基础**：拆分静态服务/API，建立配置、迁移、认证、所有权依赖、登录页和测试数据隔离。
2. **文件空间与工作区**：完成原型应用框架、上传预览、保存选择、列表搜索、工作区切换、多文件关联、删除和恢复。
3. **真实对话与沉淀**：接入多轮模型、引用抽屉、背景复用、候选确认、保存、取消及来源/版本失效。
4. **行动与成果包**：完成用户确认的行动状态、目标修改、多个产物、版本编辑、单项和整包导出。
5. **完整验收与交付**：两账号隔离验证、服务重启恢复、桌面/移动视觉核验、失败和取消路径、真实模型合成场景、运行文档及部署边界。

每个行为先写失败测试、确认失败原因，再实现与回归。已有50项后端和16项浏览器结果是MVP证据，不能继承成正式版通过；变更后的相关测试必须重新运行。

| 验收场景 | 必须得到的结果 |
|---|---|
| 新账号首次进入 | 无预填个人材料或模型答案，可以不填背景开始 |
| A/B两个账号 | 列表、搜索、预览、下载、消息、背景、行动和导出均隔离；猜测ID无效 |
| 保存与恢复 | 明确保存的内容在刷新、重登和API重启后恢复；临时内容不会成为历史 |
| 不保存、不行动 | 可完成理解和临时导出，结束后清除临时内容 |
| 多文件/不同背景 | 使用实际选择的来源，真实模型解读变化可追溯，不使用预置分支 |
| 更正或删除来源 | 相关结果标为过期，迟到响应无法恢复旧状态 |
| 多轮与目标变化 | 对话实际使用本轮确认范围，目标变化影响新行动和产物，不篡改旧历史 |
| 导出 | 下载当前编辑版本，ZIP成员与用户选择一致，包含来源和未知提示 |
| 失败与取消 | 无配置、超时、无效JSON、虚假引用、超限、断连、取消和并发冲突均有真实可恢复状态 |
| 页面可用性 | 原型主要布局可对照，键盘可操作，390像素宽度无横向溢出，原型入口均有真实行为或明确范围说明 |
| 前后端分离 | API独立运行不依赖前端构建，前端独立构建与访问，服务地址由配置决定 |

验收只使用明确标注的合成文件与合成账号，不读取用户原始资料进行自动外发。真实模型测试单独运行并记录实际结果，不混入默认单元或浏览器回归。
