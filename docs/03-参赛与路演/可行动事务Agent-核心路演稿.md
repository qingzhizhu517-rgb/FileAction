## 0:00—0:45｜痛点：读文件，累的不只是阅读

[屏幕：群消息里收到的通知、申报指南、业务材料]

大家有没有这样的经历？

群里突然发来一份文件，几十页的通知，或者一份业务材料。

你还不知道它跟自己有没有关系，但为了知道这一点，你得先点开，从头往下读。

读到一段，判断一下：这个跟我无关。

再读一段：这个好像有关系，先记下来。

最后看完，可能真正需要关注的只有几处。

**我们想减少的，就是这段反复阅读、筛选，再把内容和自己联系起来的过程。**

能不能收到文件的时候，不必先自己通读一遍，而是先交给一个了解你的助手？

## 0:45—1:20｜产品：收到文件，先交给文启

[屏幕：文启产品首页，突出文件入口]

这就是文启。

我们希望，用户收到文件后的第一反应，是：

**“先放进文启，看看这份文件对我意味着什么。”**

如果只让 AI 总结文件，得到的往往是一份内容摘要。

但没有结合个人背景的摘要，还没有回答这份文件对当下的你意味着什么。

而文启要做的是结合对你的了解，告诉你：哪些内容与你有关，为什么值得关注，有哪些要求或者限制需要注意。

文件是入口，个人背景是理解的基础，与你有关的解读才是交付的起点。

## 1:20—2:50｜系统：把文件讲成与你有关的内容

[屏幕：上传文件 → 个性化解读 → 原文依据]

那么，一份文件交给文启之后，会发生什么？

首先，系统通过文件解析和模型理解，识别其中的关键内容、要求和限制。

但读取只是开始。接下来，系统会结合与你有关、已经确认的背景，判断哪些内容值得你关注。

**它不是把所有内容压缩一遍，而是解释：为什么这几条，与你有关。**

[屏幕：展开一条关联判断，展示原文依据与相关背景]

比如，一项要求为什么需要你注意，一个机会为什么可能适合你，都应该有依据。

哪些是文件明确写的，哪些结合了你提供的信息，哪些还不能确定，需要分清楚。你也可以回到原文核对，而不是只能接受系统给出的结论。

如果缺少的信息会影响判断，文启再适当询问。你可以补充，也可以暂时不提供，不需要先填完一张个人资料表才能开始。

[屏幕：简短展示本次沉淀及修改操作]

处理过程中，沉淀不是套一套预设模板，而是根据这份文件和实际交流逐步形成。相关内容会展示出来，你可以查看、修改，并决定是否保留。

这些积累，是为了支持之后的理解。

最终，文启要回答的，不只是“这份文件说了什么”，而是：

**“这里有哪些事与我有关，它们对我意味着什么。”**

## 2:50—3:40｜场景：不同的人，得到不同的阅读重点

[屏幕：学生、教师、企业成员三张场景卡片]

这套方式，不只适用于某一种身份。

对学生来说，一份奖学金通知，可能与他刚完成的项目成果有关。文启需要指出哪些经历可能用得上，还有哪些条件需要确认。

对教师来说，一份申报指南，结合正在推进的研究方向，可能意味着一个值得进一步了解的项目机会。

对企业中的业务负责人来说，一份合作方案，需要结合当前项目，找出值得关注的内容和需要向对方确认的问题。


## 3:40—4:20｜行动：理解之后，继续帮你往下做

[屏幕：关联判断 → 用户选择 → 可编辑产物]

理解了这份文件与你的关系之后，你可以决定是否继续。

如果只是想了解，或者觉得暂时无关，到这里就可以结束。

如果你想采取行动，文启再沿着已经确认的方向，帮助你准备具体产物。

比如，申请陈述草稿、需要核实的问题、材料清单，或者一份合作讨论提纲。

这些产物应当用上刚才已经理解和确认的信息，而不是让你重新解释一遍。

重要决定和对外发送，仍然由你确认。

**从“这件事与我有关”，走到“我已经有了可以继续推进的东西”。**

## 4:20—5:00｜阶段与愿景：收到文件，先交给文启

[屏幕：个人端 MVP → 未来探索团队与企业级应用；展示预设体验入口]

目前，我们先以个人端 MVP 验证这条路径，未来再探索团队协作和企业级应用。

我们计划以奖学金等合成预设体验，帮助大家具体感受这条流程；现场按实际完成的入口展示。

但文启不以某一种身份或某一类通知为边界。

我们希望建立的是一种更轻松的文件处理方式：

**收到文件，先交给文启。**

不必每次从头阅读、筛选，也不必每次从头介绍自己。

让系统结合对你的了解，讲清楚文件对你的意义，再帮助你把这个意义变成行动。

谢谢大家。




文启是一个以文件为入口的个人行动助手，帮你理解一份文件对当下的你意味着什么，再把这份意义变成具体行动。
