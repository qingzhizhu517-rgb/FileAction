# 可行动事务 Agent · 路演答辩应答卡

导航：[[docs/可行动事务Agent-00-总览|文档总览]] · [[docs/03-参赛与路演/可行动事务Agent-核心路演稿|核心路演稿]] · [[docs/01-产品方案/可行动事务Agent-参赛主线方案|参赛主线方案]]

> 以用户于2026年10月2日指定的《路演(1).md》为主线。5分钟讲解使用核心路演稿的六段时间线，本篇回答追问，不另排团队版演示。设计目标、当前代码、实际实测和用户证据分别表述；本分支尚无可运行 MVP 或真人验证记录，不能照稿宣称全部完成。

## 一、统一开场

1. 收到一份文件，累的不只是读完，而是反复筛选，再判断它与自己有什么关系。
2. 文启是一个以文件为入口的个人行动助手，结合已经确认的相关背景，讲清哪些内容与你有关、为什么、有哪些要求或限制。
3. 你可以到此结束；想继续时，再沿已确认方向生成可编辑的具体产物。收到文件，先交给文启。

首晚视频草稿属于过去阶段的材料，不再沿用“67小时内把个人版和团队版都跑通”的承诺，也不补录或倒填首晚完成情况。

## 二、问答

### Q1 · 你们首先解决什么问题？

“用户为了知道一份文件对自己意味着什么，常常要先通读、筛选，再联系自己的背景。我们首先想让这一步更轻松：直接给出与你有关、有理由和依据的解读。材料清单和起草是用户选择继续后的一部分，不是每份文件必走的流程。”

### Q2 · 和通用 AI 读文件有什么不同？

“我们不主张通用 AI 只能摘要或没有记忆。我们重点验证的是一条连续体验：文件进来，结合你已经确认的背景解释关联，能回到原文核对，信息不足时按需询问，再由你决定是否行动和保留本次沉淀。是否比其他工具更好，需要在相同文件、背景和目标下实测，当前还没有这项比较结论。”

不以“同一份摘要谁看都一样”证明竞品做不到个性化，也不把历史功能检索当成同题评测。来源与局限见[[docs/02-调研与可行性/可行动事务Agent-竞品分析|竞品分析]]。

### Q3 · 怎么知道“与我有关”不是模型乱猜？

“设计上要把四件事分开：文件原文写的内容、你确认过的背景、系统的关联推断、还不知道的部分。关键判断能回到文件和背景依据，推断要说明理由；条件不足就提示待确认，而不是替你断言资格通过或机会一定适合。”

现场展示仅限实际实现的回溯功能，不能拿设计稿当验证。

### Q4 · 第一次使用没有背景怎么办？

“可以直接放入文件，不用先建档。先给出当前证据支持的内容；缺少的信息会影响判断时，再解释为什么需要并适当询问。你可以跳过，不能判断的地方保持未知。不会规定每次都要先答一个问题，才让你继续。”

### Q5 · 沉淀是不是先填模板，或者每句话都自动保存？

“都不是。沉淀根据文件和实际交流逐步形成，展示出来让你查看、修改、决定是否保留。确认一条信息属实，不等于同意长期保存；不保存也能完成本次解读。保留内容是为了支持之后的理解，不是为了积累一张越来越大的个人资料表。”

### Q6 · 每份文件都要生成待办吗？

“不需要。只想了解、认为暂时无关，或者尚未决定怎么做，都可以到这里结束。讲清文件对你的意义就是有效交付，不能把你没有选择行动算成失败。”

### Q7 · 选择行动后，具体能得到什么？

“目标是沿已经确认的方向，得到可以继续修改和使用的东西，例如申请陈述草稿、需要核实的问题、材料清单或合作讨论提纲。它应该用上此前已确认的信息，而不是让你再解释一遍。重要决定和对外发送仍然由你确认。”

产物类型按实际实现展示；不用计划清单冒充已支持清单。

### Q8 · 是不是只给学生做奖学金申报？

“奖学金可以是预设体验，但不是产品边界。学生读奖学金通知、教师读申报指南、业务负责人读合作方案，都是个人结合自身背景理解文件的例子。企业成员以个人身份使用，不等于我们已经实现企业部署。”

### Q9 · 为什么需要 AI？断网会怎样？

“模型用于理解文件和个人背景之间的语义关系，并生成解读与草稿；来源、授权、保存和重要操作确认由确定性代码约束。规则能处理已定义的检查，但不能用固定演示脚本冒充对任意文件的理解。模型不可用时应如实提示失败，不能静默返回预设答案。”

离线查看、文件格式和失败恢复能力，仅在实现并实测后承诺。本次文档对齐不构成模型验收。

### Q10 · 背景过期、理解错了，或材料不能复用怎么办？

“用户应能纠正本次理解、修改或停用保留内容，受影响的旧结果要重新核对。材料复用只在场景需要时检查：过去用过不代表这次一定禁用，必须有本次适用条款和触发事实。准备清单不等于资格通过，系统也不能修改已经下载或发出的外部副本。”

### Q11 · 团队版和企业版现在做吗？

“当前先验证个人端 MVP。团队协作和企业级应用是未来探索；之前设想的能力名片、分工推荐、审批对接等不属于本轮承诺。是否做、怎么授权、有没有价值，都需要单独验证。”

### Q12 · 已经实现哪些功能，有真实用户或付费吗？

截至2026年10月2日本次仓库检查：本分支未见根目录产品源码、产品测试或可运行个人端 MVP；已有规则 Demo、静态流程可视化和概念动画，不能证明当前产品能力。尚无可引用的真人访谈、产品实测或实际付款记录。其他分支或外部部署如有进展，核验后再更新。

上台按届时实际成果回答：“已经实现并实测的是……；尚未完成的是……；设计资产是……”。没有证据就直说未验证，不预填“已申报”“用户已使用”“团队分工已跑通”等结果。历史规则测试通过不等于真实 LLM 产品通过验收。

### Q13 · 数据与隐私怎么处理？

“演示使用合成资料。产品设计要求说明发送哪些内容给哪个模型服务，信息只在必要范围内使用，保存由用户选择。云端模型处理仍可能看到发出的片段，本机保存不能保证它看不到；团队探索也不会默认公开个人沉淀。”

实际删除、留存和访问控制按真实实现说明，不能承诺未经核验的“完全不外传”。

### Q14 · 谁会付费，你们如何证明价值？

“付费方还在验证。先看用户是否更容易理解文件对自己的意义，记录阅读、补充、核对与纠错成本；选择继续的人，再看产物是否实际被编辑或使用。遇到第二份文件时是否回来、是否少重复解释，也是行为证据。个人付费或未来机构采购都是假设，现在不报没有实测依据的 ROI。”

不把愿意提供截图直接认定为核心用户，也不把口头愿付当付款。执行方法见[[docs/03-参赛与路演/可行动事务Agent-用户验证执行卡|用户验证执行卡]]。

## 三、上台前核对

- 六段时间线与核心路演稿一致；主展示没有混入团队版实现承诺。
- 关键解读区分原文、背景、推断和未知；画面能支持所讲的回溯能力。
- 只询问影响判断的信息；跳过、不保存、不行动的路径按真实版本核验。
- 沉淀可查看、修改并由用户决定是否保留；选择行动后产物可编辑。
- 奖学金等体验入口确实存在且能使用，样例与背景标明合成；未完成则讲计划。
- PPT 中区分真实运行、设计示意和概念动画；新增功能、开发时间及申报据实记录。
- 测试账号、模型外发说明、失败提示、调用限额与备用录屏按实际部署检查。
- 用户、耗时与付费数字都有实际记录；没有就删去，不填占位数字上台。
- 赛事规则以官方最新书面通知为准，本库既有来源读取日期不因编辑而更新。
