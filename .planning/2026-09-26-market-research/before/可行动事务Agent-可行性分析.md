# 可行动事务 Agent · 可行性分析

> **用途**：判断这份 idea 是否适合西客松 XiHack 2026，以及怎样在现场完成可核验的核心流程。
> **依据**：赛事事实见 [[可行动事务Agent-西客松参赛对齐]]；产品范围见 [[可行动事务Agent-定位决策]]；竞品、研究与事实纠错见 [[可行动事务Agent-核查修订报告]]。
> **配套**：[[可行动事务Agent-学分认定Demo规格]] · [[可行动事务Agent-Demo状态表]] · [[可行动事务Agent-UI原型规格表]] · [[可行动事务Agent-路演答辩应答卡]]

## 一、参赛判断：这个 idea 可以继续

**适合继续作为 AI 软件应用赛道的 idea 初稿推进。** 它有可解释的用户任务、具体的 AI 使用环节，以及能在有限范围内演示的输入—核验—缺口—行动闭环。当前重点是把问题讲清楚、把范围收住、在现场完成核心流程。

本仓库目前是方案文档，没有可运行实现或真实文件实测；这符合赛前 idea 阶段，不是初稿不成立的理由。用户访谈、创业商业模式和付费证据仍待验证，但本届公布材料没有把这些、完整竞品研究或固定测试数量列为报名门槛。商业是否成立，与这次能否做出清晰可运行的参赛作品，应分开判断。

技术结论是：人工核验后的小范围规则执行有条件可行。它不等于已实现、零错误或有获奖把握；正式评审仍须展示实际完成的作品。

## 二、为什么适合 AI 软件应用赛道

| 评估主轴 | 这个 idea 的具体内容 | 现场要让评委看到什么 |
|---|---|---|
| 问题与场景 | 学生需要对照制度、个人学时与分类要求，知道满足了什么、还缺什么 | 用“总量达到门槛，分类仍有缺口”的合成案例说明任务 |
| AI 的作用 | 从制度文本提出结构化候选条款，辅助定位原文和归一化字段 | 候选条款、来源和人工核验步骤，而不只有一张算好的表 |
| 产品亮点 | 将条款、个人事实、数值差距和下一步核对事项连接起来 | 点开来源、看到缺口、改变一个假设后重新计算 |
| 核心流程完成度 | 在明确范围内完成导入、核验、执行与结果展示 | 可运行入口及可复现流程；失败、缺证和未知有明确表现 |
| 实现范围 | 先做一校、一版制度、一个群体和三个条件 | 单一场景完成，不用企业 Demo 或多模态扩张稀释时间 |

官方 AI 软件应用赛道的核验重点是“场景是否明确，核心流程能否实际完成”。上表是团队据此组织的评估方式，不是官方创新、技术或商业评分表；目前公布材料没有这类详细分项权重。

本方案不需要证明人不会手算或竞品不能计算。参赛要呈现的是：AI 帮用户把杂乱文本变成可核对的输入，再把计算结果交回到具体事务。与人工表格、现有教务展示和合理提示的通用 LLM 做系统对照，可放在赛后深化。

## 三、团队选择的最小可演示范围

以下是为了控制工作量而作的**团队选择，不是赛事对格式、学校或条件数量的硬性限制**。

| 项目 | 本轮方案 |
|---|---|
| 适用范围 | 一所学校、一个制度版本、一个明确适用群体 |
| 制度输入 | 1–2份可提取文本的制度 PDF；可从公开制度选择并标注来源 |
| 个人记录 | 一种固定格式 CSV；可使用明确标注的合成个人记录，不冒充教务导出实测 |
| 核验条件 | 总量、创新创业、文艺体育三个条件；其他类别仅导入，分类条件不核验 |
| 核心流程 | 提取候选规则与事实 → 人工核验规则、来源及适用范围 → 白名单执行 → 展示缺口、来源与假设试算 |
| 后置功能 | OCR、Word、跨校泛化、企业 Demo、外部提交 |

规则审核需确认阈值、单位、统计范围、类别和适用版本。执行器不直接运行模型生成的任意代码；规则或事实含糊时保留未知。接口、四态及计算契约统一见 [[可行动事务Agent-UI原型规格表]]。

四态含义保持一致：`SATISFIED` 是已核验事实满足条件；`CONFLICT` 是已核验事实不满足条件，包括已证实为0且低于门槛；`MISSING` 是规则已确认但缺少可明确要求补充的必要事实证据；规则或证据冲突、单位不明等归 `UNKNOWN`。未知或缺失数值用 `null`，不以0代替。未覆盖条件不显示为已通过，正式认定由学校完成。

### 合成例子足以说明亮点，真实制度必须按原文核验

以下数值与阈值是统一合成案例，不代表已核实校规或真实学生记录：

| 项目 | 学时 | 本轮表现 |
|---|---:|---|
| 社会实践 | 32 | 仅导入，不核验分类条件 |
| 志愿服务 | 18 | 仅导入，不核验分类条件 |
| 思想成长 | 24 | 仅导入，不核验分类条件 |
| 创新创业 | 12 | 门槛20，差8 |
| 文艺体育 | 0 | 已证实为0；门槛10，差10 |
| 技能特长 | 42 | 仅导入，不核验分类条件 |
| 总量 | 128 | `32 + 18 + 24 + 12 + 0 + 42`；门槛120 |

案例假设六类互斥、同单位、同统计期间、无重复，且均可计入总量；在这些前提下，两个已核验分类的缺口可合计为18学时，不能推出全部认定结论。

假设新增10个可认定的创新创业学时，总量变为138、创新创业变为22，**只关闭创新创业缺口，文艺体育仍差10**。模拟不修改原始记录，也不保证未来活动获认定。换用公开制度时按其实际条款展示，不能强行套入这组阈值。

## 四、赛前准备、67小时现场开发与最终提交

**官方开发窗口为10月1日14:30至10月4日09:30，共67小时。** 活动到10月4日下午不代表可以继续修改封存作品；排期还要预留休息、活动、排障和封包时间。官方允许1–5人组队，每人一队、每队一个主赛道作品；具体人员与分工由团队据实际能力确定。

## 五、现场完成标准与收缩策略

现场目标是“核心流程实际完成”，不是赛前通过完整产品验收。建议围绕下列关键行为安排精简用例，实际结果和未完成项如实记录：

- 合成基线的总量、两个分类缺口和来源对应正确；更换输入会触发真实重算。
- 阈值相等能判为满足，确认0与缺失记录能区分；未知数值不会被当成0。
- 规则或证据冲突、单位不明、重复计入等关键问题能被拦截或明确提示，不输出虚假通过。
- 假设试算只修改模拟结果：创新增加10后，文艺体育仍差10，原始记录不变。
- 从提交入口按运行说明可复现主流程；网络或启动故障有清楚的失败提示，备用录屏来自封包前内容。

若实时抽取不稳定，先展示人工核验和纠错步骤，缩减输入版式与界面数量；若无授权真实个人样本，用标注清楚的合成 CSV。若计算或未知处理仍有错误，应说明未完成项并收缩已完成能力的表述，不能用预置结论伪装已跑通。保持一个主场景，不临时加第二个企业场景。

原先建议的“至少30项规则边界用例、10组端到端案例”属于**赛后扩展验收集**，不是本届报名门槛或现场固定数量要求。目标、实际执行结果及证据分开记录，状态汇总见 [[可行动事务Agent-Demo状态表]]。

## 六、赛后再验证产品与商业成立条件

这些问题决定是否持续投入产品，不否定当前 idea 的参赛价值：

| 赛后议题 | 建议证据 |
|---|---|
| 真实流程是否适用 | 至少两组合规、脱敏的真实样本，核对制度适用范围、CSV来源与人工预期结果 |
| 正确性是否稳健 | 扩展至30项以上规则边界用例、10组端到端案例，保存失败、修复与回归记录 |
| 是否比替代办法省力 | 与人工表格、教务展示、通用 LLM 同题对比，记录输入、版本、提示、耗时、遗漏与修正次数 |
| 重跑与响应体验 | 分别记录抽取差异、已核验输入的执行一致性、延迟与超时 |
| 全部成本是否可持续 | 单次模型调用及重试、存储和流量；规则包冷启动、版本维护及每次人工复核工时 |
| 谁会重复使用与付费 | 观察实际任务频次，访谈学生和潜在机构使用者，再分别记录试点行为与付费结果 |

学生低频、付费能力、机构采购需求均不能凭想象确定；机构市场是独立假设，个人免费使用不会自然转为机构采购。探索访谈帮助发现问题，不等于市场成立。跨校泛化、维护成本、网络效应和商业模式都留待这些证据支持。

公开演示优先使用合成个人数据。进入真实试点前，再明确授权、最少字段、第三方模型处理、访问控制、保存期限和删除方式；不代写、不伪造、不自动提交仍是产品边界，不能因此宣称已通过合规审查。

## 七、评分规则以最终公告为准

官方页内出现专业评价85%、网络评价15%的方向设计，但换算、适用范围等仍待审定；专业奖又有按专业成绩排序的表述。这一冲突须由组委会确认，不能自行推算权重、得分或胜率，也不能编造创新或商业分项评分表。赛事更新集中维护在 [[可行动事务Agent-西客松参赛对齐]]。

当前行动是完善问题与演示草图、准备通用工具、确认可用资料及分工，并把核心实现留在正式开发窗口。用一个能解释、能运行、能检查边界的作品参加评审，赛后再判断它是否值得成为长期产品。
