# 可行动事务 Agent · 路演答辩应答卡

> **用途**：路演 / 答辩现场被质疑时的即时话术。每张卡 = 评委潜台词 + 一句主回答（背下来）+ 展开弹药 + 忌讳。
> **配套**：[[可行动事务Agent-定位决策]] · [[可行动事务Agent-产品定义]] · [[可行动事务Agent-学分认定Demo规格]]
> **用法**：先背 §0 黄金三句 + §1 通用话术；§2–6 分类弹药，赛前每人认领几张；§7 是被问就甩的一页速查。

---

## 0. 黄金三句（先背这个）

1. 「别人告诉你**这份文件说了什么**，我们告诉你**它对你意味着什么、你还差什么、下一步做什么**。」
2. 「我们不做模糊语义匹配。我们把制度文本**编译成可执行规则**，对你的事实做**带举证的裁决**——判定是符号的、可验证的，不是模型拍脑袋。」
3. 「大学只是天然实验场。凡是『收到文件 → 判断谁要做什么 → 备料 → 执行 → 汇报』的流程，都是我们的市场。」

---

## 1. 通用防守话术（被打断 / 被逼到墙角时）

- **被问到没验证的** → 「这一点我们**还没验证**，目前是方向假设。」诚实比嘴硬得分；评委多为老师，识破夸大立刻扣分。
- **被拿竞品压** → 先**承认对方强**，再切「但它解决的是另一个问题」。别否认事实（Mem 真有 Slack/Gmail 双向同步）。
- **被逼技术细节** → 拉回「LLM 只归一化，判定交规则引擎」，把话题从「模型会不会错」转到「判定层可复现」。
- **节奏** → 任何回答 ≤ 30 秒，收尾一定落到「所以我们……」。

## 2. 竞品差异化

### Q1 ·「NotebookLM 已经能带出处引用了，你的证据链有啥不同？」
**潜台词**：你最核心的「证据链」是不是已被免费产品做掉。
**主回答**：「NotebookLM 做的是**引用**——告诉你答案出自哪一页。我们做的是**裁决**——判定你**是否满足每一条**、还差几学时，并为每条判定挂上证据。引用是『内容在哪』，裁决是『你达标没』，这是两件事。」
**弹药**：① 它不算数值缺口、不做双约束（总量 vs 分类）；② 它不区分「已满足 / 冲突 / 缺失 / 待确认」四态。
**⛔ 忌讳**：别说「NotebookLM 很弱」——它很强，只是任务不同。

### Q2 ·「这不就是又一个 Mem / Notion？」
**主回答**：「Mem 回答『我正在做什么』，我们回答『**这件事对我有什么要求**』。它的推理是 context understanding，我们是 requirement → person matching。它跟上你的工作，我们把外部条款逐条判到你身上。」
**弹药**：推理类型不同，不是功能差距（见 [[可行动事务Agent-定位决策]] §3）。
**⛔ 忌讳**：别说「Mem 做不到从外部建任务」——事实错误，它有双向同步。

### Q3 ·「说白了不就是 RAG + LLM 套个壳？」
**主回答**：「如果只把文件总结出来，那确实是 RAG。但我们的 Agent 要完成四次判断：和谁有关 → 要求什么 → 还缺什么 → 下一步做什么。**RAG 到理解内容为止；我们的判定是符号化、可验证的**——这是神经符号，不是 RAG。」
**弹药**：Logic-LM / Rules as Code 佐证（LLM 解析 → 规则引擎裁决）。
**⛔ 忌讳**：别回避，直接认「总结那部分确实是 RAG」，再把差异点落在裁决层。

### Q4 ·「国内 ima / 豆包 / WPS AI 也能做。」
**主回答**：「它们是通用知识库，输出是问答。我们输出的是**带缺口和证据的可行动事务清单**，且针对中文校园的强规则文档做了专门的双约束判定。通用工具不会为『二课分类不可抵扣』这种规则写判定逻辑。」

## 3. 技术深度

### Q5 ·「LLM 抽取会幻觉，判定错了后果很严重。」
**主回答**：「所以我们把架构拆两层：**LLM 只做归一化（把文字变成数字和字段），判定交给确定性规则引擎**。数值比较是纯代码，零幻觉。抽取环节每个字段回显原文出处，低置信度标 `UNKNOWN` 让人复核。」
**弹药**：学分场景判定是纯数值 → 天然适配；SARA / LegalBench 证明「别让 LLM 直接判条文」。
**⛔ 忌讳**：别吹「我们不会幻觉」——只说「判定层不依赖 LLM」。

### Q6 ·「规则千变万化，你怎么保证抽取对？泛化怎么办？」
**主回答**：「72 小时我们不追泛化，只真做 1–2 类、做深做真。抽取靠受控词表 + 置信度 + 缺源告警，拿不准就显式标『待确认』——**我们宁可示弱，不冒充准确**。泛化是产品阶段用累积的已核验规则集去解决。」

### Q7 ·「技术壁垒 / 护城河在哪？抽取谁都能做。」
**主回答**：「LLM 抽取确实会商品化，我们不把护城河放那。护城河在**积累的已核验规则集 + 用户事实数据的网络效应**——用得越久，判定越准、缺口越可信、可补途径越全。」
**⛔ 忌讳**：别把护城河吹成「中文能力 / 无 Android / 我们懂校园」，评委一句「补个端就行」就破。

## 4. 商业与市场

### Q8 ·「学分认定一辈子用一两次，谁会持续用？」（最尖锐，必被问）
**潜台词**：低频 = 没留存 = 不是产品。
**主回答**：「学分认定是**钩子**——痛到能拉人进来。留存靠**高频入口**：奖学金评优（每年）、竞赛报名、通知 / 材料提交（每周）。同一套『文件 → 缺口 → 行动』能力，换个文件就复用。学分认定负责『第一次惊艳』，这些负责『持续回来』。」
**⛔ 忌讳**：别硬把学分认定说成高频，一测就破。

### Q9 ·「市场多大？怎么扩？」
**主回答**：「个人版验证能力，团队版做聚合，企业版是真正的量——凡是文档驱动的流程都是市场。但企业侧我们**还没访谈，是方向假设**。」

### Q10 ·「企业市场验证了吗？」
**主回答**：「没有，目前全是推演。这也是下一步要做的：找 2–3 个真实的人聊 30 分钟。」——诚实作答。

### Q11 ·「怎么赚钱？」
**主回答**：「个人版免费获客，价值在企业版订阅——按文档驱动的 workflow 席位收费。现阶段不急定价，先验证核心假设。」

## 5. 风险与红线

### Q12 ·「一键生成申请材料，是不是代写？学术诚信怎么说？」
**主回答**：「我们**不编写任何不存在的经历**，只**整理和校对已有材料 + 列出缺口**。缺来源的内容显式告警、绝不自动补写。学分场景更干净——只算数、列清单，没有代写成分。」
**⛔ 忌讳**：别用「一键生成材料」这个词，统一说「整理已有材料 + 列缺口」。

### Q13 ·「教务系统的学时数据你拿得到吗？」
**主回答**：「教务系统普遍支持导出学分统计和二课记录。用户**导出什么就丢什么**——这恰好正面证明『无痛输入』。拿不到就降级为截图 OCR。赛前我们已实测导出流程。」
**⚠️ 前提**：赛前必须真测导出，这是本 Demo 第一风险。

### Q14 ·「判错了资格，谁负责？」
**主回答**：「所有外部动作**必须用户确认**（human-in-the-loop），我们给判定和证据，决定权在用户；且判定纯数值可复算，可当场核对。」

---

## 6. 团队与执行

### Q15 ·「为什么是你们能做？」
**主回答**：「我们是大学生，亲身踩过『总量够了却没通过认定』这个坑。信管背景 + Java 后端能落地规则引擎——这个场景我们既是用户又是开发者。」

### Q16 ·「3 天能做出来？Demo 是不是预置假数据？」
**主回答**：「Demo 用**三份真实文件真解析**，判定层真跑。为控范围只真做 1–2 类，其余按汇总数字展示——我们会明确标出哪些是真解析、哪些是预置。」
**⛔ 忌讳**：被追问真假时主动区分「真解析 / 预置」，别含糊。
