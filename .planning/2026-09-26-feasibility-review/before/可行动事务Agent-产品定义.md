# 可行动事务 Agent（产品类别 / 工作名，非最终品牌名）

> 📄 配套文档：[[可行动事务Agent-Demo状态表]]（180 秒 Demo 的 11 个状态 / 7 屏 原型规格）

> **对外第一句**：别人告诉你「这份文件说了什么」，我们告诉你「**这份文件对你意味着什么**」。
> **对外第二句**：并把它变成你可以马上行动的下一步。
> **核心原语**：**可行动事务（Actionable Obligation / Opportunity）**
> **核心能力**：条款级判定 + 举证（Requirement → Evidence）

## 一、先划清边界：我们不是什么

| 不能说 | 原因 |
|--------|------|
| 「AI 知识库」「第二大脑」 | Mem / Notion / 飞书 / Capacities 的共同话术，一说即被归类 |
| 「自动打标签、建双链、知识图谱」 | 已是行业及格线，不是卖点 |
| 「我们的 AI 有记忆 / 意向 / 主动提醒」 | Mem 2026 已全部实现，讲了就是自曝无知 |
| 「Mem 做不到从外部信息建任务」 | **事实错误**——Mem 有 Slack/Gmail 双向同步、WhatsApp、日历、网页剪藏、PDF 问答 |
| 「我们什么都能做」 | 没有边界 = 没有判断力 |

## 二、核心原语：可行动事务

系统收到任何信息后，第一件事不是总结，而是判定：

> **这对我来说是一项「可行动事务」，还是仅仅一条「知识」？**

**术语说明**：不叫「义务」——义务在法律语境里有强指向。用 **可行动事务**，含两类：

| 类型 | 定义 | 例 |
|------|------|-----|
| **Obligation** | 别人要求你做 | 提交 / 报名 / 审核 / 回复 / 签署 / 补交 / 参加 |
| **Opportunity** | 别人给你一个值得抓的机会 | 比赛 / 奖学金 / 实习 / 招聘 / 活动 / 项目申报 |

### 示例：上传《2026 年国家奖学金评定办法》

**普通 AI 的输出**：该通知主要包括以下几点……

**本方案的输出**：

```
发现一项可行动事务

【国家奖学金申请】
类型：Opportunity
截止：10 月 XX 日
提交对象：XX 老师
适用对象：本科生（条件判定见证据链）

要求：
  ✓ 成绩排名      来源：《评定办法》第 3 条
  ✓ 综合测评      来源：《评定办法》第 3 条
  ✓ 获奖经历      来源：我的《XX 比赛获奖证书》
  □ 个人事迹材料   来源：—
  □ 申请表        来源：学校模板
  □ 指导老师确认   来源：—

下一步：「整理我的材料包」
```

## 三、四个支撑机制

| # | 机制 | 说明 |
|---|------|------|
| 1 | **事务抽取器** | 从任意文件识别：对象 / 条件 / 截止 / 材料 / 流程 / 责任人 / 例外情况。「请于 9 月 30 日前提交 XXX 材料至辅导员」→ 一条带截止日期的待办 |
| 2 | **Gap Analysis** | 不只说「比赛开始报名了」，而是算出**你距离完成还差什么**。输出格式：已满足 4 项 / 缺少 2 项 / 冲突 1 项 / **需准备材料 3 项** |
| 3 | **证据链（Evidence Chain）** | 每一个判定都必须能展开到「条件 → 依据条款 → 我的数据来源」。**这不是加分项，是准入项**（见下） |
| 4 | **Why Me** | 主动提醒必须回答「凭什么提醒我」：① 你曾保存过 XX ② 方向匹配 ③ 参加过类似比赛 ④ 截止还有 18 天 |

### 为什么「证据链」是准入项，不是功能

这类产品的核心动作是**判定「你是否符合条件」**。判定错了的后果（错过截止、白准备一堆材料、被老师指出不符合资格）**比不提醒严重得多**。

因此证据链不是锦上添花——**没有证据链，「资格判定」这个品类根本不成立**。它是把产品从「会胡说八道的聊天机器人」变成「可审计的事务 Agent」的那一步。

### 缺源告警设计

材料来源逐条标注，缺失来源的显式告警：

```
【待确认材料包】
✓ 成绩信息     ← 教务文件
✓ 获奖记录     ← 用户上传证书
✓ 社会实践     ← 历史记录
⚠ 以下内容缺乏来源，请用户补充：
   □ 个人事迹材料
```

### Human-in-the-loop 铁律

系统**不替学生编写不存在的经历**，只整理用户已拥有的真实材料。所有外部动作（提交 / 联系第三方 / 更新外部系统）**必须用户确认**。

## 四、竞品真相：Mem 到底能做到哪一步

> 2026-09-23 三次核查。**必须基于实证说话，不能凭想象攻击竞品。**

### 4.1 Mem 已经具备的（不可再声称「它没有」）

| 能力 | Mem 2026 实际状态 |
|------|------------------|
| 无整理输入 | ✅ 零文件夹零标签，AI 自动关联 |
| 外部来源接入 | ✅ Slack / Gmail **双向同步**、WhatsApp 快捷capture、Google Calendar / Outlook、Chrome 插件、API |
| PDF 处理 | ✅ 语义问答覆盖已保存内容含 PDF |
| 主动提醒 | ✅ Mem Agent "Proactive without the noise"，自己判断何时提醒并给 next step |
| 意向 / 目标 | ✅ 官方定位即 tasks / projects / goals |
| 记忆白盒 | ✅ 记忆存在可见笔记中，可看可改 |
| 持续上下文 | ✅ 后台持续 review 并更新对人物 / 项目 / 决策 / 优先级的理解 |

**其他同类**：Notion 3.0（Agent + Enterprise Search）、Capacities（Object + Properties + Links + Graph）、Hermes Agent + LLM Wiki（自动抽实体 + 双链 + 更新索引）、Liminary（proactive recall）、Hermes 3000（gap analysis）、Glean（Connector + Index + Enterprise Graph + Memory）。

### 4.2 两条可核实的中文场景硬缺口（比「无人优化」具体）

| 缺口 | 事实 | 对应场景 |
|------|------|---------|
| **无 Android 客户端** | Mem 截至 2026 无原生 Android 应用（仅 Web / Mac / Windows / iOS / iPad） | 校园场景绝大部分是**手机拍照存通知**，安卓用户直接不可用 |
| **转录仅支持英文** | 评测指出其语音/会议转录存在语言限制，非英语会议是真实痛点 | 中文通知、中文会议、微信语音全部受限 |

> 这两条是**可核实的**，可以说；但**仍不要吹成护城河**——评委可以回一句「LLM 中文能力已经很好，补个端就行」。

### 4.3 中文校园场景的正确定位

- ❌ 不要说「没人做中文校园文件，所以是壁垒」
- ✅ 应该说：**校园场景拥有高度标准化、强规则、强时间节点、强材料要求的文档体系，是验证「Document → 可行动事务 → Workflow」这一能力的天然实验场。**

这些文件天然具备：对象 / 条件 / 时间 / 材料 / 流程 / 责任人 / 例外情况——**是规则化推理最理想的训练与验证环境**。

大学不是壁垒，**是 AI Agent 的天然实验场**。

## 五、真正的差异化：推理类型不同

**结论：不要再打「输入方向」。** Mem 已经能接入外部来源，「谁先输入」不成立。

真正不同的是**推理类型**：

| | 普通 AI / Mem 类 | 本方案 |
|---|---|---|
| 核心对象 | Note / Context / Task | **外部制度性事务** |
| 首要问题 | 我正在做什么？ | **这件事对我有什么要求？** |
| 输入 | 我的工作 / 记录 / 消息 | 通知 / 简章 / 制度 / 要求 |
| 输出 | Task / Reminder / Draft | **可行动事务（Obligation / Opportunity）** |
| 关键推理 | **Context understanding**（理解我在做什么） | **Requirement → Person matching**（把条款条件映射到具体个人） |
| 核心能力 | Remember | **Interpret + Adjudicate（判定）+ 举证** |
| 下一步 | Remind / Draft | **Gap → Prepare → Workflow** |
| 价值 | 不忘事情 | **降低完成事务的成本** |

**一句话**：Mem 做的是「理解你的上下文」，我们做的是「**逐条判定某份文件的条款是否被你满足，并给出证据**」。这两件事结构上不同——Mem 的任务是跟上你的工作，不需要做条款级举证。

### 定位图

```
                    行动执行
                       ↑
                       │        ★ 本方案
                       │   （外部制度输入 × 行动执行）
                       │
        Workflow ──────┼────── 企业 Agent
                       │
  用户主动产生 ────────┼──────── 外部组织产生
                       │
      Mem / Notion ────┼────── AI 知识库
                       │
                       ↓
                    信息理解
```

### 回答「你这不就是 RAG + LLM 吗？」

> 如果只是把文件总结出来，那确实是 RAG。但我们的 Agent 不止回答文件内容，它要完成四次判断：
> ① **Is it relevant?** 这件事和谁有关？
> ② **What does it require?** 它要求我做什么？
> ③ **What is missing?** 我还缺什么？
> ④ **What's the next action?** 下一步怎么完成？
>
> RAG 到「理解内容」为止；Agent 从「判断对象 → 判断责任 → 判断缺口 → 规划行动 → 等待确认」。

## 六、明确砍掉什么

| 砍掉 | 理由 |
|------|------|
| 关系图谱可视化（不作核心） | 评委看到漂亮图谱只会想「又一个知识库」。图谱藏在后面，用户不需要知道底层有 Knowledge Graph |
| 用户自建标签体系 | 会把产品拽回 Notion / Obsidian / Capacities。**用户不创建标签，结构由 AI 产生** |
| 「第二大脑」等泛化话术 | 已失去区分度 |
| 全能输入 | 72h MVP 只做 **PDF / Word / 图片 + 文本** |
| 「预计准备时间 3 小时」 | **删掉**。这类时间预估不可靠，一旦出错会摧毁整条信任链。改为「需准备材料 3 项」 |
| 一次性铺开所有场景 | 先跑通单点 |

## 七、72 小时 MVP：第二课堂学分认定 Agent

> 校园主场景已从「奖学金申请」换成「**第二课堂学分认定**」——理由与完整规格见 [[可行动事务Agent-学分认定Demo规格]]。
> 一句话：它命中的是「**总量达标 ≠ 分类达标**」这个学生最痛、最看不见的地方。

**一条闭环，跑通即胜。**

```
「培养方案 + 二课认定办法 + 我的已修学时统计」三份文件（真实解析）
        ↓
① 规则解析：总量约束 + 各类别分类约束
        ↓
② 读取用户 Context（从教务导出文件抽取实际学时）
        ↓
③ 双约束判定：总量 vs 分类 分别核算
        ↓
④ Gap Analysis：还差哪一类、多少学时，按缺口排序
        ↓
⑤ 证据链：每条判定的依据条款 + 学时来源
        ↓
⑥ 依《认定办法》反查可补途径 → 生成补修清单
        ↓
⑦ 用户确认（Human-in-the-loop）
```

**为什么这个场景更好**：输出的是**数量缺口**（"再修 8 学时"）而不是资格判定（"你不合格"）——数量缺口天然可行动；判定是**纯数值**，完全适配「LLM 归一化 + 规则判定」；且**无学术诚信风险**。

**⚠️ 72h 现实约束**：
- 只真实覆盖 **1–2 个类别**（建议创新创业 + 文艺体育），其余按汇总数字展示
- **先定义单位换算（学时 / 学分）再动代码**——认定办法常混用，口径错了缺口会全错
- **赛前必须实测教务系统能否导出真实学时统计**（本场景第一风险）
- Demo 限定为「3 份真实文件 + 1 条主线」，**不要做通用规则引擎**

## 八、待验证的问题与风险

| # | 风险 | 说明 | 应对 |
|---|------|------|------|
| 1 | **证据链缺失 = 品类不成立** | 资格判定错误后果严重（错过截止、白准备、被指出不符合） | 证据链是准入项，不是可选项；关键字段回显原文出处 |
| 2 | **学术诚信红线** | 校内「一键生成申请材料」实质是代写个人事迹，评审多为高校教师 | 统一表述为「**整理与校对已有材料 + 列出缺口**」；不编写不存在的经历；缺源显式告警 |
| 3 | 差异化窗口短 | Mem 迭代快，无 Android / 中文转录两项缺口会被补上 | 护城河放在「条款级判定 + 举证」，不放端和语言 |
| 4 | 冷启动 | 新用户无历史材料，首次体验平淡 | 「导入即得」：一次导入整学期材料即产出可见事务清单 |
| 5 | 主动提醒噪声 | 提醒太多等于没提醒（Mem 用户已有此抱怨） | 只推「可行动」提醒（有截止 + 有缺口） |
| 6 | 原语重设成本 | 改为「可行动事务优先」后交互需重做 | 交互原型先于功能开发 |
| 7 | **把目标当事实** | 竞品对比表里「本方案」列全是 ✓，那是**目标状态不是已验证能力** | 路演前必须完成实测，未验证项留空或标注 |

## 九、产品命名

**建议：现在不要定名。核心假设尚未验证，定名是本末倒置。**

### 外部候选与风险

| 候选 | 我的判断 |
|------|---------|
| **知事** | ❌ **有严重语义碰撞**。「知事」是日本都道府县首长的正式官名（東京都知事），也是中国古代/民国官名（县知事）。中文语境第一反应不可能是「知道事情」，比「信息资产 OS」更危险——后者至少准确 |
| 有事 | ⚠️ 日常口语「你有事吗」，歧义高，且商标/搜索难度大 |
| 知行 | ⚠️ 王阳明「知行合一」，认知度高但品牌已被大量占用 |
| 事见 / 应事 | 🟡 生造感强、不撞既有语义，但需要解释，不是 3 秒懂 |
| InContext | 🟡 英文可用，中文校园场景不直觉 |

**命名方向建议**：名字应来自「**把要求变成动作**」这个动作本身（动词性），而不是来自「信息 / 资产 / 知识」这类名词。等核心假设验证后再专门做一次命名 + slogan + Logo。

## 十、演进路径

| 阶段 | 形态 | 场景 |
|------|------|------|
| 1 | 个人版 | 大学场景（验证场）——奖学金 / 评优 / 竞赛 |
| 2 | 团队版 | 团队知识与工作记忆 |
| 3 | 企业版 | **Document-driven Workflow** |

**企业侧入口不是「企业 AI 知识库」**（Glean / Notion / 飞书 / M365 已极强），而是：

> 凡是「收到一份文件/通知 → 判断谁需要做什么 → 准备材料 → 执行 → 汇报」的流程，都是市场。

例如教育机构：教育局通知 → AI 理解 → 判断涉及哪些教师 → 生成任务 → 匹配模板 → 教师提交 → 自动汇总 → 负责人周报。

> ⚠️ 企业侧**尚未经过任何真实访谈**，属方向假设。路演只能说「下一阶段将从个人场景向企业侧的文档驱动型 Workflow 延伸」，**不能说「已验证企业市场」**。
