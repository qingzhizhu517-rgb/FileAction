## 3. 本轮统一的关键口径

- **范围**：一校、一版制度、一个适用群体；1–2 份文本 PDF + 一种 CSV 导出；先核验总量、创新创业、文艺体育三个条件。
- **架构**：模型提取候选、人工审核、确定性比较。可复算不等于端到端零错误，学校完成正式认定。
- **样例**：所有演示数值为合成数据；六类 `32+18+24+12+0+42=128`。创新差 8、文体差 10，其他类别仅导入未核验。
- **状态**：有证据的 0 学时为 `CONFLICT`；缺明确可补的事实证据为 `MISSING`；规则、单位或来源冲突未解决为 `UNKNOWN`。
- **试算**：创新假设增加 10 后，该类变为 22；文体仍缺 10，不宣布全部通过，不写回已认定事实。
- **证据**：计划、合成案例、人工核验、现场抽取和缓存回放须区分，不把待测事项写成已经完成。

## 4. 尚待验证的事项

| 优先级 | 事项 | 完成证据 |
|---|---|---|
| P0 | 目标校、有效规则、适用对象、样本处理权限 | 可核对的制度与导出样本、规则审核记录 |
| P0 | 三条件计算、0/缺证、单位、重复与部分覆盖 | 按 UI 规格保存的参考答案与运行结果 |
| P1 | 抽取、定位和人工校正是否可靠 | 端到端样例、错误分类、人工修改及耗时 |
| P1 | 是否优于现有替代流程 | 同输入的人工表格、教务展示和 AI 对照 |
| P2 | 使用频次、成本、付费和机构需求 | 用户行为、访谈记录及后续试点证据 |

原有场景冲突和无依据承诺已纳入本轮修订；上表是尚需真实验证的问题，不能用文档修订代替完成。

## 5. 维护约定

定位和范围以定位决策为主，字段与计算以 UI 规格为主，外部事实以有日期的来源为依据；不把任何产品文档当成真实校规。冲突时修正主文档并同步下游，不只修改路演话术。

新增业务文档更新本地图；正文变更更新已有 `updated` 字段。个人成绩、获奖和学时明细不入库，公开样例使用合成或适当脱敏数据。完整协作规范见 [[AGENTS]]。
