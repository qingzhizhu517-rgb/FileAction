# 可行动事务 Agent · 内部筛选速览

> **结论：可以做受限原型验证；当前证据不足以确认完整产品或商业可行性。**
> 本库尚无应用实现与真实测试结果。定位以 [[可行动事务Agent-定位决策]] 为准，具体范围见 [[可行动事务Agent-学分认定Demo规格]]，核查依据见 [[可行动事务Agent-核查修订报告]]。

## 一、这次到底验证什么

**有限制度范围内的条款核验与缺口规划助手。** 用户导入制度文件与个人记录，系统帮助核对要求、定位证据、计算已知缺口，并整理下一步。

核心假设：部分学生需要跨文件核对第二课堂要求，现有方式容易遗漏分类门槛或混淆口径。是否普遍存在、现有教务系统是否已解决、用户是否愿意另用工具，均需实地验证。

本轮拟验证的工作流是：

```text
制度 PDF + 个人 CSV
  → 抽取候选规则与事实
  → 人工核验来源、适用范围与单位
  → 白名单比较逻辑计算
  → 逐项状态 + 证据 + 缺口 + 候选补修清单
```

不将模型能力视为已解决，也不把用户输入视为唯一瓶颈。规则、数据、解析、界面和人工核验共同决定结果质量。

## 二、主 Demo 的一屏结论

**以下为合成数据与假设制度，只展示三个已核验条件。** 样例假设各类互斥、同单位且不可跨类抵扣，因而两个分类缺口可以求和；真实规则须另核实。

```text
二课总学时  128 / 120  SATISFIED
创新创业     12 / 20   CONFLICT，缺 8 学时
文艺体育      0 / 10   CONFLICT，缺 10 学时

已知分类缺口：2 类，共 18 学时。
其余类别未核验，不能判断整体认定是否通过。
```

分类导入值：社会实践 32、志愿服务 18、思想成长 24、创新创业 12、文艺体育 0、技能特长 42，合计 **128**。非本轮核验类别只显示导入值，不给“达标”标记。

可演示一次 what-if：假设创新创业新增 10 学时并获认定，则该类达到 22、缺口归零；文艺体育仍缺 10。假设总量变为 138；模拟不写回已认定事实，也不代表整体通过。

这里的价值是把“总量足够”与“所核验类别仍有缺口”并列展示；不能宣称所有学校都有这些门槛、学生无法自己计算或既有系统无法展示分类。

## 三、团队应守住的范围

| 本轮拟做 | 本轮不做 |
|---|---|
| 一校、一版制度、一类适用学生 | 多校自动适配、完整资格认证 |
| 1–2 份文本 PDF + 一种可取得的 CSV 导出 | OCR、Word、任意表格、微信、语音、教务接口 |
| 总量、创新创业、文艺体育三个条件 | 全类别规则、任意例外推理、通用规则引擎 |
| 规则与事实人工核验、来源回显、确定性比较 | “零幻觉”、无人校验的自动裁决 |
| 本地候选补修清单、用户选择与模拟 | 自动报名、发消息、外部提交、企业运行 Demo |

“72 小时”以样本就绪和 2–3 名熟悉技术的成员为前提。缺少真实输入时，只能验证合成交互或计算，不能声称完成学校适配。详细日程和验收见 [[可行动事务Agent-可行性分析]]。

## 四、三个必须能解释的设计

1. **规则与本人证据分开。** 每项结果能查看制度版本、原文位置、CSV 对应行、单位与比较值。引用可帮助审查，但有引用不代表结论必然正确。
2. **不把缺证当零值。** `SATISFIED` 是已核验且满足；`CONFLICT` 是已核验且不满足，包含明确的 0 学时；`MISSING` 是可明确补充的证据缺失；`UNKNOWN` 是适用性、证据冲突、单位或例外未明。四态不必同时出现在基线样例中。
3. **行动与结果分开。** 制度允许的补修途径不等于现在可报名的活动；报名资格、时间、名额和最终认定需另查。生成清单不代表完成，模拟增加学时不代表实际获认定。

不编造经历、证书、规则或缺失字段；个人原始记录不入文档库，试点使用合成或获授权脱敏数据。

## 五、竞品与创新怎么判断

Mem、Notion、NotebookLM、ima 可能已具备导入、引用、计算或任务能力。**提示词加电子表格、人工核对、现有教务系统**都应进入比较，不能只挑知识库类产品。

本方案的差异化假设是“固定、可复查、可纠错的核验流程”。用同一批输入比较正确性、遗漏与错误通过、证据定位、修正时间和总耗时。不能凭产品定位推断对方“只会摘要”“不能判定”，也不能把采用 Rules as Code、LLM 或证据引用本身当作新技术。

规则维护经验与个人数据复用可能有价值，但没有已证明的护城河或网络效应。外部产品状态、论文与核查限制统一见 [[可行动事务Agent-核查修订报告]]。

## 六、按顺序验证四类可行性

| 关口 | 需要取得的证据 | 若证据不成立 |
|---|---|---|
| 数据与规则可得 | 目标校有效制度、适用群体、可用 CSV、可对账样本 | 调整试点范围；暂停真实适配承诺 |
| 技术正确性 | 人工标准答案、边界与异常样例、计算和溯源结果 | 先修正口径与规则，再扩功能 |
| 用户价值 | 观察真实核对流程，比较现有工具下的耗时与错误 | 缩小问题或停止该场景投入 |
| 商业与持续使用 | 复用频次、付费对象与意愿、审校及支持成本 | 保留工具形态，暂不扩大为平台 |

学分核验可能低频，具体依学校流程而定。奖学金、通知报名是后续留存假设，不能因为理论上出现更多就视为留存已解决。企业侧尚未完成访谈或购买验证，不在本次实现范围内。

## 七、团队现在需要落实的三项决策

1. **落实样本负责人。** 先取得一校一版的获授权制度与脱敏导出，确认真实规则符合演示范围；为人工标准答案指定复核人。
2. **锁定受限原型。** 先做三个条件及完整证据链，沿用 [[可行动事务Agent-Demo状态表]] 的 180 秒主线；新增格式、类别和场景须在基线通过后另评估。
3. **设定继续或停止的标准。** 按 [[可行动事务Agent-可行性分析]] 完成输入、正确性、用户价值验收；达不到时调整范围。访谈结果与失败样例进入核查记录，不把演示成功当作产品成立。

命名暂用“可行动事务 Agent”。先核实问题是否值得解决，再决定品牌、长期记忆、主动提醒和团队版。
