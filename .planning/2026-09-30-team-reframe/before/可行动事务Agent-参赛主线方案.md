# 可行动事务 Agent · 参赛主线方案

导航：[[可行动事务Agent-00-总览|文档总览]] · [[02-调研与可行性/可行动事务Agent-竞品分析|竞品分析]] · [[03-参赛与路演/可行动事务Agent-路演答辩应答卡|路演答辩应答卡]]

> 本篇于2026年9月30日经三轮追问重整，取代旧方案（已移入 [[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-定位决策|旧方案归档]]）。方向回到原始愿景：主动发现、可信复用、直接行动，并以同一内核延伸到团队与企业。

## 1. 一句话

**你做过的事，会在下一个机会出现时主动站出来，并告诉你哪些能用、哪些不能用、下一步做什么。**

模型已经知道很多，缺的是“了解你”。每开一个新对话都要重新解释自己，AI 就始终不懂你。本项目沉淀用户确认过的高质量个人上下文，让一份新通知直接变成可行动事务。

## 2. 内核：Document → 可行动事务 → Workflow

普通 AI 读完通知只会说“该通知主要包括以下几点”。本项目把文档转成一件带对象、条件、时间、材料、流程和责任人的事务，并接着推进。

| 层级  | 同一内核回答的问题                   | 本届形态        |
| --- | --------------------------- | ----------- |
| 个人版 | 这件事和我有关吗？我已有什么、还缺什么、下一步做什么？ | 主线，完整实现     |
| 团队版 | 这份通知需要谁交什么？谁交了、谁没交？         | 社团场景轻量实现    |
| 企业版 | 收到文件后，判断谁需要做什么、准备材料、执行和汇报   | 路线图，不做 Demo |

校园通知高度标准化，规则、时间节点和材料要求都很强，是验证这条内核的天然实验场。

## 3. 个人版：三个亮点

### 亮点一：主动发现

用户丢进一份通知，Agent 从个人记忆中找出相关的 Idea、经历、获奖和意向，主动提示：

```text
发现一项可能与你有关的活动

【大学生创新创业大赛】 截止：10月12日（原文第2条）
你此前保存的「校园交友平台」Idea 与本次“社会服务”赛道相关。
你曾表达意向：“以后想做 To B 教育方向创业”。

你已有： ✓ 项目 Idea   ✓ 项目介绍（v2，6月）   ✓ 部分团队信息
要处理： △ 成员名单需按本届重新签字
本次不能用：✗ 往届获奖证明（第5条：已获奖成果不得重复申报）
还缺：   □ 商业计划书   □ 项目 PPT   □ 指导老师信息

下一步：「起草项目简介」「导出待办与日历」
```

意向层记住用户随口说的一句话，例如“以后想找教育相关的兼职”，并在之后的相关通知中说明关联理由。意向只用于解释相关性，不等于用户决定报名。

### 亮点二：可信复用

每条匹配都能点回通知原文和资料原文。对外只讲三类状态，每类下面列具体原因：

| 对外状态 | 内部原因举例 |
|---|---|
| ✓ 可用 | 来源可定位、版本有效、本次用途未发现冲突 |
| △ 要处理 | 需按本次更新、缺签字、版本过期、尚未检查、规则不明需核实 |
| ✗ 本次不能用 | 适用的禁用条款与触发事实同时成立，例如已获奖成果禁止重复申报 |

护栏规则：模型初稿与用户确认分开标注；“本次不能用”不能被普通勾选解除；未检查不等于缺材料；材料齐全不等于资格通过。用户纠正事实后，相关旧结果标为过时。

### 亮点三：直接行动

- 生成缺项待办和截止日期，导出日历文件与 Markdown 准备清单。
- 用已确认的资料起草缺项材料，例如项目简介、个人事迹材料，标为模型初稿供用户修改。
- 不替用户提交、不代签字、不编造经历。

### 两个底色

- **无痛输入**：截图、拍照、转发的文字、PDF、Word 都可以进入。多模态模型负责识别，识别不清的部分标出来请用户确认。
- **记忆自己长出来**：每办完一件事，用户确认过的事实沉淀为记忆卡片，关联图随之增长。第二份通知（例如奖学金）进来时，竞赛获奖记录会自动连到“个人事迹材料”。用户可以查看、修改、停用和删除每张卡片。

## 4. 团队版：社团负责人的一次收件

1. 负责人上传一份通知，Agent 拆解出“谁需要交什么、何时交”。
2. Agent 生成任务，通过链接派发给 2–3 名成员。
3. 成员不需要先用过个人版：没有记忆就直接上传材料；有记忆的成员可以一键授权已有卡片提交。
4. 负责人看到汇总进度：谁已交、谁缺什么、哪份材料被护栏拦下。

白盒边界：负责人只看到成员针对本次任务授权提交的卡片与状态，看不到成员的完整记忆；汇集 Agent 的判断依据对所有成员可见。团队版能独立启动，也会把成员带进个人版。

竞争提醒：接龙管家、飞书、钉钉已能从文档生成收集表、催交和汇总（见 [[02-调研与可行性/可行动事务Agent-竞品分析|竞品分析]]）。团队版的差异只讲两点：成员从个人记忆授权提交；提交物先过护栏，过期或不能用的材料在汇总前就被标出。

## 5. 企业版：路线图

企业入口不是“企业 AI 知识库”，这一类 Glean、Notion、飞书和 M365 已经很强。入口是这条流程：

```text
收到文件/通知 → 判断谁需要做什么 → 准备材料 → 执行 → 汇报
```

例：教育局通知 → AI 理解 → 判断涉及哪些教师 → 生成任务 → 匹配模板 → 教师提交 → 自动汇总 → 负责人周报。差异点在第一步：读懂一份非结构化通知，并判断谁要做什么。审批流和表格收集已有成熟工具，可以作为下游对接。

## 6. 本届范围

| 做 | 不做（进入路线图） |
|---|---|
| 真实 LLM 通知理解，支持截图、PDF、Word、文本 | 自动提交到学校系统 |
| 个人记忆卡片、意向层、关联图可视化 | 后台推送与定时提醒（本届仅在应用内主动提示） |
| 主动发现、三类状态与原文回溯、禁重复拦截 | 完整多人账号与权限体系 |
| 待办、截止日期、日历导出、缺项材料起草 | 企业部署与企业 Demo |
| 团队版：负责人分派、成员授权提交、汇总进度 | 全量采集聊天、邮箱或网站 |

备用：第二场景（奖学金）的跨事务双链，放进问答环节演示。

## 7. 5 分钟展示

| 时间 | 内容 |
|---|---|
| 0–30秒 | 痛点：群通知刷屏、材料散落、每次都要重新向 AI 解释自己 |
| 30–180秒 | 个人版：截图通知 → 要求清单 → 主动发现旧 Idea 与意向 → ✗ 拦下往届获奖证明 → 起草简介并导出待办 |
| 180–250秒 | 团队版：负责人分派 → 成员授权卡片提交 → 汇总进度 |
| 250–285秒 | 企业路线图：同一内核放大到“教育局通知 → 教师任务 → 周报” |
| 285–300秒 | 边界：合成资料、模型初稿需确认、不自动提交 |

另有 3 分钟问答，应答见 [[03-参赛与路演/可行动事务Agent-路演答辩应答卡|路演答辩应答卡]]。

## 10. 验证信号与路线图假设

“个人 → 团队 → 企业”作为路线图假设讲，不作为已成立的商业路径。每层配一个验证信号：

| 层级 | 验证信号 |
|---|---|
| 个人 | 真实用户遇到第二件事务时自然回来使用 |
| 团队 | 同一位社团负责人连续多个周期用它收件 |
| 企业 | 找到一个愿意试点的机构岗位，并明确付款人 |

开赛前找 3 名同学，按他们最近一次真实的报名经历做回顾访谈，记录原话，作为问题价值的证据。

## 11. 不变的底线

- 演示资料为合成数据并明示；不编造用户、经历或测试结果。
- 模型初稿与用户确认分开；准备清单不等于已报名，材料齐全不等于资格通过。
- 本机保存不等于云端模型看不到数据：说明发送了哪些片段、发给哪个服务方。
- 不使用“零幻觉”“竞品都做不到”等说法。
