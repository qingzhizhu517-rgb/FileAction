# 可行动事务 Agent · 可行性分析

> **用途**：区分技术方案、已知证据与待验证假设，为继续、缩减或暂停提供条件，不预测比赛成绩。
> **依据**：定位与范围以 [[可行动事务Agent-定位决策]] 为准；外部事实、来源及修订依据统一见 [[可行动事务Agent-核查修订报告]]。
> **配套**：[[可行动事务Agent-学分认定Demo规格]] · [[可行动事务Agent-Demo状态表]] · [[可行动事务Agent-UI原型规格表]] · [[可行动事务Agent-路演答辩应答卡]]

## 一、当前结论与证据边界

**有限范围的辅助核验在技术上有条件可行；创业可行性尚未验证。** 本仓库目前只有方案文档，没有可运行实现、真实文件实测、用户访谈或付费证据。下文的流程、测试门槛与时间预算均为计划，不是已达到的结果。

可验证的产品假设是：在同一套制度与个人记录下，结构化要求、确定性计算和来源定位，能否比人工表格、现有教务展示及通用 LLM 更快地发现缺口，并降低复核成本。不能预先声称学生必然看不见缺口、人工做不到、竞品不能计算，或已形成护城河。

## 二、MVP 边界与成立前提

| 项目 | 本轮约定 | 未满足时的处理 |
|---|---|---|
| 适用范围 | 一所学校、一个制度版本、一个适用群体 | 无法确定版本或适用对象时停止判定 |
| 制度输入 | 1–2份文本型 PDF | 扫描件、复杂版式先退出本轮范围；OCR、Word 后置 |
| 个人记录 | 一种已确认字段与单位的 CSV 教务导出 | 无法取得时，仅做明确标注的合成演示，不声称已验证真实接入 |
| 执行条件 | 总量、创新创业、文艺体育三个条件 | 其他类别仅导入，分类条件不核验 |
| 输出 | 范围内状态、数量缺口、规则及事实来源 | 不输出完整学分认定结论；正式认定由学校完成 |
| 后置事项 | 企业 Demo、跨校泛化、OCR、Word、外部提交 | 不计入本轮交付或72小时预算 |

有两至三份输入材料不等于“三份真实文件已解析”。演示必须分别标明合成数据、人工核验数据、实时抽取结果及尚未实现能力。

## 三、技术路线与主要失效点

拟采用“提取候选规则与事实 → 人工核验规则、来源及适用范围 → 白名单规则执行 → 展示缺口与证据”的流程。LLM 可辅助归一化，但不能把未审核文本或模型生成的任意代码直接交给执行器。字段、状态和接口定义统一引用 [[可行动事务Agent-UI原型规格表]]，本篇不另建契约。

确定性执行只保证相同输入与规则得到相同结果，不能保证输入、规则解释或程序本身正确。风险包括漏抽条款、单位错误、重复记录、规则版本混用、适用对象错误和证据不完整。需要规则核验、输入校验、明确拒绝状态和回归用例共同控制，不使用“零幻觉”或“CSP 新算法”作为准确性证明。

四态的业务含义须保持一致：

- `SATISFIED`：必需证据可识别且足够，已核验事实满足对应条件。
- `CONFLICT`：已核验事实明确不满足条件；例如已证实文艺体育为 `0`，要求为 `10`。
- `MISSING`：规则已确认，但缺少可明确要求补充的必要事实证据，不能推断为零或未达标。
- `UNKNOWN`：规则或证据冲突、单位不明等使结论无法确定；未知数值使用 `null`。

这里的 `CONFLICT` 指事实与要求不符，规则或证据相互冲突归 `UNKNOWN`。缺失、未知和未覆盖条件都不能被包装成完整认定通过。

### 统一合成样例

以下数据和阈值仅用于演示，不代表已核实校规或真实学生记录：

| 导入项 | 学时 | 本轮核验范围 |
|---|---:|---|
| 社会实践 | 32 | 仅导入，不核验分类条件 |
| 志愿服务 | 18 | 仅导入，不核验分类条件 |
| 思想成长 | 24 | 仅导入，不核验分类条件 |
| 创新创业 | 12 | 阈值20，缺8 |
| 文艺体育 | 0 | 已证实为零；阈值10，缺10 |
| 技能特长 | 42 | 仅导入，不核验分类条件 |
| 总量 | 128 | `32 + 18 + 24 + 12 + 0 + 42`；阈值120 |

该合成样例假设各类互斥、同单位、不可跨类抵扣且均可计入总量，因此两个已核验分类的缺口可合计为18学时；其他规则仍未核验，不能推出整体通过。假设一项活动可新增10个被认可的创新创业学时，则总量变为138、创新创业变为22，**只关闭创新创业缺口，文艺体育仍差10**。模拟不修改原始记录，也不保证未来活动会被学校认可；未知的报名限制和时间成本不能被编造成“最低成本方案”。

## 四、验证计划与继续条件

| 要回答的问题 | 所需证据或实验 | 继续条件 |
|---|---|---|
| 真实输入是否可得、可用 | 取得获授权且脱敏的目标制度与同格式 CSV，记录字段、单位和导出限制 | 三个条件均能找到适用规则与必需事实；否则缩减范围或明确改为合成演示 |
| 规则是否可执行 | 人工核验条款、版本、阈值、单位和来源，记录无法表达的例外 | 白名单能表达本轮条件；例外被阻断或明确标为未知 |
| 计算与状态是否正确 | 建立人工核验的预期结果并执行回归用例 | 目标为预期状态与数值全部一致，缺失或未知不误报通过 |
| 输出是否便于复核 | 检查每项结论能否定位规则与输入记录 | 目标为全部已判定项可回溯；拒绝判定项明确说明缺什么或哪里不确定 |
| 重跑是否稳定、等待是否可接受 | 固定样本多次运行，分别记录抽取差异、已核验输入的执行一致性、延迟和超时 | 当前均待测；已核验输入的判定应一致，端到端延迟门槛在试点前按任务需求冻结 |
| 单次服务成本是否可承担 | 按一次核验记录模型调用及重试、存储和流量成本，注明计费口径 | 当前均待测；先测实际成本，再与使用价值、可能收费及预算比较 |
| 规则与复核的人力投入是否可持续 | 记录一校一版规则包的首次整理、来源核验和测试工时；另计规则更新维护与每次事实复核工时 | 冷启动、维护和单次复核成本均待测，不能把人工投入隐去或当成模型费用 |
| 是否有使用价值 | 用相同材料对比人工表格、教务展示和通用 LLM | 记录错误、修正次数、核对耗时和成本，确认优势是否足以覆盖维护成本 |
| 用户是否愿意再次使用 | 观察目标学生的实际任务，记录触发频次和返回原因 | 有重复需求再扩展场景；低频不自动等于失败，也不凭通知设想推断留存 |
| 谁愿意付款 | 分别访谈使用者、业务负责人及可能的采购方 | 有明确问题与试点意愿后再设计收费实验；访谈不能替代付费证据 |

**建议最小测试基线：至少30项规则边界用例、10组端到端案例。** 边界用例覆盖阈值前/等/后、确认零值、缺失、未知、重复记录、单位不明和版本冲突；不支持的输入应验证拒绝行为。端到端案例覆盖真实或合成输入的完整流程、部分覆盖及反事实模拟，并标注数据来源。按 [[可行动事务Agent-UI原型规格表#九、建议验收集与实测记录]] 保存原始结果，[[可行动事务Agent-Demo状态表]] 汇总状态并链接证据；测试目标、实际结果、失败项和修复后结果分开，当前不得填写“已通过”。

同题比较须固定材料、任务、人工预期结果和评估方法，记录工具版本及提示。现有教务系统无法展示某项时，应记录实测边界，不能据单校结果概括所有学校。

## 五、72小时预算与暂停条件

72小时是**已有可用样本、2–3名熟悉所选技术栈的成员、范围已冻结**时的条件预算，不是当前团队能力声明或交付承诺。

分段工程预算统一维护在 [[可行动事务Agent-UI原型规格表#八、72 小时条件预算]]。预算只覆盖受限原型、技术验收与彩排；用户价值对照和商业验证需另留时间，不能为了在72小时内完成而省略或假报。

若没有可用样本、三个条件无法解释清楚、出现错误通过且无法修复，或证据无法回溯，应暂停“真实辅助核验”的承诺，缩减范围或仅展示已标注的合成原型。不要用预置答案冒充抽取成功，也不要临时扩展 OCR、企业流程来填补缺口。

## 六、商业与合规仍需独立验证

学生任务频次、付费意愿、获客方式与支持成本均未知；“个人免费 → 企业订阅”不是已验证增长路径。机构市场是独立假设，需要明确业务负责人、采购方、流程成本、数据访问权及部署约束，不能把所有文档流程当作可服务市场。规则维护与评测数据可能形成积累优势，但目前没有网络效应或护城河证据。

只整理已有事实、列缺口和计算数值，可以收窄代写风险，不能据此宣布合规通过。试点前需要核实校规与数据使用权限，明确最小收集范围、脱敏、第三方模型处理、访问控制、保存期限和删除方式。真实个人记录不入库，演示优先使用合成数据；用户确认也不能替代输入与规则校验，或免除产品方对错误处理的责任。

**下一步顺序**：先验证样本与三个条件，再实现和验收，随后比较用户收益，最后讨论扩展与收费。任何“已验证”结论都应能指向日期、材料、方法和实际结果。
