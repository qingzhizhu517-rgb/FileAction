# 可行动事务 Agent · 个人 MVP 开发设计

导航：[[docs/可行动事务Agent-00-总览|文档总览]] · [[docs/01-产品方案/可行动事务Agent-参赛主线方案|参赛主线方案]] · [[docs/03-参赛与路演/可行动事务Agent-核心路演稿|核心路演稿]]

## 1. 设计依据与首个交付

2026年10月2日读取项目现行方案、路演与协作规范，并核对旧方案与既有设计资产。设计起草时分支为 `codex/personal-mvp-design`，当时根目录尚无产品源码与产品测试。本篇为用户已在本次会话确认的实施设计；后续实际结果见 [[docs/01-产品方案/可行动事务Agent-个人MVP开发验证|个人 MVP 开发验证]]。本次批准不改变历史计划或旧 Demo 的参考性质。

首个交付是一条可以实际操作的个人端路径：**上传文件 → 说明并确认模型外发 → 解释与自己的关系并核对依据 → 自愿补充或纠正 → 自愿保留背景 → 选择继续后编辑并导出产物。** 用户没有背景也能开始，只理解后结束也算完成目的。

先做单机、单用户本地 Web 应用，只监听回环地址；公网试用、账号与多人隔离需要单独实现和验收，不能将本地版直接当作评委公网服务。本次不实现团队分工、企业权限、自动提交、后台推送、日历与关系图。

## 2. 实施方案比较

| 方案 | 优点 | 成本与限制 | 建议 |
|---|---|---|---|
| React + TypeScript + Vite；FastAPI + SQLite | 前端适合维护对话、证据与编辑状态；Python 便于处理文件；SQLite 可明确控制保留和删除 | 需要 Node 与 Python 两套开发依赖，开发时要配置同源代理 | 推荐；以一条端到端流程为范围 |
| FastAPI + 原生 ES Modules 页面 | 构建依赖少，启动简单 | 随证据、编辑、异步取消与记忆管理增加，界面状态需要更多手工维护 | 可用于进一步压缩范围 |
| TypeScript 全栈 + SQLite | 一套语言和主要运行时 | 文件解析与 Windows 数据库依赖需重新验证；仓库没有可沿用的全栈工程 | 若已有团队偏好可替换 |

设计起草时已发现 Node 22.20.0 与 Python 3.12.0，仅确认运行时存在。后续安装、锁定依赖和实际构建结果分别记录在实施计划和开发验证中。

## 3. 用户流程与界面

### 3.1 上传与理解

首页突出文件入口和“收到文件，先交给文启”。单次处理一份文件；背景输入是可选自由文本，不要求填个人档案。提供明确标注的合成通知和合成人设用于体验，样例只有输入，没有预填分析答案。

文件先在本地后端解析，显示文件名、解析范围及可定位的原文片段。首批实现 UTF-8 TXT/Markdown；同一 MVP 的后续解析任务增加有文本层 PDF 和 DOCX 正文/表格。格式只有在相应测试通过后才出现在“已支持”列表。图片、扫描件 OCR、加密文件、手写内容、PDF 复杂阅读顺序及 DOCX 图片/批注/修订不是本轮能力；检测到缺页或不可提取内容时显示限制，不声称已经完整读取。

初版设定文件上限 10 MiB、提取文本上限 40,000 字符、PDF 上限 50 页。超限直接说明并请用户缩小范围，不静默截断。DOCX 同时检查解压后的大小，避免仅依赖压缩包体积。空文件、乱码、类型与内容不符均有明确错误。

调用模型前展示实际配置的服务域名、模型名和将发送的解析文本、当前确认背景及本次指令范围，用户点击明确的“同意发送并解读”。无配置时显示未连接；失败时允许手动重试，不生成替代答案。

### 3.2 解读与补充

主区域显示与用户有关的内容、关联理由、要求/限制及未知；点击依据可展开本地原文位置和相关背景。页面用标签区分文件事实、已确认背景、系统推断和待核实事项，不把推断包装成文件结论。

模型仅在缺信息影响判断时提出带理由的问题。用户可回答，也可跳过；跳过后保留当前可支持的解读，未知不自动变成事实。用户输入须显式点击“确认并用于本次”才进入已确认背景，模型提炼的候选事实不能自行变为已确认。

提供“我已理解，到此结束”，不强迫生成任务。界面不沿用旧方案的六态材料核对作为通用流程；既有黄白品牌配色可供参考，但前端从产品需求新写，旧 Demo 不复制为产品代码。

### 3.3 沉淀与行动

本次背景及候选沉淀均可查看来源、编辑或放弃。单独点击“保留供下次使用”才写入本机 SQLite；回答、确认属实和生成解读本身都不授权长期保存。下一份文件使用保留背景时，先让用户选择仍适用的条目，再纳入外发确认。

保留背景可编辑、停用和确认删除。编辑产生新版本；停用或删除不再参与后续检索。本次会话中使用过该背景的结果立即标记需重新解读，生成与导出旧产物按钮禁用。已下载副本无法撤回，删除也不承诺取回此前发给模型服务的数据。

用户主动选择行动方向后，再请求模型生成 Markdown 草稿。第一版使用通用可编辑产物：用户可选择核实问题、准备清单或自填起草目标；以已确认背景和可核对文件内容为依据，未知留为待补项。草稿可编辑、本地下载；没有外部发送或自动提交能力。用户修改不能使旧版本来源自动变成有效，背景变化后需重新生成或重新核对。

## 4. 模块与数据边界

| 模块 | 职责 | 明确边界 |
|---|---|---|
| `src/web/` | 文件上传、证据浏览、解读与背景状态、保存选择、草稿编辑 | 不存放模型密钥，不把模型文字当 HTML 执行 |
| `src/server/parsers/` | 类型检查、文本提取、大小/页数限制、原文分段 | TXT/MD 定位到行；PDF 定位到页和提取段；DOCX 定位到正文段落或表格单元格，不伪造页码 |
| `src/server/model/` | 可配置模型服务适配、提示词、结构化输出解析 | 没有密钥/超时/拒绝/非法结果全部明确失败，测试替身只存在于测试 |
| `src/server/domain/` | 来源校验、背景确认、结果版本、保存授权与产物权限 | 权限和失效由代码控制，不依赖模型自己遵守 |
| `src/server/storage/` | SQLite 中显式保留的背景和版本 | 原始上传、解读与对话默认仅留会话内存，不落盘到资料库 |
| `tests/` | 领域、解析、API 与浏览器测试，明确标注的合成数据 | 单元替身测试与真实模型验收分别报告 |

开发前端使用 Vite 的本地代理访问 FastAPI；构建后可由后端提供前端静态文件，避免常规使用中跨域授权。拟采用 Pydantic 约束服务端输入输出、pytest 测试后端、前端测试工具验证交互；准确依赖版本与命令由实际实现记录，当前不提供不存在的启动命令。

核心对象：

- `Document`：唯一 ID、内容哈希、文件名、类型、解析警告、带位置的片段。
- `ContextFact`：ID、文本、来源、是否用户确认、版本、是否启用；保存状态单独管理。
- `Reading`：文件版本、采用的背景版本、解读项、原文引用、背景引用、未知及可跳过的问题。
- `Artifact`：用户选定的目标、生成草稿与编辑文本、依赖版本、是否仍有效。
- `Session`：随机会话标识、当前文件/背景修订号、活动请求；不用共享的全局“当前文件”。

每个引用由模型返回片段 ID 和引用文字。后端检查 ID 存在、文字确实属于对应片段、背景 ID 及版本已确认有效；校验失败的结果不作为可信解读展示。校验只能证明引用可定位，不能证明语义判断必然正确，界面仍保留推断/未知与人工核对入口。

## 5. 模型、存储与错误处理

模型的基础地址、密钥与模型名从服务端环境或受控配置读取。接入时根据实际提供商文档实现一个适配器，不猜测模型名、不扫描或打印密钥。确认设计后，工程可以先完成模型未配置路径、测试替身与接口合同；真实集成需已配置可用服务，且仅用合成输入验收。

文件及模型输出作为不可信数据处理，不执行文件中的“忽略指令”、命令或链接。模型没有工具执行权限；不允许从模型回复直接写数据库、发消息或提交。HTTP 接口限制请求大小，校验会话与来源，只绑定本机并拒绝非预期 Origin/Host。生产构建对静态资源设限，不能暴露仓库、环境文件或运行数据目录。

临时解析文件读完即清理；会话结束、重置或闲置 60 分钟后丢弃内存里的文件和对话。原始内容不写应用日志，日志只记录脱敏错误码和请求状态。SQLite 放在已忽略的 `var/` 内，用户确认保留后才写入；这是本机持久化，不宣称加密存储或云端完全不可见。

模型调用设置 60 秒超时，不自动重试以避免重复费用。用户取消后终止可终止的网络请求，并使本次响应失效；明确取消不保证提供商停止已开始的计算或计费。换文件、修改背景、重置和新请求都会改变修订号，迟到响应不得覆盖最新页面或保存数据。

当模型失败、来源校验失败或修订号过期时，保留用户本地输入和编辑内容；显示可理解的原因与下一步。点击重试会发起新请求，不用上次答案假装成功。

## 6. 实施顺序与验收

确认本设计后编写详细实施计划，按以下顺序推进；每个产品行为均先写失败测试并确认失败原因，再实现、回归，不直接把以下目标标记完成。

1. 建立新产品目录、配置边界和合成样例；先测试无模型配置时的真实错误行为。
2. 以 TXT/Markdown 贯通解析、稳定引用与来源校验，再加文本 PDF/DOCX 的解析边界测试。
3. 接入真实模型适配与解读结构，测试错误输出、拒绝、超时、取消及迟到响应。
4. 完成前端上传、解读、原文核对、按需补充与结束路径。
5. 实现本次确认/长期保留分离、背景编辑停用删除及版本失效。
6. 完成主动选择行动、草稿编辑与 Markdown 导出，处理旧结果失效。
7. 实际走浏览器流程；有可用模型时用合成输入做真实集成；最后更新经过实测的运行说明和状态记录。

| 验收场景 | 必须观察到的行为 |
|---|---|
| 零背景上传 | 不先要求建档；有依据内容可读，未知清晰；没有固定首问 |
| 同一文件、不同确认背景 | 解读实际使用所选背景并可回溯，变化来自模型调用而非预填答案 |
| 引用与不可信输出 | 引用定位可核对；不存在引用/未确认背景不能蒙混通过；HTML/脚本按文本处理 |
| 跳过、不保存、不行动 | 都能完成本次理解；无授权不写持久化；结束不触发起草 |
| 第二份文件与保留背景 | 用户主动选择复用仍适用内容，外发范围准确可见 |
| 更正、停用、删除 | 后续不使用旧版本，相关结果失效；本机删除与外部副本限制明确 |
| 用户选择后的产物 | 只在用户选择后生成，可编辑并导出实际编辑内容，引用和未知随稿附带 |
| 失败与取消 | 空文件/超限/不支持格式/模型未配置/调用失败如实提示；取消和迟到响应不污染状态 |
| 数据边界 | 密钥不进浏览器；未同意不外发；原文件不进 Git；不同会话不会互用文件 |

浏览器验收覆盖上传、错误提示、展开引用、跳过问题、确认但不保存、保留与删除、主动生成、编辑导出、重置和取消。真实 LLM 不可用时只能报告相关工程测试和失败路径通过，不宣称个性化理解能力已经验收。
