# 可行动事务 Agent · 后端 MVP 设计规格

导航：[[docs/可行动事务Agent-00-总览|文档总览]] · [[docs/01-产品方案/可行动事务Agent-参赛主线方案|参赛主线方案]] · [[docs/03-参赛与路演/可行动事务Agent-核心路演稿|核心路演稿]]

> 本规格承接已确认的个人端后端设计：以文件为入口，先解释文件对当下用户的意义，再由用户决定是否保留沉淀或生成可编辑产物。团队协作、企业部署、自动提交和外部发送不属于本版范围。
>
> 本文记录的是设计与验收目标。模型未配置、调用失败或未完成浏览器验收时，必须如实报告，不能把测试替身、预置回答或静态 Demo 当作真实模型能力。

## 1. 目标与非目标

### 1.1 目标

- 提供本机可运行的后端 HTTP API，接收 UTF-8 TXT/Markdown 文本文件。
- 解析文件并保留可定位的行号、原文片段和文件元数据。
- 通过真实 LLM 调用形成个性化解读，区分文件原文、用户已提供的背景、系统推断和未知事项。
- 支持用户补充或跳过影响判断的信息；补充不等于长期保存授权。
- 将拟沉淀内容单独展示，只有用户明确选择后才写入本地记忆。
- 仅在用户主动选择继续行动后生成可编辑产物，并标明模型初稿与待确认事项。
- 提供明确的未配置、超时、解析失败、引用无效和模型返回无效状态。

### 1.2 非目标

- 不实现团队协作、企业权限、审批、组织集成或自动对外提交。
- 不支持任意 PDF、扫描件、OCR 或远程文件抓取；首版只公布 TXT/Markdown。
- 不承诺零幻觉、资格通过、规则完全拦截或自动更新已下载的外部副本。
- 不把旧 `docs/05-交互Demo/` 规则模拟复制为产品实现。

## 2. 架构

```text
HTTP API
  ├─ 文件与会话模块：接收、校验、行号解析、会话状态
  ├─ 模型适配器：读取环境配置、构造请求、调用真实 LLM、超时
  ├─ 结果校验器：校验结构、引用原文、背景来源和未知标记
  ├─ 沉淀模块：暂存拟保留内容，显式确认后写入/删除本地记忆
  └─ 产物模块：用户选择继续后生成 Markdown/JSON 草稿
```

技术选择为 Node.js 内置 HTTP 模块，使用 `node:test` 做单元与集成测试；首版不引入第三方运行时依赖。运行数据写入仓库已忽略的 `var/`，密钥只读取 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 环境变量，不写入代码、日志或测试报告。

## 3. 数据与状态

- `session`：会话 id、文件 id、创建时间、当前解读状态。
- `document`：文件名、媒体类型、原始文本、行数组、大小和 sha256；文件内容不进入 Git。
- `interpretation`：模型版本/调用时间、发现项、引用、背景引用、推断、未知、可选问题和状态。
- `memoryCandidate`：本次形成的候选沉淀，包含来源、用户编辑内容和 `pending/retained/discarded` 状态。
- `artifact`：产物类型、模型初稿、使用的已确认信息、待确认项和用户编辑版本。

状态机为 `uploaded -> interpreting -> interpreted | failed`；只有 `interpreted` 才能进入沉淀确认或产物生成。用户可以处于 `interpreted` 后选择 `understood_only`，不生成产物。

## 4. API 约定

- `GET /api/status`：返回服务版本、支持格式、模型是否已配置；不返回密钥。
- `POST /api/documents`：接收 `{filename, mediaType, text}`，校验大小、编码和格式，返回 `documentId`、行数和引用信息。
- `POST /api/interpretations`：接收 `documentId`、可选 `background[]` 和 `previousAnswers[]`，调用真实模型并返回结构化解读。
- `POST /api/interpretations/:id/answers`：记录本次补充或跳过；不自动写入长期记忆。
- `POST /api/memories`：只接受已展示的候选内容和用户明确的 `retain: true`。
- `DELETE /api/memories/:id`：删除本地保留项，不声称删除模型服务侧日志或外部副本。
- `POST /api/artifacts`：仅允许 `interpretationId` 状态为 `interpreted` 且用户已选择继续时调用。
- `GET /api/artifacts/:id/export?format=markdown|json`：返回可下载草稿，包含来源和“待本人确认”标记。

请求体、响应体和错误码在实现计划中固定；所有未知字段不静默采用。

## 5. 模型输出与校验

模型必须返回 JSON，至少包含：

```json
{
  "findings": [
    {
      "claim": "与用户有关的判断",
      "relation": "关联理由",
      "documentEvidence": {"quote": "文件原文", "lineStart": 1, "lineEnd": 1},
      "backgroundEvidence": [{"id": "bg-1", "quote": "用户确认的背景"}],
      "kind": "document|background|inference|unknown",
      "uncertainty": "不能确定的内容或空字符串",
      "question": "仅在缺失信息影响判断时提供的可选问题"
    }
  ],
  "proposedMemory": {"content": "拟沉淀内容", "source": "来源说明"},
  "unknowns": ["待确认事项"]
}
```

确定性代码重新计算行号并核对 `quote` 是否确实来自该文件；背景引用必须来自本次请求或已明确保留的记忆。无法定位、结构错误、缺少未知标记或模型返回非 JSON 时，接口返回失败，不静默降级为预置回答。

## 6. 错误与隐私

- 400：格式、编码、字段或状态非法。
- 413：文件超过公布上限。
- 503：模型未配置。
- 502：模型返回无效结构或引用无法核验。
- 504：模型超时或网络失败。
- 服务日志只记录请求 id、状态码、耗时和错误类别，不记录文件正文、背景、密钥或完整模型响应。
- 上传内容只写入本地 `var/`；删除 API 只删除本仓库数据，不宣称云端数据已删除。
- 模型外发范围、服务地址和失败状态必须通过 `/api/status` 与客户端提示可见。

## 7. 验收与测试

### 7.1 单元测试

- TXT/Markdown 正常解析、空文件、超限、非法媒体类型、行号和引用原文。
- 模型输出结构、未知标记、引用核验和背景引用核验。
- 补充回答不自动保存；候选内容的 `retain` 才能写入；删除后不可再读取。
- 未选择继续时不得生成产物；产物草稿包含来源和待确认标记。
- 模型未配置、超时、网络失败、非 JSON、坏引用均产生明确错误。

### 7.2 集成测试

使用标记为测试替身的假模型适配器覆盖 API 状态机和错误路径。假模型只用于隔离测试，不作为产品能力或真实模型效果证明。

### 7.3 真实验收

在配置真实 `LLM_*` 环境变量后，使用脱敏合成文件执行一次真实调用，核对原文引用、未知事项和失败提示；记录实际模型、日期、状态和未验证范围。未配置或调用失败时，报告为未完成，不写成通过。

### 7.4 浏览器验收

若后续接入网页，必须实际走通上传、失败提示、原文引用、补充/跳过、不保存、只理解结束、继续生成、编辑和导出；本规格本身不构成浏览器验收证据。

## 8. 实施边界

实现阶段先写失败测试，再写最小实现，最后重构并回归。启动和测试命令只有在实测后才写入 `README.md`。未经用户明确授权不 commit、push、merge、部署或发送真实材料。
