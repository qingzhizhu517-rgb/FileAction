# Demo 一：已有记忆，上传新通知后复核与复用

导航：[[可行动事务Agent-00-总览|文档总览]] · [[05-交互Demo/可行动事务Agent-交互Demo使用说明|启动与使用说明]] · [[90-历史归档/旧方案-2026-09-30/03-参赛与路演/可行动事务Agent-Demo二-零记忆首次使用演示|Demo 二：零记忆]]

**演示目标：已有资料可以少传一次，但每次新用途仍需重审。** 观众要看见上传前后变化、旧资料的适用限制，以及纠正记忆后旧清单立即失效。

[打开 Demo 一网页](../../../05-交互Demo/demo-with-memory.html)。请先按使用说明启动本机服务；不要直接双击HTML文件。合成日期固定为2026-09-30，合成通知与人物均非真实制度或个人记录。

## 1. 演示素材与起点

同一位合成学生此前参加过“星桥学生项目实践计划”第一期。本次收到第二期通知，要准备自己的报名材料。N01是合成历史通知，N02是本次通知；本原型只处理提供的TXT演示格式。

| 素材 | 进入方式 | 第二期通知下的预期 |
|---|---|---|
| P01 在读身份资料 | 演示准备阶段自愿保存，现场重新读取 | 可引用候选；历史确认不等于本次已核对 |
| P02 项目经历 | 同上 | 可引用候选；稍后更正项目角色，演示版本与失效 |
| P03 第一期签字名单 | 同上 | 需更新/确认，不能用于第二期名单 |
| P04 第一期已使用的成果证明 | 同上 | 不可用于本次，通知禁止重复使用与既有使用事实均有出处 |
| P05 第二期新签字名单 | 现场上传新文件 | 新名单成为候选，旧名单的限制仍保留 |
| N02 第二期通知 | 现场上传 | 提取六项要求、分支、期限、渠道和未提供的附件A |

最多选定5份个人资料。老师确认书未在这5份中；附件A故意不提供，以展示检查边界。不要把“在已选资料中未找到”说成“用户从未拥有”。

**排练前准备：**打开侧栏“演示工具”→“清空本演示数据”，再点侧栏“载入 4 份演示记忆”。这一步会将4份合成资料写入本机记忆；随后点顶部“新事务”或刷新，真实重读。向观众说明这是提前建立的合成资料，不是自动积累或真实用户留存。TXT可从“演示工具”下载，也可从 `05-交互Demo/samples/` 选取。

## 2. 三分钟主线脚本

以下是排练分配，不是解析性能承诺。未能在指定时间完成时，正常等待或缩短讲解，不切换成未标注的固定结果。

| 时间 | 演示动作 | 观众应看到的结果 | 讲解要点 |
|---|---|---|---|
| 0–20秒 | 展示侧栏“4份已保留资料” | 新事务已重读4份来源，没有沿用上次的审核和选用 | “上次主动留下的资料还在，这次按新通知重新判断。” |
| 20–45秒 | **加入通知**：点“选择通知文件”上传N02；选适用身份，核对后点“一次确认以上三项” | 六项要求、期限、渠道与禁用条件集中出现；附件A缺口保留 | “先看这次规则，再决定旧资料还能不能用。” |
| 45–85秒 | 点“下一步：选择资料”，确认4份资料本次使用；点“生成准备清单”，在R4点“查看依据” | R1/R2候选、R3需更新、R4禁用、R5本次未找到、R6无法判断；R4面板对照通知和成果原文 | “文件在，不代表这次能用。往期成果已使用，不能靠勾选放行。” |
| 85–105秒 | 关闭依据面板，点“调整资料”→“选择资料文件”，上传P05；再点“生成准备清单” | 本次5份；R3变为新名单候选，“查看依据”仍能看到旧名单限制 | “只补一份新名单，其余资料接着用。” |
| 105–125秒 | 在R1、R2、R3分别点“查看依据”→“我已核对本次依据”→“选用于准备清单”；关闭面板后点“导出准备清单” | 已核对的候选进入已选区；待办、未知和排除项仍随Markdown导出 | “先看证据，再审核，再选用；带走的是准备草稿。” |
| 125–155秒 | 点“调整资料”，在P02点“查看详情”→“更正为项目成员”；回到“准备清单”观察旧结果过时，再点“重新生成准备清单” | P02版本增加，旧导出不可用；重新生成后候选需再次核对 | “角色记错了，可以纠正；旧结论立即失效。” |
| 155–180秒 | 点“为下次保留”，对要留的资料依次勾选“已核对这份资料”“保留到本机记忆”，点“保留所选资料”→“开始新事务” | 实际重读已保存来源；本次审核、选用和通知不会继承 | “保留来源，下次重新判断。是否留下，由我选择。” |

页面只走“加入通知 → 选择资料 → 准备清单”三步，来源和保存按需打开面板。排练可用通知的“使用样例”和资料页的“加入第二期新名单”；使用这些按钮时，应说“载入合成样例”，不能称为现场文件上传。“未检查”的完整展示见Demo二，不为凑齐六态另造资料。

## 3. 上传前后要讲清的效果

| 时点 | 可以得到什么 | 仍然不知道什么 |
|---|---|---|
| 只有历史记忆 | 查看本人曾选择保存的来源、版本和用途 | 尚无本次规则，不能判断第二期适用性 |
| N02上传并确认后 | 本次要求清单，与所选记忆逐项配对 | 附件A内容、未选文件是否存在、整体资格是否满足 |
| P05上传后 | 第二期签字名单有新的可引用候选 | 不会自动补出老师确认书，也不会解除P04禁用 |
| P02更正后 | 新版本来源与重新生成的准备结果 | 已下载的旧文件不会被远程改写，需重新导出 |

## 4. 六个关键问题如何体现

| 可行性分析中的问题 | 本Demo中的具体处理与证据 |
|---|---|
| 首次没有记忆 | 本页也可不载入预置记忆而先上传通知；完整独立演示见Demo二，保存不是开始或导出的门槛 |
| 找文件与确认成本 | 仅选4份相关记忆、补传1份名单；“演示工具 → 运行与成本”登记找文件与辅助时间，计时包含确认和纠正 |
| 文件存在但不适用 | P03本期不符、P04命中明确禁用；“查看依据”对照双边来源，禁用条目不能选用 |
| 记忆过期或纠正失效 | 真实保存后重读；P02更正使旧结果、旧选用和导出失效；重查后重新审核 |
| 支持与调用失控 | 在“演示工具”查看模拟分析、缓存、重试和实际耗时；故障演练最多一次自动重试，真实模型调用为0 |
| 协作与企业扩张 | 全程只处理一位学生自己的资料；成员名单是输入内容，没有共享、代他人确认、自动分派或审批 |

## 5. 选做的故障与边界演练

1. **模拟技术失败。** 在“演示工具 → 故障演练”选择“持续失败 · 重试一次后停止”，返回演示后点“重新检查”。观察一次重试后停止，再切回“关闭 · 正常检查”重查。文件读取有困难时可展开“读取有困难？粘贴 TXT 文本”。这是模拟，不是真实模型可靠性统计。
2. **迟到结果。** 开始检查后立刻更正、停用或删除有关资料，旧请求返回时不得回填旧结果；需按新版本重查。没有发生该操作时，不宣称现场已经验证了这一项。
3. **范围不完整。** 上传不支持的文件，保留读取失败/待处理标记；未读资料存在时，不能把空配对显示为“本次未找到”。移除失败项仅表示主动缩小检查范围。
4. **版本缓存。** 对未变化的输入点“重新检查”，到“演示工具”观察“版本缓存命中”；缓存不产生真实模型调用，也不继承未做的本次审核。

## 6. 演示通过的判断

- 新通知和新名单确实来自本次文件读取，内容能定位到原文行与版本。
- 4份演示记忆来自明确保存后的浏览器读取；本页不读取Demo二的存储空间。
- 禁用资料不能选用；审核与选用分开，附件A缺口持续可见。
- 更正后旧快照不能导出；新结果必须重新核对，停用/删除内容不能被迟到响应恢复。
- 实际打开下载的Markdown，能看到所选项、未检查/待办、排除说明、来源、版本和覆盖边界。

本Demo证明的是受控交互与浏览器内状态行为。真实模型抽取、任意PDF、正式数据库/服务端一致性、真人节时、留存、付费和企业需求均未由本次演示证明。此原型形成于2026年9月30日，参赛时须如实列为赛前既有资产。
