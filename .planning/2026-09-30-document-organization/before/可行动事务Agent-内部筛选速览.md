# 可行动事务 Agent · 内部筛选速览

> **本轮设计主线：竞赛/项目报名材料复核与复用助手。** 原始愿景仍是让已整理的个人资料在下一件事情中继续有用；先用一件可检查的任务实现低摩擦输入、可控记忆、跨文件关联与个人意向。
> 2026-09-27完成限定设计审定，依据仍为2026-09-26读取的资料；没有新增产品实测或用户实验。范围与六状态见 [[可行动事务Agent-问题处理与方案审定]]，产品方案见 [[可行动事务Agent-Idea完善方案]]，行为契约见 [[可行动事务Agent-产品定义]]，证据见 [[可行动事务Agent-市场调研与验证]]。

## 一、一句话与第一批任务

**先把通知变成要求清单，再把你选的资料与本次要求对上，说明哪些可引用、哪些要更新，并由你选择留给下次复用。**

优先观察近期正在准备竞赛/项目报名的学生或项目负责人。用户已确认可触达大学生和社团，这不等于需求、频率或付款证据；社团先观察负责人的个人工作，不在本届做多人协作。

通知即可启动；没有旧资料也能得到要求清单。按需选资料和跨事务保存都可跳过，不先建完整档案。首次仍有找文件和选版本成本，先争取减少人工对照与重复核对，不承诺自动找齐散落资料。

## 二、为什么选择这一范围

| 路线 | 已有证据与反证 | 当前处置 |
|---|---|---|
| 竞赛/项目材料复核 | 正式通知有多渠道、项目书/PPT/证明和历史项目背景；现有AI、表格和学校系统可能已足够 | 做限定原型，与最佳已有方法同题比较 |
| 通用个人记忆 | Mem、remio、通用AI等已有记忆、上下文与行动；迁移成本高 | 保留愿景，不建全量知识平台 |
| 社团材料与交接 | 正式流程有负责人及申请—总结—报销材料链；已有表单与审批系统 | 独立观察，不把可触达当作采购证据 |
| 第二课堂学时 | 三条件便于演示，但PU学校指南已有分类得分、最低要求与完成进度 | 留档备选，不作为新主线契约或中途第二套产品 |

北理工通知对已用于获国奖的同一成果及支撑材料限制重复申报，说明“记忆中已有”并不等于“本次可用”。所有公开流程仅证明流程存在。若合理使用的通用AI加模板已经同样方便，方法可转为模板/插件，独立应用不必坚持。

## 三、拟实现的完整使用链

```text
一份通知先进入
  → 确认当前事务和适用分支，列出已读来源、未读附件及覆盖范围
  → 生成要求清单；未提供个人资料时显示“未检查”
  → 用户按需选择最多5份资料，也可跳过
  → 按本次要求复核资料版本，显示六状态、原因和原文依据
  → 导出保留未核实/部分覆盖标记的Markdown工作清单
  → 用户自愿选择保存可复用事实、资料及必要来源
  → 刷新或新建事务，读取已保存内容，再核对第二份通知
  → 展示需更新或不可用于本次的材料
  → 纠正事实/停用来源，使关联旧结果过时，再生成待复核结果
```

这是设计链，尚无运行记录。个人意向、已确认事实和系统建议分开：读过通知不等于要报名，要报名不等于已提交，历史确认也不自动适用于新事项。

演示要让人看到要求出处、资料出处、第二次真正复用了什么，以及一次纠正如何使旧结果过时。同一长对话追加通知不能证明持久记忆；只有第一份清单只能称单次材料整理。

## 四、六状态与记忆边界

判断单位是“某份资料的某版本，对本次某要求”，不是对整个人的资格裁决。

| 材料状态 | 判断与处理 |
|---|---|
| 未检查 | 未提供资料或必要检查未完成，不判个人缺材料 |
| 可引用候选 | 来源可定位，已核对部分未发现适用冲突，保留检查范围 |
| 需更新/确认 | 有明确可补的事实、版本或形式问题，列出具体下一步 |
| 本次未找到 | 规则明确、范围非空且所需检查完成，范围内未发现候选 |
| 不可用于本次 | 已确认命中适用的禁用条件，排除本次选用 |
| 无法判断 | 规则、分支、来源冲突或语义不明，保留来源并列待核实问题 |

同项保留所有原因；有候选不代表已检查全部输入。选用不等于审核事实，普通选用按钮不能解除禁用；只有有效依据变化并重新审核后才能重判。缺本次签字可列需更新，禁止条款是否适用不明则是无法判断。

当前事务工作副本与跨事务留存分开。用户选择保存后才形成持久记忆，原件不改；修改/停用使直接关联结果过时，迟到旧响应不能覆盖新版。清除要处理本机副本、派生事实、缓存与索引；已导出副本不能远程撤回。以上均需实现后验收，本机存储也不等于云模型不接触处理片段。

清单可带未检查、待核实及部分覆盖标记导出。禁用材料只在排除说明中出现；材料齐全、资格通过、正式提交都不能由导出动作推断。

## 五、本届冻结范围与5分钟展示

| 项目 | 设计范围 |
|---|---|
| 用户与样本 | 单用户，2份相关演示通知；每次最多5份选定资料，允许零资料 |
| 输入与界面 | 文本/PDF；通知要求、资料与依据、准备结果三个工作面 |
| 必做 | 分支与覆盖、来源、六状态、Markdown清单、选择保存、新事务读取、纠正后过时 |
| 退出本届 | 文件打包、后台提醒、OCR泛化、全量采集、多用户权限、企业部署、学校接口、自动提交和完整资格判定 |
| 资料性质 | 合成或获授权脱敏资料；历史通知只作历史样本，预审输入与回放明示 |
| 官方窗口 | 2026年10月1日14:30—10月4日09:30，67小时；1–5人；正式5分钟展示＋3分钟问答 |

以下为团队内部时间轴，不是解析速度承诺，也不是赛事规定的分段要求：

| 时间 | 展示内容 |
|---|---|
| 0–35秒 | 目标用户和重复准备问题 |
| 35–85秒 | 通知先入与要求清单 |
| 85–145秒 | 选择资料、逐项复核与来源 |
| 145–205秒 | 保存后新事务读取，一项禁用或需更新 |
| 205–255秒 | 纠正、旧结果过时与实际清单 |
| 255–300秒 | AI分工、本届新增及边界 |

67小时包含休息、活动、视频与封包。内部关口为10月2日18:00单次流程、3日12:00持久读取与过时、3日18:00边界检查及冻结；4日09:00前检查上传，09:30前按最终入口完成封包、备用录屏和回执留存。关口及降级详见 [[可行动事务Agent-问题处理与方案审定]]。

核心未通应减声明、缩范围；固定答案和人工补齐不能冒充自动能力。赛前研究、通用准备与复用组件须按规则说明，不能冒充现场新增；首晚60秒团队介绍与最终录屏分开。赛事依据与待确认条款见 [[可行动事务Agent-西客松参赛对齐]]。

## 六、验证顺序与退出条件

1. **运行先验收。** 零资料路径、分支覆盖、六状态、禁用、来源、真实导出、刷新/新事务读取、过时和迟到响应须有记录。设计反例不能替代运行通过。
2. **首轮要有净价值。** 与本人最佳办法及合理使用的通用AI加模板公平比较，输入和确认机会相当；难度接近并交替顺序。寻找、上传、确认、纠正、导出全计时，报告首轮、第二轮及合计。所有开始的任务保留在各组完成/失败分母，人工代办单列，不能删掉困难样本。原4/6和25%只作可讨论的早期信号。
3. **记忆要有增量。** 与只保存原文件相比，看实际减少了多少重复劳动。活跃申请者、低频者和负责人分组；未知/失联不能当无机会，提醒后使用与自然返回分开。同时报告第二次机会率、有机会者的复用和全体首用者的再次使用；历史重放不算留存。
4. **成本与付款分开证明。** 记录模型、解析、重试、存储、审核、支持和模板维护，创始人工时不按零计。先试限定任务的按次/任务包，口头愿付与支付分开；有重复任务和购买再考虑学期方案，不预设订阅。

现有AI已同样方便，转模板/插件；首轮有用但复用少，保留一次性工具；人工支持吞掉收益，收缩范围或明确服务模式。个人侧证据弱不自动证明企业版更有价值。完整对照与成本口径见 [[可行动事务Agent-可行性分析]]。

当前只通过限定设计，原型运行、用户价值和商业仍未验收。下一步应落实一份可读通知及可解释样本，在赛事边界内完成原型，再按顺序验收。
