# 可行动事务 Agent · 路演答辩应答卡

导航：[[可行动事务Agent-00-总览|文档总览]] · 分类：参赛与路演

> **使用前提**：本稿依据 [[01-产品方案/可行动事务Agent-问题处理与方案审定|可行动事务Agent-问题处理与方案审定]]，用于限定原型的沟通与排练。当前仅设计审定通过，原型运行、用户价值、留存与商业均未验收；引号内按现阶段计划口径撰写，赛后须据真实成果更新。
> **主线**：通知先入 → 确认当前事务与适用分支 → 按需选择资料 → 逐项复核并导出 → 自愿保存可复用内容 → 新事务读取与重新检查。首次零旧资料也能开始，保存不是获取清单的前提。
> 产品说明见 [[01-产品方案/可行动事务Agent-Idea完善方案|可行动事务Agent-Idea完善方案]]、[[01-产品方案/可行动事务Agent-产品定义|可行动事务Agent-产品定义]]，证据见 [[02-调研与可行性/可行动事务Agent-市场调研与验证|可行动事务Agent-市场调研与验证]]，赛事见 [[03-参赛与路演/可行动事务Agent-西客松参赛对齐|可行动事务Agent-西客松参赛对齐]]。外部事实沿用2026-09-26保存的来源，本轮未重新联网核验。

## 一、开场：从一份通知开始准备

**开场三句：**

1. 「一份报名通知来了，先要弄清自己适用哪条要求、该准备什么，再决定找哪些材料。」
2. 「我们计划先给出有出处的要求清单；用户按需选择资料，逐项看哪些可引用、哪些要更新，哪些还没检查。」
3. 「这次确认过的内容，可以自愿保存。下一份通知来时重新核对版本和使用条件，让已有资料继续有用。」

把“白盒记忆”讲成看得见、能确认和改正的个人资料；把“意向”讲成用户这次想办什么。不要用“所有平台都没记忆、不会行动”证明差异，也不把公开流程讲成已经做过的用户访谈。

### 首晚60秒介绍脚本草稿

10月1日晚介绍团队、问题与计划即可，不要求已有完整成品。以下按届时真实情况录制，队名和分工由成员填写：

- **0–10秒**：「我们是【队名】，成员负责【实际分工】。我们想做一个竞赛和项目报名材料准备助手。」
- **10–25秒**：「从一份通知开始，先弄清本次要求，再选择相关资料。没有旧资料，也能先拿到要求清单。」
- **25–50秒**：「我们计划让AI关联要求与资料，给出有出处、能复核的准备结果。确认过的内容可自愿保存；第二份通知来时重新检查，指出需要更新或本次不能用的材料。」
- **50–60秒**：「现场先跑通准备、保存、再次使用和纠错，随后用真实任务检验它有没有减少重复劳动。」

这只是脚本草稿，时长须实测。首晚介绍不等于最终作品包；不能为赶首晚视频把计划说成已实现。

### 正式5分钟排练安排

| 时间 | 计划展示内容 |
|---|---|
| 0–35秒 | 问题与本次事务 |
| 35–85秒 | 通知先入、适用分支和要求清单 |
| 85–145秒 | 按需选择资料、复核与来源 |
| 145–205秒 | 保存后在新事务读取，展示一项禁用或需更新情况 |
| 205–255秒 | 纠正或停用、旧结果过时，以及实际清单 |
| 255–300秒 | AI与代码分工、现场新增成果和能力边界 |

以上为团队排练建议，另有3分钟问答；分秒不代表解析性能承诺。预审输入、合成资料、实时处理、人工审核及缓存/录屏分别标明。若跨事务持久读取未完成，只能演示并声明单次材料整理。

## 二、问题、记忆与AI价值

### Q1 · 你们具体解决什么问题？

「先帮助一位学生或项目负责人看懂竞赛、项目报名通知，再对照本次选定资料，知道哪些可引用、哪些要更新、哪些尚待核实。先做好一次材料准备，再检验保存后的第二次使用能否减少重复劳动。」

**依据边界：**官方通知确认存在多材料、多渠道、版本和身份分支；负担多大、是否愿意换工具，仍需真实任务验证。零资料只生成要求与未检查项，不推断用户缺材料。

### Q2 · 记忆在哪里？不就是上传文件问答吗？

「我们计划让用户选择保存已确认事实及必要来源，保留用途和确认时间。刷新或开启新事务后仍能读取，再核对新要求。保存可以跳过；旧确认也不能直接算作新事务已经确认。」

**展示重点：**演示一次重启/新事务读取、一次纠正或来源停用，以及一次旧结果过时。同一长对话里追加通知不能证明持久记忆；还要记录第二次少输入了什么、增加了多少复核成本。

### Q3 · “意向”是什么意思，系统会自行替我决定报名吗？

「意向是用户明确说这次想办哪件事，比如‘我想申这个项目’。先确认当前事务和本人适用分支，再对照资料。读过通知不等于决定报名，计划参加也不等于已经参加；意向与个人事实分开记录。」

**边界：**本届从用户提供通知开始，不持续采集全量聊天或网站。导出保留期限原文、来源版本及“暂定”等性质；后台提醒和自动提交退出本届范围。

### Q4 · 为什么用AI，文件夹和表格不能做吗？

「AI适合从不同写法的通知中提出要求与资料匹配候选；代码检查来源、引用范围和版本，用户审核解释。我们计划把这些步骤接到可导出的清单，比较包含找文件、整理、确认与纠错成本的完整任务。」

**边界：**模型给出引用不保证理解正确；资料中的文字不能改变系统权限，也不能指挥外部提交。

### Q5 · Mem、NotebookLM、ima或通用AI也有记忆、引用和行动吧？

「是，单独有记忆或引用不足以证明优势。我们聚焦一类报名材料准备，把要求、资料版本、复核与产物接成流程，再和用户最佳现有方法、合理使用的通用AI加模板比较两次完整任务。如果没有优势，就转为模板或插件，或停止独立应用投入。」

**边界：**使用市场调研中的有来源描述，不声称其他平台没有记忆、不能行动或无法计算。

## 三、复用边界与实际产物

### Q6 · 找到旧材料，就能直接复用吗？

「不能。旧项目介绍可能提供背景，成员名单需要重新确认，旧申请表要核对版本和本次签字。我们按‘某份资料的某个版本，对某项本次要求’判断，保留原因；资料不合用也不等于申请人整体没有资格。」

**证据例子：**北理工2025年一份研究生国奖通知限制已获国奖的同一成果重复申报。已确认命中该限制才判本次不可用；使用史未知是待确认事实，规则是否适用不明则无法判断。不能推广为所有奖项或赛事的统一规则，详见市场调研来源。

### Q7 · 材料准备的几种状态怎么解释？

「六种状态分别说明检查进度和本次使用条件。每项同时显示原因、依据和检查范围，用户能知道下一步该补什么检查。」

| 状态 | 答辩解释 |
|---|---|
| 未检查 | 尚未提供资料，或所需检查未完成 |
| 可引用候选 | 来源可定位，本次已核对范围未发现冲突，仍由用户决定是否选用 |
| 需更新/确认 | 有具体可补的事实、版本或形式问题，如使用史、成员、本次签字 |
| 本次未找到 | 规则明确、选定范围非空且所需检查完成，在该范围没有找到候选 |
| 不可用于本次 | 已确认适用禁用条件或排除事实命中这份资料 |
| 无法判断 | 规则解释、适用分支、来源冲突或关键语义不明 |

**边界：**未读附件和部分检查必须显露覆盖范围；找到一个候选不等于其他要求均已检查。抽取、审核与选用分开，普通“选用”不能解除禁用；需有效证据或规则变化并重新审核。

### Q8 · 最后给用户什么？会自动报名或生成完整材料吗？

「本届计划交付Markdown材料清单，也允许导出带未检查、待核实或部分覆盖的工作草稿。清单包含要求出处、对应资料、已审阅选用项和后续待办；文件打包不在本届范围。」

**边界：**需更新与无法判断项留在待办区，禁用材料只列排除说明，不能进入已选材料区。未审阅候选标为模型初稿；不编造经历、签字或审批。准备完成仅指声明范围内的材料准备阶段，不代表提交、审核或资格通过；一个渠道的回执不能证明另一渠道已提交。

### Q9 · AI匹配错了、记错了怎么办？

「每个候选要求和复用建议都应能回到原文。纠正事实或停用来源后，先把相关结果、审阅和选用标记置为过时，再生成待复核结果。旧请求晚返回，也不能覆盖新版本或重新激活已停用内容。」

**边界：**只承诺处理已记录的关联，关联不清时保守使当前草稿全部过时。旧结果不作普通导出，已下载文件不会自动改写；重新打开或导出时还要核对日期。以上须实现后运行检查，当前不报准确率或测试通过数。

## 四、范围、样本与可行性

### Q10 · 67小时现场准备做多大？

「冻结一个用户、一类竞赛或项目报名材料准备事务、两份演示通知，每次最多五份选定资料，支持文本和PDF。界面分为通知要求、资料与依据、准备结果三个工作面，跑通来源、六状态、清单导出、选择保存、新事务读取和纠错后过时。」

**执行重点：**文件打包、OCR泛化、任意格式、多用户权限、企业部署、学校接口、后台提醒、自动提交和复杂资格判断后置。10月2日18:00检查单次事务，3日12:00检查持久读取与过时，3日18:00冻结功能并排练；这是内部关口，未达成须收缩完成声明，不能用预填答案补成品。

### Q11 · 通知和个人资料从哪里来，哪些是真实的？

「计划选择两份可读、可解释的相关通知，搭配明确标注的合成资料；真实用户资料须获授权并适当脱敏。历史通知只作历史样本，不展示成当前报名机会；合成规则也不能套到真实赛事上。」

**演示要求：**具体样本尚待落实。附件未取得就显示未读；PDF失败后请求粘贴文本，不能称PDF解析成功。实时处理失败可展示错误、明确标注的人工审核输入或封包前录屏，但不能据此证明自动抽取已实现。

### Q12 · 为什么不再把第二课堂学时作为主卖点？

「学时方案留档备选。学校官方PU指南已写明分类得分、最低要求和完成进度；当前限定原型选择材料准备，检验‘资料为下一件事继续服务’是否有实际价值。本届不同时开发第二套产品。」

**备用案例口径：**学时规格的四态、字段和算法只属于该备用方案，不约束材料主线。若另行讨论原合成算例，创新创业增加10只关闭该类缺口，文艺体育仍差10，不说整体通过。

### Q13 · 团队版和企业版呢？

「仍是假设。先观察社团负责人个人如何处理连续事务，确认现有表单确有缺口后再研究协作；企业须另选岗位、流程、权限、付款人和集成方式。本届只做单用户。」

**边界：**已知能接触学生和社团，不等于已经验证团队产品或企业市场；本届不安排企业Demo。

### Q14 · 市场、频次和付费有证据吗？

「公开流程支持这个问题值得研究，但还没有真实用户任务对照和付费证据。接下来分别观察活跃申请者与低频用户，完整记录首次准备、第二次复用和人工帮助成本，再看是否值得继续做。」

**验证口径：**同时报告多少人实际遇到第二次事务，以及有机会的人是否再次使用；失联不能算无机会，自然返回与被提醒后返回分开。对照计入找文件、确认、纠正及维护，保留失败分母；“4/6独立完成、中位节时25%”仅是待讨论的早期信号，不能抵消关键错误或证明市场成立。

## 五、个人资料与现场贡献

### Q15 · 我可以知道系统记住了什么、删除它吗？

「设计上由用户选择保存已确认内容及必要来源，保留用途和确认时间，并能修改、停用或清除。本届在本机单用户工作目录运行，原件不改；没有选择保存的工作副本只留当前会话内存，刷新或退出可能丢失。」

**边界：**首版不承诺保存PDF原件，未获准保存的内容不能借快照或日志留存。清除覆盖应用控制的文本、派生事实、缓存和快照私密片段；已导出文件和云端已接收内容不能靠本地删除撤回。本机存储不等于云模型未见数据，发送片段与服务方须说明；真实试用前核对处理政策，这些机制仍需运行验证。

### Q16 · 你们现在做了什么，现场新增什么？

「目前完成公开调研、问题梳理和限定设计审定；尚无运行原型、用户价值或商业验收。现场计划按实际分工实现材料准备、可选保存、新事务读取和纠错；通用底座与本届新增贡献分别说明。」

**边界：**赛前完整核心功能、可直接演示成品或本主题视频成片不能冒充现场新增；既有底座须申报，不通过改名换皮包装成果。

## 六、提交与评审准备

- **开发时间**：10月1日14:30到10月4日09:30，共**67小时墙钟窗口**，包含休息、活动、录制和提交；12:00投票截止不延长开发。
- **队伍**：官方1–5人，每人只加入一队、每队一个主赛道作品，按实际能力分工。
- **首晚安排**：60秒团队介绍讲问题、计划与真实进度即可；首晚介绍不是最终作品包。23:00对应队伍登记及项目页资料安排，不擅自解释为全部视频环节截止。
- **正式评审**：**5分钟展示＋3分钟问答**，至少3名评委；按本篇时间轴排练，保留第二次读取、纠错与实际产物。
- **建议材料**：可运行应用或入口、必要源文件、运行说明、实际录屏，以及复用与新增说明。10月4日09:30前最后一次有效提交及回执为准，备用录屏也须此前提交；上传成功、审核通过和上线分别核实。
- **公开与评分**：不统一要求公开开源，必要材料受限供授权评委；专业85%与网络15%的方向及其适用仍待明确，专业奖排序口径冲突见赛事对齐篇，不自行推算胜率。

赛事事实与团队建议分别标注；最终入口、评分口径和成果协议等仍待主办方正式确认，报名或签约前核对最终规则。上台前核对：样本是否落实；零资料路径是否可用；保存能否跳过；两次事务是否都有实际行为；引用、禁用和过时处理是否有证据；清单是否保留未知与覆盖范围；所有完成声明是否对应实际成果。
