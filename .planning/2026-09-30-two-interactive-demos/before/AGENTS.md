# 文档协作规范

## 项目结构与文档职责

本仓库是西客松 XiHack 2026「可行动事务 Agent」的 Markdown/Obsidian 方案库，尚无应用源码、测试目录或独立资源目录。

- 从 `可行动事务Agent-00-总览.md` 查阅文档地图。
- 根目录仅保留总览和本规范；业务文档按职责放入下列目录，文件均以 `可行动事务Agent-` 开头。
- `01-产品方案/`：`Idea完善方案` 描述体验，`问题处理与方案审定` 维护处置与范围，`产品定义` 维护行为契约；另有定位决策和内部筛选速览。
- `02-调研与可行性/`：市场调研篇保存外部证据，可行性篇维护交付依赖与验证口径。团队、企业仍是假设。
- `03-参赛与路演/`：参赛对齐篇保存赛事事实，路演答辩篇维护与实际证据一致的展示草稿。
- `04-学时备选/`：学分规格、Demo状态表、UI规格属于学时备选，不自动约束材料复用主线。
- `90-历史归档/`：核查修订报告留存历史纠错，`原始草稿/` 留存原始愿景。两份草稿正文原样保留，引用的两张图片尚未提供。
- `.planning/` 保存来源、核查及整理前副本，既有历史快照不随现行文档改写；`.obsidian/` 为编辑器配置。

## 阅读与检查命令

用 Obsidian 打开目录或用 Markdown 编辑器阅读。当前没有构建、运行服务、测试或 lint 命令；技术栈建议不代表已有实现。

```sh
rg --files -g '*.md'                  # 列出文档
rg -n '文件打包|未检查|不可用于本次' -g '*.md' .  # 检查范围与状态
rg -n '\[\[' -g '*.md' .              # 检查双向链接
```

## 格式与命名

正文及协作回复使用中文。新业务文件采用 `可行动事务Agent-主题.md`，放入职责目录并同步总览；每篇一个一级标题，逐级组织章节。原始草稿以保全原文为先，不补写标题或重排段落。

库内用带目录的 Obsidian 链接 `[[目录/文档名|可读名称]]`，表格中的别名分隔符写成 `\|`。移动或重命名时同步现行引用、Markdown相对链接和编辑器保存的文件路径。正文中以代码标注的 `.planning/` 路径默认相对于库根目录；可点击的Markdown链接相对于所在文件。

保留 YAML 元数据，正文或导航变更更新 `updated`；该字段仅表示文档编辑，不刷新外部来源的实际读取日期。YAML/JSON缩进两个空格，代码块标明语言。当前未配置格式化工具。

## 验证要求

无测试框架或覆盖率门槛。修改后核对标题、表格、围栏、链接和示例；目录整理还需核对总览计数、文件保全与既有缺失附件。修改前将原文与路径清单保存到独立的 `.planning/日期-任务/`；原始草稿、旧审查记录和 `before/` 副本不批量改写。新增应用代码后再按实际工具补充运行说明。

材料主线统一六态：未检查、可引用候选、需更新/确认、本次未找到、不可用于本次、无法判断。空资料或检查未完不能判未找到；选用不等于审核，材料齐全不等于资格通过。保存可选，新事务重审，变更使旧结果过时。

学时备选保留自己的四态；复算128及假设138/22/0，已知0不等于缺证，部分覆盖不等于完整认定。来源、版本、事实与意向分开；桌面推演、运行测试和真人验证分别报告。

## 提交与 Pull Request

当前目录未初始化Git，没有可核验的提交惯例。启用后建议用动作式消息，例如 `docs: 统一材料复用状态`，每次聚焦一个主题。PR写明原因、涉及文档和验证结果；有相关issue时链接，界面或渲染变化附截图。

## 证据、赛事与数据

外部事实附来源及实际读取日期，设计修改不冒充重新核验。官方开发67小时、展示5分钟加问答3分钟；180秒仅为学时备选片段。赛前方案与既有组件按规则说明，不冒充本届新增。

个人资料不入库，示例脱敏；不把本机保存说成云模型不接触数据。避免提交密钥、`.DS_Store`、`.obsidian/workspace.json` 等本机状态。
