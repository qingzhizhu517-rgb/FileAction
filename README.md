# 文启 FileAction

**收到文件，先交给文启。**

文启是一个以文件为入口的个人行动助手，帮你理解一份文件对当下的你意味着什么，再把这份意义变成具体行动。我们首先关注反复阅读、筛选并联系自身背景的成本；有依据的个性化解读是第一交付，用户可以到此结束，选择继续后再形成可编辑产物。

这是西客松 XiHack 2026「文启 / FileAction（可行动事务 Agent）」的代码仓库。方案、研究与既有设计资产放在 `docs/`。当前主线是**个人端 MVP 的验证**：结合已确认背景、分清原文与推断、按需询问、让用户查看和决定是否保留沉淀。团队协作与企业级应用是未来探索。Document → 可行动事务 → Workflow 只在用户选择行动时继续展开。

## 本地开发与兼容MVP回归

目录已调整为 `front/` 与 `backend/`。正式个人版正在依照[技术开发设计](docs/01-产品方案/可行动事务Agent-正式个人版技术开发设计.md)和[实施计划](docs/01-产品方案/可行动事务Agent-正式个人版实施计划.md)开发。正式API与前端独立运行；旧MVP的SQLite和无账号会话仅用于兼容回归，不是正式多账号服务。

本机环境为 Windows PowerShell、Python 3.12、Node.js 22；Python虚拟环境仍在根目录 `.venv/`。以下回归命令已在目录迁移后执行：

```powershell
Push-Location backend
../.venv/Scripts/python -m pytest tests -q
Pop-Location
Push-Location front
npm.cmd test -- --run
npm.cmd run typecheck
npm.cmd run build
Pop-Location
.venv/Scripts/python front/e2e/run.py
```

迁移回归结果：后端50项、前端12项、浏览器16项通过，类型检查和构建通过；后端有1条既有Starlette/httpx弃用告警。浏览器测试采用合成资料与HTTP模型替身，不代表正式版或真实模型验收。正式版新增测试的命令、结果与未完成范围见[正式个人版开发验证](docs/01-产品方案/可行动事务Agent-正式个人版开发验证.md)。

用户已选择本机Docker Compose。2026年10月3日本机Docker已可用，隔离的PostgreSQL/pgvector与非持久Redis已用于合成数据集成测试；腾讯云COS和Embedding的真实服务尚未验收。正式存储不以SQLite替代。Embedding推荐[阿里云百炼](https://bailian.console.aliyun.com/) `text-embedding-v4`，模型与维度须显式配置；云存储、文件索引、查询Embedding和生成分别授权。生成模型已有本机配置，但本轮工程测试不读取或调用它。

正式版生成链路的独立合成验收（已实测退出0，需Docker、项目依赖与Playwright浏览器）：

```powershell
.venv/Scripts/python front/e2e/run_formal_generation.py
```

此命令创建并清理本次专属PG/Redis容器与API/Worker/前端进程，不读取真实 `.env`；生成模型为明确标注的本机HTTP替身。它验证工程流程，不代表真实云服务或根目录Compose验收。

密钥只填写根目录 `.env`，示例见 [.env.example](.env.example)。不将密钥放入前端、不复制到备份、不提交Git。旧8766/8767/8768调试服务可能仍在运行，保留根目录旧 `dist/` 以免中断；正式开发不接管它们。历史真实模型冒烟证据仍见[个人MVP开发验证](docs/01-产品方案/可行动事务Agent-个人MVP开发验证.md)，历史路径不改写。
