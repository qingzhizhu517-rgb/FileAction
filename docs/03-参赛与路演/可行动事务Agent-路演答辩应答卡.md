# 可行动事务 Agent · 路演答辩应答卡

导航：[[docs/可行动事务Agent-00-总览|文档总览]] · [[docs/01-产品方案/可行动事务Agent-参赛主线方案|参赛主线方案]] · [[docs/02-调研与可行性/可行动事务Agent-竞品分析|竞品分析]]

> 口径依据 [[docs/01-产品方案/可行动事务Agent-参赛主线方案|参赛主线方案]]。引号内为计划口径；赛中实际完成什么，就按实际改写，不把计划说成已实现。

## 一、开场与首晚视频

**开场三句：**

1. 「群里一份通知刷屏，你得先弄清跟自己有没有关系，再翻出散落的材料，还要每次都重新跟 AI 解释自己。」
2. 「丢一份文件，我们的 Agent 站在你的角度读给你听：跟你有什么关系，要不要做点什么。它会主动从你过去的 Idea、经历和意向里找出相关内容，告诉你哪些能用、哪些不能用。」
3. 「然后直接行动：列出缺项和截止，起草缺的材料；临时组队时，它还了解每位队友擅长什么，按人推荐分工。」

**首晚60秒团队视频草稿**（按届时真实进度录制）：

- 0–10秒：「我们是【队名】，5 名成员分别负责【实际分工】。」
- 10–30秒：「我们做文启 FileAction：丢一份文件，它站在你的角度读给你听，主动发现你过去做过的哪些事和这次有关。」
- 30–50秒：「每条匹配都能回到原文，往届已获奖的成果会被拦下；然后生成待办、起草材料。组队时，它按每个人的能力和意向推荐分工。」
- 50–60秒：「这 67 小时我们用真实模型把个人版和团队版跑通。」

## 二、问答

### Q1 · 你们解决什么问题？

「大学生每学期会遇到竞赛、奖学金、项目申报等多份通知。每次都要重新弄清要求、翻找旧材料、判断旧材料还能不能用。我们把一份通知直接变成可行动事务：和你有什么关系、你已有什么、还缺什么、下一步做什么。」

### Q2 · 沉淀个人上下文、有记忆的产品很多，你们有什么不同？

「对，很多 AI 都能读文件、也都有记忆，我们不跟它们比谁记得多。区别是，它们给的是通用的解读，我们给的是你的解读。比如通知要求近三年获奖，我们会告诉你：这张证书能用；那张去年已经用来评过国奖，这次不能再用；还缺一份推荐信。之所以能判断，是因为我们记下的是你每次办事留下的证据，出处、版本、用没用过，而不是聊天偏好。组队时，这些记忆还能经你授权，让队友知道你擅长什么。」

**追问“大厂加这个功能很容易吧？”**：「技术上不难，难在场景规则和信任设计：禁重复申报、版本过期、按需索取、授权边界。我们先在校园事务这个窄场景把它做对。」不说大厂做不到。

### Q2b · 公司简章、规章制度这类文件，也会告诉我“怎么办”吗？

「不是每份文件都要你做点什么。它先判断这份文件跟你有什么关系：是通知，就告诉你下一步；是规章制度，就挑出跟你有关的几条；是公司简章，就结合你想做的事说说它可能有什么用，猜不到就问你一句。没什么要做的，它会直接说没有，不硬凑待办。」

可现场丢一份公司简章演示。

### Q2c · 回应这么开放，不就是个聊天 AI 吗？

「开放的是回应形式，不是判断依据。判断材料能不能用时，始终是可用、要处理、本次不能用三类，并附出处；导出的待办和清单格式固定。你随时可以纠正它，纠正里透露的意向经你确认会记下来，下次读得更准。」

### Q2d · 你们说“无痛”，第一次用什么都没有，怎么办？

「第一次用不需要建档。丢进一份文件，它先读一遍，只问你一个跟这份文件直接相关的问题，比如“你上传它是在找实习吗？”，点一下就能看到站在你角度的第二版解读。之后只有事情确实需要某条信息时，才当下问一句，你也可以跳过。每次回答都会留下来，用得越多，要问的越少。」

具体竞品能力见 [[docs/02-调研与可行性/可行动事务Agent-竞品分析|竞品分析]]。不说“其他产品没有记忆”或“做不到”。

### Q3 · “主动发现”是怎么做到的，会不会乱推荐？

「新通知进来时，Agent 把通知要求和你的记忆卡片、意向做匹配，每个推荐都附理由和原文出处。本届的主动提示发生在应用内，不做后台推送。推荐只是候选，由你确认。」

### Q4 · 旧材料能直接复用吗？

「不一定。比如有的通知规定已获奖成果不得重复申报，这类材料会标为“本次不能用”，普通勾选解除不了；成员名单、旧版申请表会标为“要处理”。材料齐全也不等于资格通过。」

### Q4b · 这个功能去掉 AI，用规则引擎能不能做？

「不能。规则引擎只能执行写好的规则，可每份通知的规则都不一样：这份写“近三年获奖”，那份写“已获奖成果不得重复申报”，还有截图、PDF、群里转发的文字。我们没法事先把所有通知的规则写好，只能每次让模型从原文里读出来。读出来之后，像“本次不能用不能被随手勾掉”这类护栏，我们用代码写死，不交给模型。读规则靠 AI，守规则靠代码。」

**追问“断网了还能用吗？”**：「理解新文件要调用模型，断网时读不了新通知，界面会如实提示，不会编一个结果出来。已经保存的记忆和导出的清单照常能看。」可以现场打开 API 调用记录或日志佐证。

分工依据见 [[docs/01-产品方案/可行动事务Agent-参赛主线方案|参赛主线方案]] 第2节“为什么必须用 AI”。

### Q5 · AI 匹配错了、记错了怎么办？

「每条结论都能点回原文。你可以修改、停用或删除任何一张记忆卡片，改完后相关的旧结果会标为过时，需要重新生成。」

### Q6 · 团队版做什么？会不会变成监工？

「不做监工。临时组队时，汇集 Agent 根据每个人授权的能力名片，把这件事拆成工作块，按人推荐谁做哪块，每个推荐都附理由和出处；它还会指出团队缺什么能力，并起草团队介绍、分工表这类共用材料。分工由大家自己决定，它不催交、不盯进度。」

### Q6b · 会不会泄露队友隐私？

「汇集 Agent 只看得到成员授权的能力名片，看不到完整记忆；每条名片成员都可以确认或隐藏。推荐理由对全队可见。」

### Q6c · 飞书、钉钉、接龙管家不是也能分任务吗？

「它们擅长分派、催交和汇总，我们不走这条路。我们是先了解人、再推荐事，而且对人的了解来自每个人在真实事务里逐步沉淀的记忆，不是一张临时填的技能表。」

### Q7 · 队友没用过个人版怎么办？

「照常参与，不用先填问卷。他的名片先空着；等他分到一块工作、开始处理相关文件时，Agent 才在当下问一句需要的信息。回答会沉淀下来，名片越来越丰富，下次推荐也更准。」

### Q8 · 企业版呢？和飞书、钉钉有什么区别？

「企业版目前是路线图。飞书、钉钉的审批和表格收集已经很成熟，我们要补的是它们之前的那一步：读懂一份非结构化通知，判断谁需要做什么。审批和表格可以作为下游对接。」

### Q9 · 数据安全吗？

「演示全部使用合成资料。记忆由用户确认后才保存，可以随时删除。通知和资料片段会发送给模型服务方处理，我们会说明发送了什么；本机保存不等于模型看不到数据。」

### Q10 · 有用户验证吗？商业模式呢？

「我们现在处在从 0 到 1 的阶段，先证明需求。种子用户是一学期多次参赛、经常临时组队的活跃学生。我们没发问卷，而是请【N】名同学打开上次申报的真实文件夹，一步步还原过程；其中【X】人讲到用错材料或被退回的经历，【Y】人愿意把正在准备的真实通知截图发给我们。下一步是赛后做付费测试：提供一次真实的材料对照，付小额费用才能用，看有多少人真的付钱。」

方括号按 [[docs/03-参赛与路演/可行动事务Agent-用户验证执行卡|用户验证执行卡]] 的实际记录填写。未做就如实说未做，不编造人数或原话，不外推成比例或市场规模。

### Q10c · 谁为这个产品付费？一年能省多少钱？

「先说实话：付费方还在验证。我们有三个假设：一是学生个人在申报季小额付费；二是学院或创新创业学院按学生数采购，因为材料一次合格，老师就少做退回和答疑；三是申报辅导机构，顾问核对材料的时间能省下来。能省多少，我们按一个公式算：每次申报省下的对照时间，乘以每学期申报次数，再加上避免被退回或失去资格的损失。访谈里同学回忆，人工对照一次大约要【T1】，用我们的产品在合成通知上实测是【T2】。」

方括号只填真实测得或有来源的数字，填不了就说“还没测”。不报市场规模，不把假设说成已有客户。口径依据 [[docs/01-产品方案/可行动事务Agent-参赛主线方案|参赛主线方案]] 第11节。

### Q10b · 用 AI 开发成本低，大厂也能做，你们的优势在哪？

「对，用 AI 降低开发成本不是我们的优势，大厂同样能做到。我们的优势在窄场景：禁重复申报、版本过期这类规则，还有按需索取、授权边界这些信任设计。大厂做的是通用助手，不会为‘这张证书去年评过国奖’这种细节专门设计。我们先在校园事务这一小块把它做对。」

不说大厂做不到。

### Q11 · 哪些是现场新增？

「9月30日做过一版规则模拟的交互设计稿，10月1日做过一版静态的流程可视化，都没有接入模型，已经申报。PPT 录屏和你们试用的网页里，真实模型理解、主动发现、护栏、材料起草和团队分工推荐都在这 67 小时内实现。」

按实际完成情况改写这一句。

## 三、上台前核对

- 演示用的通知和资料是否标明为合成。
- 主动发现、禁重复拦截、材料起草、分工推荐、按需索取、零记忆首问是否都是真实运行，而非预填答案。
- 团队 Demo 的成员人设是否为合成，没有放入队员真实信息。
- PPT 中的产品画面是否都来自赛中实现版本的真实录屏或截图。
- 官方收集问卷是否已填写，填写的网址和测试账号能否登录，重置是否生效，入口引导卡和合成样例是否就位，调用限额是否已设。
- 失败时是否有封包前提交的录屏备用。
- 访谈人数和原话是否真实。
- Q10c 的耗时数字是否有实测或访谈记录支撑；没有就删掉数字。
- 断网或模型报错时界面是否如实提示；API 调用记录能否当场打开。
- 赛事时间、评分和提交入口以官方最新通知为准（本库记录读取于2026年9月26日）。
