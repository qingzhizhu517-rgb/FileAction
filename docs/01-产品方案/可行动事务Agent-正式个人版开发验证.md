## 2. 测试环境与数据

- Windows、仓库根目录 `.venv`、独立 `front/` 与 `backend/`。测试禁用真实 `.env`，只使用明确标记的随机合成账号和资料。
- 本任务独立PostgreSQL/pgvector容器位于回环端口15432，数据库名 `fileaction_test`；Redis位于回环端口16379。API测试使用Redis逻辑库0，浏览器验收使用逻辑库1，避免限流状态相互影响。未清空数据库或Redis。
- 认证、RLS、组合外键、临时生命周期和队列集成必须使用真实本机PostgreSQL/Redis。纯函数和外部供应商边界可以使用明确标记的HTTP/COS替身。
- 不调用真实COS或Embedding；生成模型适配器的HTTP替身结果不证明模型理解质量。真实外部服务兼容、费用和质量另行验收。
- 基础浏览器脚本只启动并终止自己的8786/8787子进程；独立生成验收另建随机回环端口的专属容器与进程。均不接管原有8766/8767/8768服务。

### 3.1 真实本机浏览器复现

在仓库根目录执行以下已实测命令；脚本读取本任务合成服务配置文件，不读取真实 `.env`。

```powershell
.venv/Scripts/python front/e2e/run_formal_real.py
```

链路包含注册及登录、合成TXT临时上传与原文、退出重登旧原文404；随后用第二份合成文件建立工作区、修改目标、确认仅本次使用的背景，并核对外发预览实际包含这些内容。取消预览时生成POST数量为0；确认结束后工作区和临时原文均返回404。

### 3.2 独立生成链路复现

以下命令已实测退出码0；真实UI/API/Worker/PG/Redis，模型为本机HTTP合成替身，不读取真实 `.env`。每次建立专属临时Docker容器并迁移到当前head，配置受限角色，退出后只清理本次服务。运行前需已安装项目依赖、Playwright浏览器且Docker可用。

```powershell
.venv/Scripts/python front/e2e/run_formal_generation.py
```

2026年10月3日首次运行发现Windows解析到无扩展名docker入口，改为查找docker.exe后复跑退出0；输出标记为 `synthetic_http_model_only=true`、`isolated_infrastructure=true`。该次工具输出未保留Playwright逐项计数，故不补填计数。随后容器清单中没有本入口前缀的残留容器。此入口不证明根目录Compose、真实COS、Embedding或真实生成模型验收。

## 5. 未完成与未验收

### 5.1 尚在实施的能力

受授权SQL检索与完整索引任务、查询Embedding授权；文件版本与删除影响预览/精确后台清理；保留工作区、独立背景与保存补偿；用户确认的行动、可编辑成果及版本/导出；账户删除闭环，以及完整Compose启动和Worker恢复验收。完整范围以技术合同与实施账本为准，不以页面存在或数据库表已建判断完成。

### 5.2 外部依赖及质量验收

真实COS版本桶、真实Embedding配置与兼容、正式版真实生成模型合成冒烟、30案例评测、真人使用与公网访问均未由本记录验收。现有生成模型配置不自动作为Embedding凭据。

### 5.3 当前实现限制

- COS暂要求开启版本控制，缺少精确VersionId时拒绝成功；技术合同中可空版本的非版本桶路径尚不支持。
- 临时账目升级需先停止旧版写入者，不支持旧版持续写入时滚动补账；没有为了本次开发强制退出用户。
- 上传取消会等待已启动的同步调用及补偿收敛；进程暂停超过租约、Redis长期失联、独立OOM及后台未知对象核对仍待验证。
- 正式API不以SQLite、规则回答或静默回退掩盖未配置依赖。
