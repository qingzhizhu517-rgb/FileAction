# 可行动事务 Agent · 用户验证执行卡

导航：[[docs/可行动事务Agent-00-总览|文档总览]] · [[docs/03-参赛与路演/可行动事务Agent-核心路演稿|核心路演稿]] · [[docs/01-产品方案/可行动事务Agent-参赛主线方案|参赛主线方案]]

> 本轮首先验证“收到文件后，是否更容易理解它对当下的我意味着什么”，再观察用户选择后的行动。原来要求开赛前完成的访谈不视作已执行；从实际执行日记录，不回填2026年10月1日之前的结果。当前没有可填入的访谈、产品实测或付款数据。

## 1. 找谁、看什么

找近期收到过通知、指南或业务材料，并实际花时间判断与自己关系的人。学生可以作为便利样本，教师与业务负责人也是待验证场景；不要求受访者反复参赛或临时组过队，不把便利样本当作唯一用户群。优先观察真实发生过的一次过程，尽量避免只找队友形成偏向。

先验证阅读、筛选、联系自身背景的过程。材料出错和重复申报仅在真实发生时记录，不将团队分工列为本轮必问。

## 2. 邀请与隐私说明

```text
我们想了解：你收到一份文件后，怎样判断它跟自己有什么关系。
大约15分钟，请你回忆最近一次真实经历；方便的话，可以在自己的设备上
展示已脱敏的片段。可以跳过任何问题，不需要给我们完整文件或个人资料。
我们只记录你同意的必要信息，不会未经许可把内容发给云端模型。
```

本地查看、研究记录、上传模型和长期保存是不同用途，分别说明并取得相应同意；不以一句“不会外传”掩盖云端处理。优先使用合成资料体验，不上传或入库真实敏感数据。不愿提供文件或截图，也可参与观察，不据此排除为非核心用户。

## 3. 回顾访谈：约15分钟

1. 最近哪一份文件让你需要判断“跟我有什么关系”？收到时你想解决什么问题？
2. 你先读了哪些部分，怎么筛掉无关内容？哪些地方需要再读或向别人确认？
3. 判断时联系了哪些个人经历、当前项目、需求或限制？这些背景在哪里，是否重复介绍过？
4. 最后怎样确认哪些内容值得关注？原文在哪里，有没有无法确定的地方？
5. 你后来做了什么，还是了解后就结束？为什么这样选择？
6. 若用过 AI，给了哪些文件、背景和提示？哪些结果有用，哪里还要自己核对或纠正？
7. 是否有另一份文件需要重复使用相同背景？当时实际上怎样处理？

耗时没有计时就记为回忆估计。不要引导“是不是很痛”“如果有这个产品你会用吗”，不要把期待当作行为证据。

## 4. 体验观察：真实产品与设计稿分开

MVP 未实现时可以观察概念理解或设计稿操作，但记录为概念访谈/设计稿观察，不能称作真实模型能力验证。真实版本可用后，再按以下路径观察，实际支持什么就记录什么：

| 环节 | 观察内容 |
|---|---|
| 文件进入 | 能否开始理解，不先要求填资料表；失败是否明确 |
| 无背景或缺背景 | 先给出有依据的内容；提问是否有必要，跳过是否能继续 |
| 有已确认背景 | 阅读重点是否因相关背景变化，用户能否理解关联理由 |
| 原文核对 | 区分文件事实、背景、推断和未知；记录错关联、漏项及纠正 |
| 本次沉淀 | 用户能否查看、修改并选择保留或不保留，不因回答问题自动保存 |
| 是否行动 | 允许理解后结束；选择继续时是否复用已确认信息，产物是否可编辑 |
| 第二份文件 | 若实际发生，记录保留背景是否仍适用、是否减少重复解释 |

可用同一份合成文件配两个不同的已确认背景，检查阅读重点是否有依据地变化。需要公平比较工具时，保持文件、背景、任务目标一致，记录日期、版本和全部提示；标明顺序和重复阅读可能造成的影响。不以“只给对照工具做摘要”作为优势证据。

## 6. 判断信号

- 用户能指出与自己有关的内容、理由和依据，而非只说“摘要不错”。
- 误关联或未知能被识别和纠正，必要补充没有变成整张资料表。
- 用户可以拒绝保存或到此结束；不把“没有采取行动”自动算成失败。
- 选择继续的人实际编辑或使用了产物；仅生成一份文件不等于它有价值。
- 真正遇到第二份文件时再次使用、复用背景，是后续信号，不由访谈意愿替代。

只引用实际发生的匿名案例、原话、计时和操作记录，明确是回忆、合成场景、设计稿还是产品实测。小样本不外推比例、市场规模或其他身份群体；没有做就说未做。付费、访问、重复使用和口头表态分开报告，不使用占位数字冒充证据。

## 8. 后续付费验证：计划

个人端真实可用并完成必要核验后，再测试用户是否愿为个性化解读或选定的产物准备实际付费。具体方式、金额和规模届时确定；记录邀请、实际付款、退款及实际使用，不提前写成已收费。团队和企业付费假设另行验证，当前不混入个人端价值结论。
