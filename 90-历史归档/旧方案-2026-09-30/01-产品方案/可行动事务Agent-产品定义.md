# 可行动事务 Agent · 产品定义

导航：[[可行动事务Agent-00-总览|文档总览]] · 分类：产品方案

> **愿景**：让已经整理过的个人资料，在下一件事情到来时继续有用。
> **本轮主线**：竞赛/项目报名材料复核与复用助手。用户已确认能触达大学生及校园社团；本篇把限定原型的行为写成可检查契约，不代表功能已实现或商业成立。
> **阅读关系**：[[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-问题处理与方案审定|可行动事务Agent-问题处理与方案审定]] 维护问题处理与范围；[[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-定位决策|可行动事务Agent-定位决策]] 记录选择；[[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-Idea完善方案|可行动事务Agent-Idea完善方案]] 展开使用链；本篇维护行为契约。市场与赛事事实沿用 2026-09-26 读取的来源，本轮未重新联网核验。

## 一、为谁解决什么问题

首批拟面向近期准备竞赛或项目报名的一位学生、项目负责人。收到新通知后，用户可能需要重新找项目介绍、经历、证书和旧计划书，解释背景、核对版本与要求；发生频次与负担待访谈确认。

产品拟把**新通知与用户认可的个人信息、旧资料对上**，回答“能复用什么、哪些要更新、还缺什么、下一步做什么”。一次事务交付可检查的准备结果，下一次事务再复用已确认信息，逐步形成个人记忆。

从通知开始，不要求先整理资料、建标签或填写个人档案。没有旧资料也可得到通知要求清单；记忆在单次结果之后自愿保存。能否省时、是否值得上传和持续使用，仍是待验证假设。

## 二、四个核心对象

| 对象 | 本次处理及可选保存的内容 | 必须区分什么 |
|---|---|---|
| 个人资料与事实 | 所选来源文本、原文件名及版本、可引用片段、所属人、确认时间与适用范围 | 原文写过某数字，不代表它仍是当前事实；保存文本不等于保存原件 |
| 个人意向 | 用户明确表达的目标、关注事项和可停用的偏好 | “想参赛”不等于“已报名”或“符合资格” |
| 当前事务 | 通知及关联来源版本、适用分支、要求、日期、渠道、选定材料和检查覆盖 | 机会相关性、资格条件、材料准备是不同判断 |
| 准备结果与复用关系 | 带版本的清单快照、资料与要求配对、理由、审阅/选用标记、待办 | 模型候选、用户核对、选用于草稿、正式提交和批准不能混同 |

事务可以是需要履行的要求，也可以是用户主动选择的机会。系统不替用户决定参加，不自动将个人资料共享给社团或第三方。

## 三、首个使用闭环

以下是拟实现流程，不是已经发生的测试。演示采用单用户、2 份相关通知；每次最多选择 5 份资料，允许零资料路径。

```text
加入通知 → 核对当前事务、适用分支、原文与未取得附件
  → 获得通知要求清单；零资料时个人材料项为“未检查”
  → 按需选择资料，检查匹配、用途、版本与禁用条件
  → 核对关键事实，纠正后令旧结果过时并重新检查
  → 导出可打开、保留待核实标记的 Markdown 工作草稿
  → 可选择保存所选来源文本和已确认事实，也可跳过
  → 新事务或刷新后读取已保存内容，按第二份通知重新检查
```

旧项目背景可能可引用，成员名单和计划书需更新，申请表须使用本届版本；命中明确禁止重复申报的资料应排除本次用途。未取得附件、PDF 读取失败或只选部分页，均展示实际覆盖，不能记为全文已检查。读取失败时提示粘贴可读文本，不能用预填答案补成成功。

**第一次交付眼前事务的草稿，第二次才检验复用。** 保存不是导出的前提；同一聊天上下文不算持久读取，两轮演示也不证明长期使用价值。

## 四、白盒记忆如何进入产品

每条拟保存的记忆显示内容、来源版本、确认状态与时间、适用范围、所属人和可见范围。明确区分**已确认事实、用户意向、系统建议**；模型推断不能悄悄变成事实。

- **仅本次使用**：候选与工作副本只在内存中，刷新可能丢失；不自动写入跨事务记忆或正文日志。
- **选择保存**：单次结果后，用户勾选来源文本和已确认事实，显示保存范围，实际写入成功才显示“已保存”。原件不改，也不把未经选择的快照片段偷存下来。
- **新事务读取**：重新核对适用对象、规则版本、期限和禁用条件；历史确认不等于新任务自动确认。
- **修改/停用**：增加来源或事实版本，先令关联快照、审阅及选用标记过时，再生成待复核的新结果。依赖不确定时保守扩大失效范围，不暗中沿用旧值。
- **删除**：清除应用控制的对应来源文本、派生事实、缓存和快照引用；最多保留不含正文的删除标记。停用可以保留历史，删除内容不能通过历史或迟到响应恢复。

本届限定本机单用户，来源 ID、事实 ID 与结果条目显式关联，不实现完整知识图谱或多人权限。下载到应用外的副本无法远程改写或收回；本地删除也不能撤回云模型已接收的数据。真实试用前须落实供应商处理、备份与删除边界。

## 五、六种材料状态与审阅、选用分开

### 材料准备状态

| 状态 | 成立条件 | 示例或下一步 |
|---|---|---|
| 未检查 | 未提供资料，或该项检查尚未完成 | 选择资料、补可读内容或重新检查 |
| 可引用候选 | 来源可定位，本次已核对的适用检查未发现冲突 | 展示出处、模型/人工审阅状态，用户再决定选用 |
| 需更新/确认 | 相关资料存在，但有具体可补事实、版本、形式或权限问题 | 当前成员未确认、旧表格、缺本次签字 |
| 本次未找到 | 规则明确，选定范围非空且所需检查完成，未发现对应候选 | 显示范围并允许补充，不推断用户从未拥有 |
| 不可用于本次 | 已确认适用的禁用规则或明确权限限制与触发事实共同成立 | 排除该资料的本次用途，提供另一份资料 |
| 无法判断 | 规则解释、适用分支、来源冲突或关键语义未明 | 列出具体待核实问题，不强行归为材料缺失 |

判断绑定**资料版本×要求版本×本次用途**。禁止条款适用性不明属于“无法判断”；条款明确但“是否曾用于获奖”未知，属于“需更新/确认”；二者均有依据且命中禁用，才是“不可用于本次”。普通确认或选用不能解除禁用，只有有效的新证据或新规则版本经重新核对后可重判。某材料不可用不等于申请人整体不合资格。

### 审阅、选用与覆盖

每项分别记录模型初稿/已核对依据、用户是否选用于草稿、实际检查的资料及片段范围。模型不能把自己设为已审阅，点击选用不代表审核事实，保存也不代表选用。只有核对当前依据后的可引用候选能进入已选区；需更新/确认、无法判断留在待办，禁用项只列排除说明，不能进入建议提交清单。未核对项可出现在工作草稿中，但必须带待审阅标记。

已有候选与其他资料未检查可同时显示。只检查 2/3 份时保留部分覆盖，不能作“所有资料均未找到”的结论；读取成功也不保证模型没有语义遗漏。材料齐全不等于资格通过，本届不做复杂资格判定。`SATISFIED`、`CONFLICT`、`MISSING`、`UNKNOWN` 继续仅用于学时备选的受控条件，不硬套材料六态。

## 六、来源、迟到响应与实际产出

每个建议展开到：**本次要求及版本 → 所选资料/个人事实及版本 → 引用片段与位置 → 理由 → 结果快照**。规则原文与本人证据分别展示，缺失附件和未知分支保持可见。

LLM 产生结构化候选，程序校验来源 ID、原文片段、字段与版本，人核对关键解释和事实。通知中的指令只是数据，不执行其中代码或外部动作。无可定位出处的输出不能成为已确认依据；不承诺“零幻觉”或“完整自动编译”。

每次请求携带任务版本、输入来源版本、全局 `epoch` 和请求序号。修改/停用/删除时递增版本与 `epoch`，立即使相关结果和缓存失效；服务端提交结果、客户端显示结果、保存与导出前都核对这些值。旧响应直接丢弃，最多记录无正文的原因；即使服务端先接受、删除后响应才抵达页面，也不能回填。多页无法同步失效时只允许一个活跃操作页面。

本届产出是可打开的 **Markdown 准备清单**，保留来源、版本、生成时间、覆盖、待办、未检查/待核实标记与排除说明。只列链接和说明时称“材料索引”；文件打包退出本届。生成或选用候选不等于正式提交、资格通过或审批完成，产品只记录准备阶段。

旧快照过时后关闭导出，本届不提供旧快照导出，重新检查后生成新版本。重新打开或导出时检查当前日期，已过有效期也须重查；暂定日期和冲突不得悄悄变成确定期限。已下载文件保持生成时状态，应用内注明其对应版本已过时，由用户重新导出。

演示中的合成数据、人工核验输入、实时抽取与缓存回放分别标明。解析失败不静默替换成预填答案；不编造个人经历、名单、证书、制度条款或已完成操作。

## 七、个人意向与期限提示

本届仅在用户加入通知或主动检查时关联；期限随清单导出，暂定或待核实性质保留，后台提醒与主动监控后置。关联说明用途，允许忽略或停用目标；一次参赛意向不等于持续监控授权。

首版不承诺读取全部微信聊天、持续扫描校园网站或自动发现所有机会。日期要核对年份、对象与暂定状态；新通知改变旧要求时显示差异，未经确认不覆盖旧版本。

## 八、本届范围与学时备选

| 层次 | 设计范围 |
|---|---|
| 主线与样本 | 单用户、2 份演示通知；每次最多 5 份选定资料，可不选；通知先入后按需复核 |
| 本届必做 | 粘贴文本/可读文本 PDF、来源与覆盖、六态、Markdown 草稿、可选持久保存、新事务重审、变更过时与迟到响应拦截 |
| 最小架构 | 熟悉的前端＋本机后端＋本地数据库；少量版本记录和显式依赖，无需复杂检索基础设施 |
| 本届不做 | 文件打包、复杂资格比较、任意格式/OCR泛化、全量资料导入、后台提醒/监控、多人权限、企业部署、外部提交 |

界面采用“通知要求、资料与依据、准备结果”三个工作面，记忆详情在侧栏查看。具体学校与通知尚待选定；样本超出能力则缩范围并说明限制。持久保存未完成时只能展示单次工具，不能拿聊天上下文顶替记忆。

第二课堂学时保留为**备选技术演示**；三个条件、四态及合成算术见 [[90-历史归档/旧方案-2026-09-30/04-学时备选/可行动事务Agent-学分认定Demo规格|可行动事务Agent-学分认定Demo规格]]。不把其阈值、单位或状态套到材料主线，也不在开发途中同时做第二套产品。

西客松正式开发窗口为 67 小时墙钟时间，队伍 1–5 人，正式评审 5 分钟展示＋3 分钟问答。赛前与复用边界见 [[90-历史归档/旧方案-2026-09-30/03-参赛与路演/可行动事务Agent-西客松参赛对齐|可行动事务Agent-西客松参赛对齐]]，交付关口见 [[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-问题处理与方案审定|可行动事务Agent-问题处理与方案审定]]。9月30日新增 [[05-交互Demo/可行动事务Agent-交互Demo使用说明|两份受控交互Demo]]，仅展示部分浏览器交互，不代表本篇完整产品契约验收；真实模型、PDF泛化和正式服务端数据库仍未接入。该原型属于赛前资产，不能冒充现场新增。[[90-历史归档/旧方案-2026-09-30/04-学时备选/可行动事务Agent-UI原型规格表|可行动事务Agent-UI原型规格表]]、[[90-历史归档/旧方案-2026-09-30/04-学时备选/可行动事务Agent-Demo状态表|可行动事务Agent-Demo状态表]] 仅适用于学时备选。

## 九、团队与企业只保留明确的相邻假设

团队版仍是假设，第一种可能是**一个事项的协作材料夹**，先观察负责人个人工作，不进入本届实现。以后若做成员收件，个人档案默认私有，只共享明确选择且有权提供的内容。

责任人由负责人指定或成员确认，模型不自行分配义务。交接记录谁可看、谁可改、谁确认；撤销访问不能回收他人已下载的副本。学校或老师的审批权独立存在。

企业方向另建问题池，关注特定申报、受约束交付或重复收件，不预设个人免费最终转成企业订阅。用户、付款人、已有系统与维护责任都需独立研究。

## 十、差异化与下一步验证

2026-09-26 的公开调研显示，ima、Mem、ChatGPT、Claude、Notion 等已有输入、记忆、引用或行动能力，不能以“别人不会”证明价值。来源与限制见 [[90-历史归档/旧方案-2026-09-30/02-调研与可行性/可行动事务Agent-市场调研与验证|可行动事务Agent-市场调研与验证]]，本轮未进行同题产品实测。

本项目拟验证的区别是**完成一次具体校园事务，并在下一次减少重复准备**。观察完整耗时、初始化与确认负担、错误/过期引用、可复用材料以及第二次独立使用；不只统计收藏量或生成字数。相关实验与商业探索见 [[90-历史归档/旧方案-2026-09-30/01-产品方案/可行动事务Agent-Idea完善方案|可行动事务Agent-Idea完善方案]]，均非已完成结果，也不是黑客松报名条件。

本机保存不等于本地推理。分析前说明向哪一模型服务发送哪些选定片段；本次处理、长期保存、对外共享分别授权。密钥只留后端，日志不写私人正文；无鉴权的公网部署不称私人资料库。开发与展示使用合成或获授权且适合该处理方式的脱敏资料，原始个人记录不入本库。

设计审定、原型运行、用户价值与商业验证分层记录；当前没有运行或用户验收结果。若通用 AI 加模板同样方便，应考虑模板/插件或停止独立应用投入，不用增加功能掩盖结果。
