# 可行动事务 Agent · 产品定义

> **愿景**：让已经整理过的个人资料，在下一件事情到来时继续有用。
> **当前推荐**：从校园个人事务的材料复用切入，优先考虑竞赛或项目报名。用户已确认能触达大学生及校园社团；具体场景和功能仍是建议，尚未定案、实现或完成用户验证。
> **阅读关系**：[[可行动事务Agent-定位决策]] 记录当前选择；[[可行动事务Agent-Idea完善方案]] 展开使用链与实验；[[可行动事务Agent-市场调研与验证]] 保存市场证据；本篇定义产品应怎样工作。

## 一、为谁解决什么问题

首批拟面向近期需要准备竞赛、项目申请或评优材料的学生。拟聚焦的情况是：用户已有项目介绍、经历、证书、旧计划书等资料，但收到新通知时仍要重新找文件、解释背景、核对版本与填写要求；具体发生频次与负担待访谈确认。

产品拟把**新通知与用户认可的个人信息、旧资料对上**，回答“能复用什么、哪些要更新、还缺什么、下一步做什么”。一次事务交付可检查的准备结果，下一次事务再复用已确认信息，逐步形成个人记忆。

低摩擦输入、可控记忆、跨文件关联与个人意向是这一体验的组成部分。无需先整理全部资料、建立标签体系或填写完整个人档案；先使用当前任务需要的少量信息。能否省时、是否值得上传资料和持续使用，仍是待验证假设。

## 二、四个核心对象

| 对象 | 拟保存什么 | 必须区分什么 |
|---|---|---|
| 个人资料与事实 | 原件、可引用片段、来源、所属人、确认时间与适用范围 | 原文写过某数字，不代表它仍是当前事实 |
| 个人意向 | 用户明确表达的目标、关注事项和可停用的偏好 | “想参赛”不等于“已报名”或“符合资格” |
| 当前事务 | 通知版本、要求、材料、日期、渠道与确认事项 | 机会相关性、资格条件、材料准备是不同判断 |
| 准备结果与复用关系 | 本次清单、引用来源、需更新项、待办，以及哪些内容可供以后复用 | 文件存在、内容适用、已提交和已获批准是不同状态 |

事务可以是需要履行的要求，也可以是用户主动选择的机会。系统不替用户决定参加，不自动将个人资料共享给社团或第三方。

## 三、首个使用闭环

以下是设计示例，不对应某项赛事的完整规则，也不是已经发生的测试。本届建议限定为单用户、2 份相关通知、2–5 份旧资料。

```text
2–5 份旧项目资料 + 用户确认的必要背景
  → 加入一份新通知，提取有出处的要求与材料候选
  → 关联旧资料，说明哪些可引用、哪些需更新或补充
  → 用户纠正事实，按资料与结果的显式关联更新相关结论和清单
  → 导出可打开的材料清单或索引
  → 经用户确认，将可复用信息与来源实际保存
  → 新建事务或刷新后，重新读取已保存信息处理第二份相关通知
  → 只追问差异，并检查旧材料是否仍适用
```

例如旧项目介绍的背景可作为候选来源，但成员名单需重新确认，计划书需更新，申请表须使用本届版本。系统应展示一项“找到了但不能直接复用”的资料，而不是只演示全部匹配成功。

**第一次使用证明单次事务处理；第二次才检验记忆能否减少重复输入。** 第二轮不能仅依赖同一聊天上下文；旧资料每次都要重新上传、重新解释时，不能宣称已验证跨事务复用。两轮演示也不代表长期使用价值已获验证。

## 四、白盒记忆如何进入产品

每条拟保存的记忆应显示：内容、来源、确认状态、适用时间、所属人和可见范围。明确区分**已确认事实、用户意向、系统建议**；模型推断不能悄悄变成用户认可的事实。

- 从当前事务提取少量候选记忆，让用户能确认、改正、停用和删除。
- 用户更新事实或停用来源后，按已记录的资料、事实与结果关联，标明受影响的事项并重新检查；不得在新结果中暗中沿用旧值。
- 同一来源在不同事务中的用途分别记录，避免把上届材料直接当作本届有效证明。
- 标签用于查找；“已收藏”或“已记住”都不证明内容正确、最新或有权共享。

本届原型限定单用户，资料固定私有；可见范围先展示为明确字段，不实现多人权限系统。首版用来源 ID、事实 ID 与结果条目的显式映射实现关联，无需完整知识图谱。完整删除、备份和共享副本规则需在真实服务前落实；不能用一个删除按钮宣称所有副本已经清除。

## 五、材料状态与条件判定分开

### 材料准备状态

| 状态 | 对用户意味着什么 | 示例 |
|---|---|---|
| 可引用候选 | 已找到相关内容与来源，针对本次用途的检查未发现具体问题，只待用户确认选用 | 与本次用途相符、未发现过时信息的旧项目问题描述 |
| 需更新/确认 | 已发现具体的时间、格式、版本、用途、权限或事实问题，需要更新或核实 | 通知要求最新成绩单而仅有去年版、成员变动待确认、报名表版本不符 |
| 缺少材料 | 在当前资料范围内未找到通知要求的内容 | 尚未提供的签字页 |
| 无法判断 | 原文不清、规则冲突或证据不足 | “相关成果”没有说明认定范围 |

“缺少材料”不表示用户从未拥有该材料；“材料齐全”不表示资格通过。系统也不能凭现有证据，替学校或赛事作正式认定。

### 简单条件的可选核验

当通知具有明确、可执行的条件时，可使用已经核验的规则与事实进行确定性比较。既有四态沿用：`SATISFIED` 表示满足；`CONFLICT` 表示明确不满足；`MISSING` 表示规则明确但缺必要事实证据；`UNKNOWN` 表示规则适用性、来源冲突、单位或例外未明。已证实为 0 不等于缺证，缺失值不能补为 0。

这套状态服务于条件判定，不能直接套在所有材料和意向上。复杂语义、资格例外和未知条件交给人工确认；没有完整覆盖时不输出整体通过。

## 六、证据、重算与实际产出

每个材料建议应能展开到：**本次要求及版本 → 对应旧资料/个人事实 → 引用片段与位置 → 复用理由或待确认原因**。规则原文与本人证据分别展示，纠错后更新相关结果。

拟采用解析与 LLM 产生结构化候选、人工确认关键事实、受支持规则做确定性比较的组合。语义匹配仍可能遗漏或误引；数字计算可复现也不能消除上游错误。不使用“零幻觉”“完整自动编译”或通用 CSP 突破作承诺。

最低产出是可下载的材料清单，包含来源、版本、缺项和待办。只输出链接与说明时称“材料索引”；仅在实际附带用户选定文件时称相应文件包，不把它说成已经满足所有要求的提交包。报名、邮件发送与学校审批仍在外部渠道完成，提交状态需要回执等依据。

演示中的合成数据、人工核验输入、实时抽取与缓存回放分别标明。解析失败不静默替换成预填答案；不编造个人经历、名单、证书、制度条款或已完成操作。

## 七、个人意向与期限提示

本届先支持新通知加入后的关联和用户主动检查；期限仅随材料清单导出，后台定时提醒与主动监控后置。每次推荐解释“为何与当前目标有关”，允许忽略、暂停或停用目标；不把一次参赛意向等同于持续监控全部资料的授权。

首版不承诺读取全部微信聊天、持续扫描校园网站或自动发现所有机会。日期要核对年份、对象与暂定状态；新通知改变旧要求时显示差异，未经确认不覆盖旧版本。

## 八、本届原型建议与备选场景

| 层次 | 建议内容 |
|---|---|
| 推荐主线 | 单用户、2 份通知、2–5 份资料；首轮清单与保存→新事务或刷新读取→第二轮复用与纠错 |
| 优先实现 | 文本 PDF/粘贴文本、带出处的要求、少量可修改记忆、显式关联、材料状态、含已确认期限的可打开清单 |
| 条件允许再做 | 一种常见文档格式、简单条件核验、通知差异、用户选定文件打包 |
| 后续能力 | 全量资料导入、OCR泛化、后台定时提醒、主动监控与持续发现、多成员实时协作、外部提交 |

界面可围绕“事项收件箱、材料与依据、准备结果”三个工作面展开，记忆详情作为可展开区域。具体通知和输入格式由可得样本决定，尚未选定某校或某项比赛。

第二课堂学时保留为**备选技术演示**，不是唯一主场景。其三个条件、四态及合成算术见 [[可行动事务Agent-学分认定Demo规格]]；不将该场景的阈值和单位套到竞赛材料。选择备选时，同步调整演示和实现，不把两套主线塞进一次展示。

西客松正式开发窗口为 67 小时墙钟时间，队伍 1–5 人，正式评审 5 分钟展示＋3 分钟问答。赛前准备及复用申报按 [[可行动事务Agent-西客松参赛对齐]]；当前只完成方案与资料研究，不将其当作已开发产品。推荐主线的界面和展示安排见 [[可行动事务Agent-Idea完善方案]]；[[可行动事务Agent-UI原型规格表]]、[[可行动事务Agent-Demo状态表]] 仅适用于学时备选。

## 九、团队与企业只保留明确的相邻假设

团队版的第一种可能是**一个事项的协作材料夹**：一位负责人建立活动或申请，成员补充自己负责的材料。无需每个人先沉淀完整个人记忆；个人档案默认私有，只共享明确选择且有权提供的内容。

责任人由负责人指定或成员确认，模型不自行分配义务。交接记录谁可看、谁可改、谁确认；撤销访问不能回收他人已下载的副本。学校或老师的审批权独立存在。

企业方向另建问题池，关注特定申报、受约束交付或重复收件，不预设个人免费最终转成企业订阅。用户、付款人、已有系统与维护责任都需独立研究。

## 十、差异化与下一步验证

ima、Mem、ChatGPT、Claude、Notion 等已覆盖部分甚至多项输入、记忆、关联和行动能力；带引用的多文件工具也已成熟。不能以“别人没记忆、不会算、不会执行”证明本项目价值。可引用事实、反证和非营销反馈见 [[可行动事务Agent-市场调研与验证]]。

本项目拟验证的区别是**完成一次具体校园事务，并在下一次减少重复准备**。观察完整耗时、初始化与确认负担、错误/过期引用、可复用材料以及第二次独立使用；不只统计收藏量或生成字数。相关实验与商业探索见 [[可行动事务Agent-Idea完善方案]]，均非已完成结果，也不是黑客松报名条件。

开发和路演优先使用合成或获授权脱敏资料；原始个人记录不入本库。真实试点前明确授权、用途、第三方模型处理、保存和删除方式。工作名暂保留，先用能接触的一位学生或社团负责人的真实任务校准推荐方向。
